# HEIC 디코더의 GNU 런타임 자료

이 자료는 pi-heif-decoder 1.7.0.post4 Windows wheel에 포함되어 플립링 프로그램에 동봉된 GNU 런타임 DLL 세 개에 대응합니다. OCR용 Tesseract의 Debian GCC 14 DLL과 다른 구성요소이므로 별도 GCC 16.2.0 소스를 제공합니다.

- libgcc_s_seh와 libstdc++: 공식 MSYS2 gcc-libs 16.2.0-3 원본의 PE .text 섹션 SHA-256이 각각 wheel DLL과 동일합니다.
- libwinpthread: 공식 MSYS2 libwinpthread 14.0.0.r375.g9c1abbbf5-1 DLL의 전체 SHA-256이 wheel DLL과 동일합니다.
- libgcc와 libstdc++는 wheel 배포 과정에서 DLL 이름과 수입 이름에 해시가 붙어 전체 바이너리 SHA-256은 다릅니다. 수입 DLL 이름의 해시를 정규화하면 원본 수입 심벌 목록이 같으며 .data와 .idata 섹션의 변경은 기록에 보존했습니다. 전체 바이너리를 재컴파일하여 동일성을 입증한 것은 아닙니다.

GCC-PKGINFO.txt와 WINPTHREAD-PKGINFO.txt에 정확한 원본 패키지·버전·빌드 정보를, HEIC-GNU-대조 JSON에 본문 섹션·수입 목록·다운로드 해시를 보관합니다.
각 .src.tar.zst는 MSYS2의 전체 소스 패키지이며 원본 GCC tar.xz 또는 mingw-w64 Git 소스·패치·PKGBUILD·.SRCINFO를 포함합니다. 패키지-빌드방법에도 원본 PKGBUILD와 .SRCINFO를 별도로 보관합니다.
GCC-원문고지와 WINPTHREAD-원문고지에는 원문 저작권·GPL·LGPL·GCC Runtime Library Exception 등의 해당 고지가 있습니다.

## 소스 제공과 재현

GCC Runtime Library Exception이 있더라도 별도 libstdc++ 바이너리를 재배포할 때에는 해당 GPL의 상응 소스 조건을 준수해야 하므로 이 자료를 프로그램 licenses 폴더에도 함께 동봉합니다.
공식 설명: https://www.gnu.org/licenses/gcc-exception-3.1-faq.html
MSYS2 MinGW64 환경에서 해당 소스 패키지를 풀어 정확한 PKGBUILD와 패치를 사용하여 makepkg-mingw로 빌드할 수 있습니다. 컴파일러·런타임 버전과 패키지 리비전은 PKGINFO의 값을 사용합니다.
pi-heif-원본빌드방법에는 정확한 배포 소스의 setup.py·pyproject.toml·Windows libheif PKGBUILD를 원문 그대로 보관합니다. 해당 PKGBUILD는 MSYS2 gcc-libs 의존성을 사용하고 Python 확장 빌드는 MSYS2 라이브러리를 연결합니다. wheel 생성 전에 delvewheel을 준비하는 설정도 포함합니다. 전체 디코더 소스는 인접 HEIC-소스 폴더의 pi_heif_decoder-1.7.0.post4.tar.gz에 있습니다.
재빌드·호환 동적 DLL 교체·수정 디버깅을 위한 역공학에 추가 제한을 두지 않습니다. 원본 DLL을 수정하거나 교체하지 않고 자료만 보완했습니다.

## 확인 범위

원본 배포 패키지의 DLL과 실제 설치된 wheel·프로그램 DLL을 직접 비교했습니다. MSYS2 소스 아카이브 다운로드 해시는 로컬에서 계산했으며 원격 PGP 서명 검증이나 컴파일러 재빌드는 수행하지 않았습니다.
수입 이름의 해시 정규화와 실행 코드 섹션 동일성을 근거로 원본 패키지를 대응했으며, libgcc/libstdc++의 전체 바이트가 같다고 주장하지 않습니다. 원문 라이선스가 이 설명보다 우선합니다.
