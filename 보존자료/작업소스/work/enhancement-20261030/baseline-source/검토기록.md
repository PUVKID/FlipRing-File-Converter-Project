# 플립링 구현 검토

확인일: 2026-10-21. 제작자: PUVKID. 무료 배포판입니다.

원본 기능과 변환 표는 기존 검토 결과 및 `engine.TABLE`을 기준으로 유지합니다.
원본 저장소 https://github.com/statewarrior483/DragWheel 의 `RadialMenu.swift`와 `AppDelegate.swift`는 동작과 화면 구성 확인에만 사용했습니다.
라이선스가 없는 원본의 코드·이미지·실행 파일은 복사하거나 고객 배포물에 넣지 않습니다.
PUVKID가 작성한 기존 Python 엔진은 변경하지 않았습니다.

## 요구 사항과 구현

- 기본 실행은 트레이 상주입니다. 원본처럼 설정을 트레이에서 열 수 있습니다.
- 큰 대시보드와 단계 카드를 제거하고 설정·도구·기록·정보만 작은 창에 제공합니다.
- 수동 파일·폴더 선택 기능은 트레이와 설정창에 남기며 선택 후 원형 메뉴에서 형식을 고릅니다.
- 설정창 자체에도 파일·폴더 드롭을 유지하며 드롭 후 원형 메뉴를 엽니다.
- 원형 메뉴는 어두운 원·부채꼴 출력·중앙 취소·비활성 도구 설명으로 구성합니다.
- UI는 동봉한 SUIT Regular·Medium·SemiBold 정적 TTF를 사용합니다. 공식 고정 커밋의 원본을 유지하고 `licenses/SUIT`에 SIL Open Font License 1.1 원문과 출처·해시를 보관합니다. Windows 글꼴 파일은 재배포하지 않습니다. PDF 엔진용 나눔고딕 Bold 파일과 OFL은 유지합니다. 제작자는 PUVKID로 표시합니다.
- 등장 150ms, 퇴장 120ms, 선택 강조 100ms 모션은 Qt 타이머의 실제 프레임으로 그립니다.
- 창 크기·좌표·전체 투명도는 모션 중 고정합니다. 창 내부의 그림만 변화시킵니다.
- 기존 변환 분류 10개, 다중 파일 공통 형식, 도구 탐색, 순차 변환, 기록·알림·자동 시작은 유지합니다.
- 인증·TPM·DPAPI 인증 저장·체험·만료·등급·변환 횟수 제한은 넣지 않습니다.

## 코드 조사로 확인한 수정 원인

기존 `dropEvent`는 URL 일부만 골라 받고 `possibleActions`를 다시 확인하지 않았습니다.
진입 단계에서 거부된 URL이나 Move 전용 이벤트를 직접 전달하면 변환 신호를 낼 수 있는 상태였습니다.
현재 구현은 Enter·Move·Drop마다 전체 URL과 존재 여부 및 CopyAction 가능 여부를 검증합니다.
Shift의 Move 제안은 Copy로 바꾸며, 중앙·비활성·바깥 드롭도 소비하고 변환하지 않아 원본을 보존합니다.
확정한 드롭은 재수신해도 변환을 반복하지 않도록 소비 상태를 둡니다.

기존 `poll`은 마우스 버튼이 없는 분기에서 반환하므로 미리보기 Esc 닫기에 도달하지 않았습니다.
현재 구현은 버튼 분기 전에 Esc를 확인합니다.
퇴장 모션 도중 새 메뉴를 열면 이전 모션을 중단하여 새 메뉴가 뒤늦게 사라지지 않게 했습니다.

기록 JSON의 문법이 맞지만 내용이 목록이 아닌 경우 기존 창 초기화가 실패할 수 있었습니다.
현재 구현은 기록 스키마를 확인하고 잘못된 원본 기록 파일은 덮어쓰지 않습니다.

## 검증 구분과 한계

`test_gui.py`는 실제 Qt 창·그리기·중간 모션 프레임·이벤트 전달·생성 PNG 변환을 실행합니다.
`QT_QPA_PLATFORM=offscreen`이면 화면에 창을 띄우지 않는 오프스크린 Qt 시험이며 실제 Windows 창 표시 검증이 아닙니다.
보고서의 `qt_platform` 필드로 실행한 플랫폼을 구분합니다.
키 상태·전경 창·버튼 해제 시각은 모형을 사용합니다.
실제 Windows 탐색기 OLE 드래그나 물리 Shift 키를 이 시험이 검증한 것으로 표현하지 않습니다.
Windows 레지스트리 자동 시작을 시험 스크립트가 변경하지 않습니다.
실제 탐색기 시험, 실행 파일 빌드·설치 및 고객 PC 동작은 별도 보고 대상입니다.
원본 파일과 무관한 EXP 데이터는 수정하지 않습니다.

## Mono 배포 변경

사용자 요청으로 앱 정보 화면에서 공개 기능 참고·새 Windows 앱·원본 제작자·원본 코드 이미지 미포함 안내 네 줄을 제거했습니다.
제작자 PUVKID, 무료 배포, 라이브러리 라이선스 폴더와 필수 법적 고지는 유지합니다.
표시명은 플립링 / FlipRing이며 실행·설치 파일명은 `FlipRing.exe`, `FlipRing-Setup.exe`입니다.
설치 AppId는 `PUVKID.FlipRing`, 기본 설치 경로는 `%LOCALAPPDATA%\Programs\FlipRing`로 분리합니다. 기존 정상 설치를 덮어쓰거나 제거하지 않습니다.
내부 설정 버전·기록·실행 잠금 공유는 유지하므로 기존 제품과 동시 실행하지 않습니다.
같은 폴더에 전체 소스와 빌드 방법을 보관하고, 중복 프로그램·소스 ZIP은 추가 생성하지 않습니다.
설정에서 한국어·영어를 선택하면 사용자 문구가 즉시 바뀌고 재시작 후에도 유지됩니다. 번역 모듈 `i18n.py`도 전체 소스와 해시 목록에 포함합니다.
화면과 설치 아이콘은 흑백·회색으로 정리하며 기존 원형 메뉴의 드롭 좌표·키·모션·원본 보존과 변환 엔진은 유지합니다.
설치 언어 한국어·영어와 앱 내부 언어 선택은 별개입니다. 기존 라이선스 고지와 해당 소스 자료는 삭제하지 않습니다.

## 플립링 PDF·OCR 확장

사용자 확정 요청에 따라 플립링(FlipRing)으로 브랜드를 바꾸고 PDF 편집과 한글·영문 OCR 도구를 추가합니다.
설치 AppId는 `PUVKID.FlipRing`, 설치 폴더와 자동 시작 값은 FlipRing이며 기존 제품 설치는 보존합니다.
OCR은 별도 Tesseract 프로세스로 로컬 처리하며 Windows 설치 권한을 요구하지 않는 동봉 실행 파일을 사용합니다.
Tesseract 5.5.3 공식 NSIS의 SHA-256을 winget 표시 값과 대조한 뒤 설치 실행 없이 자료만 추출했습니다.
실제 DLL 의존성만 동봉하며 학습 도구·제거 도구·NSIS 플러그인·JAR 등은 제외합니다.
원문 라이선스, 해당 소스와 빌드 패치는 `licenses/OCR`에 제공하며 법적 고지는 앱 소개 문구와 별개입니다.
`ubuntu-gcc`는 조사 때 정한 폴더명이며 GCC 런타임 두 DLL은 실제 Debian `gcc-mingw-w64-x86-64-posix-runtime 14.2.0-19+27+b1`과 SHA-256이 일치합니다. 해당 기록과 소스·패치는 출하 목록으로 보존합니다.
포장 스크립트는 실행 폴더와 전체 소스 양쪽에서 GCC 출하 목록의 경로·파일 크기·SHA-256·누락을 검사하며 외부 경로를 거부합니다.
OCR 정확도와 Word 배치·표 구조는 원본 품질에 따른 한계가 있으며 결과 검토가 필요합니다.
실제 동작 시험·고객 배포 준비 완료 여부는 최종 독립 검증 보고서의 범위를 따릅니다.

## 1.4.0 부드러운 디자인 소스 검증

흑백·회색 UI에 SUIT 3개 굵기와 자체 선택 화살표를 적용하고 버튼·탭·원형 메뉴의 상태 전환을 정리했습니다. 빠른 재진입과 호버 전환에서는 현재 시각 상태를 이어가며 드롭 영역과 창 좌표는 고정합니다. 밝은 형식 라벨과 진회색 강조의 대비를 유지합니다.
부모가 전달한 동결 소스 검사는 GUI 57개와 PDF/OCR 28개가 종료 코드 0입니다. 이는 소스 검사 결과이며 새 실행 파일의 실제 설치·Windows 화면·탐색기 조작 검증 완료를 의미하지 않습니다. 실제 배포 검증은 상위 evidence의 해당 기록을 따릅니다.
이후 실제 Windows 화면에서 탭 전환 잔상을 관찰하여 효과 객체의 수명을 전환 진행 중으로 제한하고 완료·중단·숨김 때 제거하도록 수리했습니다. 추가 동결 소스의 GUI 59개가 종료 코드 0이며, 효과 정리 회귀를 포함합니다. 이 소스 검사 통과와 수리된 실행 파일의 실제 화면 확인은 구분합니다.
수리된 새 실행 파일은 부모가 실제 Windows 화면에서 설정·기록에서 PDF로 전환한 뒤 잔상이 남지 않는 것을 확인했고, 영어 설정이 재시작 후 유지되는 것도 확인했습니다. 근거는 `evidence/탭잔상-새EXE-실제해결.json`입니다. 이 결과는 해당 실행 파일의 실제 화면 확인이며 설치 프로그램 실행 결과와는 별개입니다. 앞선 실패와 수리 전 기록은 삭제하지 않습니다.
