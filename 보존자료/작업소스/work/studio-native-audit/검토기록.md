# 플립링 실제 Windows 화면 검토

확인일: 2026-10-21. 작업: studio-redesign-20261021.

Product Design의 audit 절차를 적용했다. 실제 Windows의 격리된 Qt 소스 실행 창을 Computer Use로 조작했다. 실행 파일·설치본의 최종 검증과 구분한다. 창 크기는 본문 1080×780, 제목 표시줄 포함 캡처 1082×812다. 운영 설정·기록 대신 work/studio-preview/격리설정을 사용했다.

1. 홈 화면 — 배치 정상. `01-home.png`에서 어두운 사이드바, 실제 파일 선택 버튼, 중심 링, 빠른 설정을 확인했다. SUIT 글꼴의 한영 표시와 내용 정렬이 보인다. 정지 캡처로 실제 프레임 속도를 측정하지는 않았다.
2. PDF 화면 이동 — 정상. `02-pdf.png`에서 파일 목록과 고정 추가·정렬 버튼, 실행·취소 영역을 확인했다. 이전 홈의 글자가 남는 잔상은 관측되지 않았다.
3. OCR 선택 — 키보드 End로 정상 선택. `03-ocr-top.png`에서 긴 옵션만 오른쪽에 표시되고 파일 버튼 및 실행 영역은 화면 안에 남아 있다. DPI 증감 영역의 강한 테두리는 수정 진행 중인 버전이다.
4. 옵션 위 스크롤 — 수정 필요. 출력 형식 위에서 휠을 내리자 `04-wheel-over-output-changed-value.png`처럼 Searchable PDF가 Text(TXT)로 바뀌었다. 사용자가 옵션을 읽는 과정에서 결과 형식을 바꿀 위험이 있어 repair4로 수정 배정했다. 스크롤 막대에서는 옵션 영역 자체가 내려갔다.

다른 창이 앞을 가린 한 캡처는 잘못된 상태이므로 저장·검토 근거에서 제외했다. 자동 입력의 선택 결과를 성공으로 추정하지 않고 올바른 앱 창을 다시 찾아 확인했다.

접근성 한계: 정지 화면과 실제 버튼 동작을 확인한 범위다. 화면 읽기 프로그램의 전체 지원, 모든 화면 배율, 모든 하드웨어의 일정한 프레임 속도를 검증하지 않았다. 최종 실행 파일에서 수정된 스크롤과 입력을 다시 확인해야 한다.

## 최종 1.5 실행·설치본 검토

같은 작업에서 후속으로 캡처한 실제 Windows 화면으로 수정 결과를 확인했다. 소스 미리보기와 빌드 EXE, 설치본의 범위를 구분한다. 앞의 실패 캡처와 기록은 보존한다.

1. 빌드 EXE 홈 — 정상. `07-built-exe-home.png`에서 밝은 본문·어두운 사이드바와 중심 링, 실제 파일 선택을 확인했다. 색과 글꼴만 바꾼 이전 구성에서 작업 공간 중심으로 달라졌다.
2. 실제 파일 선택과 원형 메뉴 — 정상. `08-built-exe-wheel.png`에서 선택한 JPG의 변환 메뉴를 확인했다. 이 조작은 파일 선택 버튼을 사용했으며 물리 Shift 드래그와 구분한다.
3. PNG 변환 — 정상. `09-built-exe-converted.png`와 `evidence/스튜디오-새EXE-실제변환.json`에서 완료 표시, 새 PNG 생성, 원본 JPG 해시 보존과 640×480 디코딩 픽셀 일치를 확인했다.
4. 기록과 탐색기 — 정상. `10-built-exe-history.png`, `11-built-exe-explorer-selected.png`에서 기록의 왼쪽 더블클릭 후 탐색기 파일 위치와 PNG의 선택 강조를 확인했다. 선택의 근거는 실제 화면이며 별도 UIA 선택 속성을 조회했다고 주장하지 않는다.
5. 설치본 한영 전환 — 정상. `12-installed-home-en.png`, `13-installed-home-ko.png`에서 즉시 언어 전환을 확인했다. `17-installed-ko-after-restart.png`에서 한국어 설정의 재시작 유지를 확인했다.
6. 설치본 PDF 이동 — 정상. `14-installed-pdf-ko-clean.png`에서 전환 종료 후 홈 텍스트 잔상이 남지 않았다. 전환 직후 짧은 교차 효과와 종료 후 화면을 구분했다.
7. 설치본 OCR 긴 옵션 — 정상. `15-installed-ocr-top.png`, `16-installed-ocr-scrolled-value-kept.png`에서 파일 추가·정렬·실행 영역은 고정되고 긴 옵션만 스크롤됐다. 출력 형식 위에서 휠을 내려도 PDF 선택값이 유지되는 것을 실제 입력으로 확인했다. 강한 기본 숫자 증감 테두리는 평평한 제어부로 바뀌었다.

설치 프로그램은 실제 실행 종료 코드 0이며 설치 후 파일 616개의 배포 파일 해시 일치 근거가 있다. 자동 검사와 별개로 사용자의 탐색기 물리 Shift·중앙 취소 확인을 요청한 상태다. 이 문서는 독립 verifier 영수증이나 최종 종료 검사를 대신하지 않는다.

8. 최종 도움말 언어 수리 후 재설치 — 정상 실행. 기록 도움말의 표준 오류가 저장 당시 언어에 남던 누락을 양방향 재현하고 기존 번역 함수를 적용했다. GUI69·PDF28 재검사와 EXE·setup 재빌드 후 실제 설치 종료0, 최종 설치본 홈 `18-final-installed-home.png`를 확인했다. 배포987·설치616파일 SHA를 새로 전수 대조했다. 07~17은 같은 작업의 도움말 수정 전 후보 화면이며, 최종 후보에서 모든 조작을 다시 했다고 표현하지 않는다. 변환 엔진·모션·PDF 패널 소스는 이 좁은 수리에서 그대로다.

접근성·모션 한계: 실제 화면과 일부 키보드·마우스 동작 및 종료 프레임을 확인했다. 모든 DPI, 화면 읽기 프로그램의 전체 지원, 하드웨어별 일정한 프레임 속도와 WCAG 전체 준수는 확인하지 않았다. 모션 GIF는 앱에서 렌더링한 단계의 미리보기이며 실제 앱의 상시 반복 재생을 뜻하지 않는다.
