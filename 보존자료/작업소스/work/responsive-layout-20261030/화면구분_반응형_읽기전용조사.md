## 가장 단순한 구성

새 UI 프레임워크를 도입하지 않고 기존 위젯·objectName·시그널을 유지합니다. 공통의 화면맞춤 함수 한 개, 좁은 폭을 판정해 기존 QBoxLayout 방향/여백만 바꾸는 함수, 기존 페이지에 필요한 QScrollArea만 추가하는 구성이 적합합니다. breakpoint는 임의 해상도 이름보다 현재 콘텐츠 폭과 각 컨트롤의 sizeHint 합으로 결정합니다. 960 이상에서 기존 구조 검사가 보존되도록 설계하고, 640/800의 새 분기만 추가 검사합니다.

초소형 논리 viewport에는 모든 컨트롤을 동시에 표시할 수 없습니다. 예를 들어 물리640×480/200%는 약320×240 논리영역이며 작업표시줄·창테두리를 제외하면 더 작습니다. 이 경우 텍스트·버튼을 무한 축소하는 대신 중앙의 가로·세로 스크롤로 최소 유효 콘텐츠 전체에 도달하게 하는 마지막 대응을 권합니다. 평상시640×480 이상은 세로 재배치로 본문 가로 스크롤을 피하고, 가로 스크롤은 최소 콘텐츠도 들어가지 않는 경우에만 허용합니다. sidebar는 기존204폭 및 버튼을 유지하되 세로스크롤로 마지막 메뉴까지 도달하게 합니다. Ctrl/Tab·포커스 이동 시 필요한 scroll viewport를 함께 따라가게 해야 합니다. QScrollArea를 추가했다는 사실만으로 접근성을 통과 처리하면 안 됩니다.

중첩 스크롤과 PDF의 기존 옵션휠 경로가 가장 큰 회귀 위험입니다. 기본 화면에서는 기존 내부 옵션스크롤을 유지하고, 좁은 분기에서만 바깥 스크롤을 추가합니다. 960 이상 test67의 고정버튼 좌표 보존과 test69의 옵션값 유지·스크롤 이동·키 조작·팝업1회 기준을 그대로 둡니다. 좁은 분기에는 ensureWidgetVisible 후 전체 버튼영역과 실제 클릭/키보드 동작을 검사합니다.

기존 모션은 레이아웃을 교체하는 동안 새 애니메이션 객체나 반복 타이머를 만들지 않습니다. 모션감소 켜기/끄기, 열린 팝업/선택창, 빠른 탭 전환·resize 전후 상태를 확인합니다. 기존 지속/진행 상태 표현은 실제 작업 상태에 연결한 채 보존하고, 관측하지 않은 지속모션 추가·삭제를 요구로 추정하지 않습니다.

## 배율과 해상도 검사 계약 제안

Qt6의 창·화면 geometry는 기본적으로 장치 독립 픽셀입니다. logical640×480 @200%를 물리640×480이라고 쓰면 안 됩니다. 기본 물리 환산은 logical×배율이며 OS 작업표시줄·테두리와 반올림은 별도입니다. 목표는 첫 표시와 화면이동 뒤 frameGeometry가 해당 availableGeometry 안에 있고, 모든 필수 컨트롤에 스크롤/키보드로 도달하는 것입니다. 실제 다중모니터/DPI 전환은 offscreen 또는 QT_SCALE_FACTOR만으로 입증하지 않습니다.

최소 검사 묶음은 6논리크기×4배율×한영의 레이아웃 관측이며, 각각 독립 자식프로세스에서 시작 전 QT_SCALE_FACTOR를 설정하고 실제 DPR·창geometry·screen availableGeometry를 결과에 기록합니다. 이는 DPI 자동화 모사이며 실제 Windows의 해당 설정을 변경했다는 증거는 아닙니다. 이 묶음은 기능검사163/변환266을 매번 재실행하는 방식과 구분합니다.

1. 새 작은화면 분기: 모든6탭 방문, 프리셋·형식·실행·취소·재시도·파일추가·선택/취소·PDF편집/확대창/설정/라이선스 접근. 전체 visibleRegion은 스크롤로 해당 위젯을 노출한 후 측정하며, 포커스 Tab 순환과 메뉴 선택이1회인지 확인합니다.
2. 경계 전환: 최소폭 전후 반복 resize에서 위젯 identity/selected files/queue pending/presets/페이지순서·회전·선택/스크롤 위치·신호 수를 유지. 기존 busy 상태를 모사하되 실제 변환/취소의 회귀는 별도 원문검사로 보존합니다.
3. 외곽화면: (0,0)뿐 아니라 음수 원점/작업표시줄로 줄어든 availableGeometry와 현재 viewport가 최소 콘텐츠보다 작은 경우의 fit 함수를 별도 검사. 기본/파일선택/메시지/PDF확대창·긴 오류 도움말이 화면 밖으로 나가지 않는지 실제 Windows에서 확인합니다.
4. 픽셀 품질: SVG/QIcon을 현재 DPR에서 렌더하고 미리보기 pixmap의 표시 크기와 DPR을 기록. preview_panel의300×160 픽셀맵과 NavButton의20×20 선행 raster가 배율에 충분한지는 실제 캡처로 판단합니다. 원본을 resize마다 재읽지 말고 캐시한 이미지에만 fit합니다. QLabel의 고정 높이로 글자가 잘리지 않는지 fontMetrics와 wordWrap을 대조합니다.
5. 기존 전체163+변환266과 설치본 검증을 최종 동결 뒤 독립 verifier가 재확인합니다. 신규 레이아웃 조사가 기존 PASS·수동 Shift/PDF 정상 확인을 지우지 않습니다.
