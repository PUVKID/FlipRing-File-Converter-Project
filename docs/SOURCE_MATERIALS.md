## LEVEL 1 - Beginner · 목적부터 결과 확인까지

[같은 수준 프로젝트](읽기안내/레벨1.md) · [같은 수준 프로필](https://github.com/PUVKID/PUVKID/blob/main/docs/읽기안내/레벨1.md) · [LEVEL 1 - Beginner](#reading-level-1) · [LEVEL 2 - Explorer](#reading-level-2) · [LEVEL 3 - Practitioner](#reading-level-3) · [LEVEL 4 - Advanced](#reading-level-4) · [LEVEL 5 - Expert](#reading-level-5) · [프로젝트 첫 화면](../README.md)

이 자료는 여러 시점에 따로 보관한 제품 코드·설정·사용법·설계·라이선스를 찾는 목록입니다.

한 번에 실행하는 프로그램 묶음이 아닙니다. 예를 들어 예전 PDF 화면의 코드를 찾으려면 보강 자료 파일명세에서 원래 경로를 찾고 그 차수 설명과 함께 읽습니다.

ZIP 안의 파일은 공개 ZIP 멤버 대응 목록으로 연결합니다.

제품을 실행하는 코드와 검사·캐시 정리·복구·배포를 돕는 도구는 용도가 다릅니다. 목록에 있다고 일괄 실행하지 않습니다. 개인 운영 자료와 과거 생성 설정은 공개에서 제외되었으며 제외 기록의 크기·해시는 보존 범위를 설명합니다. 과거 전체 자료 수를 현재 공개 파일 수로 바꾸어 읽지 않습니다.

<a id="level-1-section-1"></a>
### LEVEL 1 · 목적과 이 차수의 역할

예전 작업 파일을 찾는 안내입니다. files.json은 공개된 파일의 명세, archive-members.json은 ZIP 안의 항목을 찾는 대응 표입니다. 어느 차수의 어떤 파일인지 찾은 뒤 코드를 읽습니다.

이전에 보강한 제품 코드·설정·사용법·설계·라이선스의 현재 공개 사본을 [보강 자료 파일 명세](source-materials/files.json)에서 확인합니다. [전체 차수](REVISION_INDEX.md)와 [공개 ZIP 멤버 대응](source-materials/archive-members.json)을 함께 제공합니다.

### LEVEL 1 · 입력·처리·출력

예를 들어 오래된 PDF 작업 소스가 필요하면 보존 목록에서 원래 차수와 파일을 찾습니다. 경로와 출처를 대조한 뒤 얻는 결과는 그 파일의 위치·역할을 아는 목록이며 새 PDF가 아닙니다.

| 단계 | 내용 |

<a id="level-1-section-4"></a>
### LEVEL 1 · 화면과 사용 흐름

목록에서 경로를 고르고 링크를 열어 코드와 차수 설명을 함께 읽습니다. README는 사용 안내이고 Python 파일은 코드입니다. 검사·복구·배포 도구는 제품 실행 버튼처럼 바로 실행하지 않습니다.

1. 보존 목록에서 원래 차수·경로를 찾습니다.
2. 연결된 코드와 해당 차수의 설명을 함께 읽습니다.
3. 보조 도구와 제품 실행 코드를 구분하고 필요한 입력을 확인합니다.

<a id="level-1-section-6"></a>
### LEVEL 1 · 설치 환경과 실행·사용법

여러 차수의 도구를 한 폴더에 모았다고 같은 프로그램처럼 설치할 수 있는 것은 아닙니다. 필요한 코드의 차수 안내를 먼저 읽고 그때의 입력과 준비물을 확인하세요. 특히 캐시 정리·복구 도구는 이름만 보고 실행하지 않습니다.

이 묶음은 서로 다른 시점의 작업 자료를 원래 경로로 보관합니다. 한 앱의 완전한 같은 시점 설치 환경으로 합치지 않습니다.

아래 원본 목록에서 필요한 파일을 고른 뒤 해당 차수의 실행 안내와 대조합니다. 검증·캐시 정리·복구·배포 도구에는 원래 경로와 기존 증거가 필요할 수 있으므로 일괄 실행하지 않습니다.

<a id="level-1-section-7"></a>
### LEVEL 1 · 처리 결과와 출력 읽기

결과에서 원래 위치·크기·SHA256을 함께 봅니다. 크기가 같아도 내용은 다를 수 있고 이름이 같아도 다른 차수 파일일 수 있습니다. 해시는 같은 내용인지 대조하는 식별 값이며 품질 점수가 아닙니다.

원래 위치와 파일 크기·SHA-256으로 보존 대응을 확인합니다. 같은 이름의 파일도 시점과 경로가 다르면 다른 자료입니다.

<a id="level-1-section-8"></a>
### LEVEL 1 · 제약과 문제 해결

한 폴더에서 실행되지 않아도 자료가 여러 시점에서 모였기 때문일 수 있습니다. 이전 파일과 다르면 먼저 차수와 원래 경로를 확인합니다. 없는 파일을 추측해서 만들거나 다른 차수 파일로 바꾸지 않습니다.

| 상황 | 확인할 내용 |
| --- | --- |
| 한 폴더로 실행되지 않음 | 이 묶음은 여러 작업 시점의 보존 자료이며 단일 배포 제품이 아닙니다. |
| 이전 파일과 내용이 다름 | 원래 차수·경로·해시와 전체 비교를 함께 확인합니다. |

## LEVEL 2 - Explorer · 구성과 처리 관계

[같은 수준 프로젝트](읽기안내/레벨2.md) · [같은 수준 프로필](https://github.com/PUVKID/PUVKID/blob/main/docs/읽기안내/레벨2.md) · [LEVEL 1 - Beginner](#reading-level-1) · [LEVEL 2 - Explorer](#reading-level-2) · [LEVEL 3 - Practitioner](#reading-level-3) · [LEVEL 4 - Advanced](#reading-level-4) · [LEVEL 5 - Expert](#reading-level-5) · [프로젝트 첫 화면](../README.md)

files.json은 공개 사 본의 파일 대응을, archive-members.json은 압축 내부 항목과 공개 경로의 대응을 제공합니다. 전체 차수 안내는 그 파일이 어떤 시점의 작업인지 연결합니다. 원문 경로·출처·해시를 따라 기능 소스와 보조 도구를 구분하는 흐름입니다.

이전에 보강한 제품 코드·설정·사용법·설계·라이선스의 현재 공개 사본을 [보강 자료 파일 명세](source-materials/files.json)에서 확인합니다. [전체 차수](REVISION_INDEX.md)와 [공개 ZIP 멤버 대응](source-materials/archive-members.json)을 함께 제공합니다.

### LEVEL 2 · 처리 결과와 출력 읽기

경로는 출처, 크기는 바이트 수, SHA256은 내용 식별을 담당합니다. 세 정보를 결합해 원문과 공개 사본을 연결하며 파일명 하나만으로 대응을 확정하지 않습니다.

### LEVEL 4 · 입력·처리·출력

보존 대응은 파일 내용의 식별 문제이며 프로그램 실행 결과와 다른 유형입니다. 같은 basename을 가진 자료를 시점·경로·해시 없이 합치면 서로 다른 실험이나 도구를 하나로 오인할 수 있습니다.

| 단계 | 내용 |
| --- | --- |
| 입력 | 기존 차수에서 개별 보존한 작업 소스와 문서 |
| 처리 | 원래 경로·출처·파일 대응을 찾아 읽기 |
| 출력 | 기능 소스·개발 도구·설명 문서의 보존 목록 |

<a id="level-4-section-4"></a>
### LEVEL 4 · 화면과 사용 흐름

원문 탐색 흐름은 위험한 보조 작업을 자동 실행하지 않도록 설계된 읽기 경로입니다. 파일을 찾았다는 이유만으로 캐시 정리·복구·배포의 적용 대상을 현재 환경으로 바꾸지 않습니다.

1. 보존 목록에서 원래 차수·경로를 찾습니다.
2. 연결된 코드와 해당 차수의 설명을 함께 읽습니다.
3. 보조 도구와 제품 실행 코드를 구분하고 필요한 입력을 확인합니다.

### LEVEL 4 · 설치 환경과 실행·사용법

보조 도구의 환경 의존성은 제품 런타임 의존성과 다릅니다. 보존 경로를 현재 경로로 단순 치환하면 정리·복구 대상이 달라질 수 있으므로 실행 범위와 데이터 경계를 다시 검토해야 합니다.

이 묶음은 서로 다른 시점의 작업 자료를 원래 경로로 보관합니다. 한 앱의 완전한 같은 시점 설치 환경으로 합치지 않습니다.

아래 원본 목록에서 필요한 파일을 고른 뒤 해당 차수의 실행 안내와 대조합니다. 검증·캐시 정리·복구·배포 도구에는 원래 경로와 기존 증거가 필요할 수 있으므로 일괄 실행하지 않습니다.

<a id="level-4-section-7"></a>
### LEVEL 4 · 처리 결과와 출력 읽기

보존 대응의 검증은 비교 대상의 시점과 바이트 식별에 결합합니다. 현재 공개 목록의 일치가 과거 비공개 전체 자료의 완전성이나 해당 도구의 실행 동등성을 의미하지 않습니다.

원래 위치와 파일 크기·SHA-256으로 보존 대응을 확인합니다. 같은 이름의 파일도 시점과 경로가 다르면 다른 자료입니다.

<a id="level-4-section-8"></a>
### LEVEL 4 · 제약과 문제 해결

이질적 보존 집합의 실행 불가능성은 단일 제품 결함과 구분해야 합니다. 출처 확인 없이 최신 파일로 통일하면 과거 변경 근거가 사라지므로 원문 보존과 별도 수정 기록을 유지합니다.

| 상황 | 확인할 내용 |
| --- | --- |

| 이전 파일과 내용이 다름 | 원래 차수·경로·해시와 전체 비교를 함께 확인합니다. |
