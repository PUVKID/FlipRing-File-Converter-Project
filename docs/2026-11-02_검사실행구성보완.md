# 2026-11-02 검사 실행 구성 보완

플립링 1.8.0의 고정 창·영역 구분 작업에 남아 있던 재검증을 이어갑니다. 앱 기능 버전과 실행 코드는 유지합니다. 기존 Python 소스 21개 중 GUI 검사 한 파일의 이벤트 동기화를 개정하며 나머지 20개와 실행·설치 파일은 변경하지 않습니다. 이전 실패는 [공개 상태 재확인](2026-11-02_공개반영재개검증.md)에 보존했습니다.

## 원인과 변경 범위

8개 검사 프로세스를 한꺼번에 시작한 실행에서는 PDF·OCR과 일반 작업 검사에 시간 초과가 발생했습니다. 2개씩 실행하는 비교에서는 GUI 검사가 모두 통과했지만, 긴 작업의 시작이 뒤로 밀려 전체 배치가 끝나지 않았습니다. 4개씩 긴 작업을 먼저 실행하는 비교도 일반 작업 시간 초과와 Esc 숨김 검사 실패가 남았습니다. 이 결과를 앱 전체 통과로 취급하지 않았습니다.

일반 작업 20개를 별도로 계측한 진단은 모두 통과했습니다. RAR·외부 프로세스 후손 안전 검사의 누적 시간과 첫 손상 이미지 판독 시간이 전체 실행 시간을 차지했습니다. 진단의 더 긴 외부 제한을 기존 27초 검사 통과로 바꾸어 기록하지 않았습니다.

먼저 원본 검사 본문과 기대값을 유지한 실행 구성을 다음과 같이 개정했습니다. 이후 모션 종료 관찰 한 곳에 적용한 동기화 변경은 다음 절에서 별도로 설명합니다.

- GUI 85개, PDF·OCR 28개, 일반 작업 20개, PDF 편집 30개의 실제 시작·종료 식별자를 모두 대조합니다.
- 일반 작업은 기존 클래스 단위 14개와 6개로 격리합니다. 원래 20개의 순서와 합계, 중복·누락·건너뜀 여부를 함께 검사합니다.
- 최대 2개를 동시에 실행하고 긴 작업을 먼저 시작합니다. 각 실행의 27초 제한을 유지합니다. 모션 400ms 설정과 420ms 대기 인자는 유지하며 종료 관찰 시점은 아래와 같이 개정합니다.
- 전체 배치 제한은 큐 대기를 포함한 65초, 배포 대조는 15초, 합계 80초로 정식 개정합니다. 과거 30초·45초는 당시 검사 도구의 최대값에서 정해졌으며 제품의 응답 속도 보장과 구분합니다.
- 출력 수집은 단일 읽기 소유자로 처리합니다. 시간 초과·수집 미완료·정리 오류를 성공으로 숨기지 않고 실제 관측 바이트와 UTF-8 경계를 구분합니다. Windows의 비동기 프로세스 종료 때문에 부분 출력이 남는 경우도 명시합니다.

기존 실패 원문과 검사 명세를 보존합니다. 실행 구성 변경을 제품 버전 변경이나 모든 컴퓨터에서의 실시간 동작 보장으로 표현하지 않습니다.

## 모션 종료 검사의 이벤트 동기화

독립 검사에서 상태 모션의 400ms 설정을 420ms 대기 뒤 확인해도 실행 중으로 관측되는 실패가 재발했습니다. 제어된 GUI 지연 표본에서는 대기 함수가 약 500ms 뒤 반환했는데도 애니메이션 시각이 362ms에 머물렀고, 만료 이벤트가 대기 중이었습니다. 원래 실패를 확정·보존한 뒤 이벤트를 한 번 처리하자 종료 시각 400ms·최종 상태가 적용됐습니다. 자연 발생 실패 당시의 구체적인 운영체제 지연 원인까지 확정한 것은 아닙니다.

이에 `test_78_status_motion_tracks_real_states_and_stops_on_hide_and_reentry`의 `qWait(420)` 뒤에 `APPLICATION.processEvents()` 한 번과 한국어 주석을 추가합니다. 400ms 설정·420ms 대기 인자와 정지·최종 상태·숨김·재진입 검사는 유지합니다. 관찰 시점을 이미 대기 중인 이벤트 한 라운드 처리 뒤로 옮긴 검사 계약 변경입니다. GUI 스레드가 지연돼도 420ms 벽시계 안에 끝난다는 보장과 동등하지 않습니다. 앱 실행 코드 안에는 이벤트 강제 처리를 추가하지 않습니다.

[Qt qWait 구현](https://raw.githubusercontent.com/qt/qtbase/6.12/src/corelib/kernel/qtestsupport_core.cpp), [QTimer 정확도](https://doc.qt.io/qt-6/qtimer.html#accuracy-and-timer-resolution), [processEvents의 처리 범위](https://doc.qt.io/qt-6/qcoreapplication.html#processEvents)를 근거로 관찰과 계약을 구분합니다. 기존 배율 화면 보고서는 당시 GUI 검사 해시를 그대로 유지하고, 현재 검사에서 추가한 부분을 제거하면 원본 해시와 일치하는지 대조합니다. 과거 화면 보고서를 새로 생성한 것처럼 표시하지 않습니다.

## 검증 결과

실행 구성 개정 직후 구현 담당의 실제 명세 실행에서 기능 163개가 모두 통과했습니다. GUI 85개·PDF/OCR 28개·일반 작업 14+6개·PDF 편집 30개의 실제 식별자와 원본 해시를 대조했고, 실패·오류·건너뜀·중복·누락이 없었습니다. 각 실행은 원래 27초 이내에 끝났습니다.

전체 배치는 53.766초, 배포 대조는 8.672초, 전체 관측은 62.453초였습니다. 배포 대조는 제품 Python 소스 21개·출하 파일 1,017개·내장 코드 12모듈의 결합·설치 보고서 625개·기존 변환 266개와 35개 배율 렌더의 근거를 확인했습니다. 기존 보고서와 현재 파일의 해시를 다시 대조하는 항목을 새 변환·새 렌더 실행으로 표현하지 않습니다.

첫 독립 전체 실행에서는 화면·일반 작업·PDF 편집 135개가 통과했지만, PDF·OCR의 25번째 검사에서 빈 결과 경로를 읽는 오류가 발생했습니다. 이 묶음은 24개 통과·1개 오류 뒤 나머지 3개를 실행하지 못했으며 전체 통과로 처리하지 않았습니다. 결과 콜백과 실제 OCR 예외를 관찰하는 외부 진단에서는 같은 원본 28개가 네 차례 모두 통과했습니다. 제품 코드와 원래 검사 기대값은 바꾸지 않았습니다. 실패 당시의 실제 OCR 오류 본문은 확보하지 못해 간헐 오류의 원인은 미확정이며, 진단 통과를 원인 해결로 해석하지 않습니다.

이벤트 동기화 개정 전의 한 독립 재검증에서는 기능 163개와 배포 대조가 모두 통과했습니다. 기능 배치는 52.359초, 배포 대조는 3.375초였으며 독립 검증 명령 전체 관측은 63.047초입니다. 검증 전후의 소스가 같음을 확인했고 이전 실패 이력은 그대로 유지했습니다. 새 수집기 회귀 13개는 별도 독립 실행에서 통과했고 그 코드 해시가 같습니다. 실행 구성의 옛 계약 9개는 GUI 검사 변경 이전에 통과한 기록이며, 당시 원본 전체 불변 조건을 현재 검사에도 그대로 통과했다고 주장하지 않습니다.

별도 최종 완료 검사에서도 현재 소스와 독립 검증 영수증이 일치했고 두 검사 묶음이 54.187초에 통과했습니다. 이는 직접 호출한 로컬 완료 검사이며 전역 자동 실행을 뜻하지 않습니다. 이번 마무리에서는 새 빌드·재설치와 실제 모니터 배율 변경을 다시 수행하지 않았습니다. 현재 설치본의 실제 탐색기 Shift 드래그 변환·원본 보존·중앙 취소는 사용자가 직접 시험하여 세 가지 모두 정상임을 확인했습니다. 이 응답을 자동 OLE·물리 키 입력 검증으로 표현하지 않으며, 기존 설치본의 파일 대조와 자동 검사 결과를 구분합니다.

개정된 관찰 계약의 최종 독립 검증은 163개 전부 통과했습니다. 기능 배치는 46.468초, 배포 대조는 2.828초, 독립 검증 명령은 55.641초였습니다. 같은 제어 지연을 적용한 후보 검사도 별도 독립 실행에서 1개 통과했습니다. 원본 대비 주석과 이벤트 처리 한 줄만 추가됐고, 이를 제거하면 이전 원문 해시와 일치합니다. 기존 Python 나머지 20개와 실행·설치 파일은 같으며, GUI 검사와 소스 해시 목록의 현재 배포 정합성을 확인했습니다.

## 실행물과 전체 소스

설치 폴더는 출하 파일 625개와 설치 시 생성되는 삭제 지원 파일 2개(`unins000.exe`, `unins000.dat`)를 구분합니다. 출하 파일은 모두 크기·해시를 대조하고, 두 생성물은 별도 기록하며 그 밖의 추가 파일이나 누락을 허용하지 않습니다. 설치 설정과 [Inno Setup의 기본 삭제 지원](https://jrsoftware.org/ishelp/topic_setup_uninstallable.htm), [삭제 파일 기본 위치](https://jrsoftware.org/ishelp/topic_setup_uninstallfilesdir.htm)를 함께 확인했습니다.

로컬 프로젝트 한 폴더 안에 실행 프로그램, 설치 프로그램, 전체 소스·자산·라이선스와 빌드 방법을 보관합니다. 배포 대조에서는 기존 실행물의 내장 코드와 소스, 실제 설치 파일, 배율 렌더의 소스 결합을 확인합니다. 기존 266개 변환은 엔진·검사기·관련 자산의 해시 일치 근거를 구분하며 새 실행으로 표시하지 않습니다.

공개 저장소의 [실행 전 준비 범위](../README.md#quick-start), [빌드 방법](../소스/빌드방법.md), [1.8 설명](versions/1.8.0.md), [전체 차수 표](REVISION_INDEX.md)를 함께 확인할 수 있습니다. 로컬 배포 바이너리와 비공개 운영 기록을 공개 소스 전체와 혼동하지 않습니다.

## 함께 공개한 검사 도구

Windows용 [제한 출력 수집기](../tools/release_capture.py)와 [회귀 검사 13개](../tools/test_release_capture.py)의 전체 코드를 함께 공개합니다. 수집기는 로컬 구현과 원문 바이트가 같습니다. 공개 검사 사본은 시험 기록 기본 위치 한 줄을 일반화했고, 개행 185곳이 LF에서 CRLF로 바뀌었습니다. 개행을 정규화하면 해당 한 줄을 제외한 본문이 같으며, 구문 트리도 그 대입문을 제외하고 일치합니다. [원문·공개 해시와 나머지 구문 일치 근거](validation/capture-source-provenance.json)를 보관합니다. 개인 지침·실제 실행 기록·인증값은 포함하지 않습니다.

이 두 도구는 Windows와 Python 3.12의 표준 라이브러리로 실행합니다. 저장소 폴더에서 다음 명령을 사용합니다.

```powershell
py -3.12 -B -X utf8 tools/test_release_capture.py
```

시험은 자신이 만든 프로세스와 임시 파일을 사용합니다. 종료 표본은 실제 27초 제한을 검사하므로 실행 시간이 필요합니다. 기본 기록은 임시 폴더에 저장하며 `FLIPRING_CAPTURE_TEST_OUTPUT` 환경 변수로 다른 기록 폴더를 지정할 수 있습니다.

새 보조 검사의 초기 1초·5초 실행 기대와 3초 종료 기대는 실제 사용 계약인 27초와 최대 2초 정리 예산으로 명시 개정했습니다. 초기 독립 검사 실패를 보존하며 같은 종료 성능 검증을 유지했다고 표현하지 않습니다. 원제품 163개·자식 27초·모션 400/420ms와 수집기 drain 1초는 변경하지 않았습니다.

## 원격 공개 사본 정리의 보존

이번 후속 기록은 개인정보·개인 사용자 경로와 팀 자료를 정리한 원격 커밋 `8fb6983c985bcac932e6b103472ea589bbd84293`을 기준으로 통합했습니다. 직전 원격의 297개 파일 변경과 공개 보류 안내, 개인정보가 정리된 차수 비교·파일 목록을 유지합니다. 삭제된 자료나 정리 전 개인 값을 복원하지 않았습니다.

위 기능 검사와 배포 대조는 로컬 제품 원본에 대한 근거입니다. 개인정보를 정리한 공개 사본은 원본과 바이트가 다를 수 있으며, [공개 사본 기준](PRIVACY_PUBLIC_COPY.md)과 [원본·공개 파일 대응](source-materials/files.json)의 현재 공개 해시 및 원본 대응 해시를 구분합니다. 이번 통합에서 공개 제품 소스의 개인정보 정리를 되돌리거나 로컬 제품·실행·설치 파일을 수정하지 않았습니다.
