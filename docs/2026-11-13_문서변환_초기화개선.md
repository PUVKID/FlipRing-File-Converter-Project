# 플립링 1.11 문서 변환 초기화 개선

Windows에서 문서마다 격리한 LibreOffice를 시작할 때 준비 시간이 반복되는 구간을 확인했습니다. 앱이 만드는 일회용 프로필에 `UseOpenCL=false`를 추가했습니다. 사용자의 LibreOffice 설정은 바꾸지 않으며, 앱의 화면 모션에도 영향을 주지 않습니다.

## 변경 범위

- [문서 설정](../소스/document_formats.py): 일회용 프로필에 OpenCL 설정 한 항목과 설명 주석을 추가했습니다. 매크로·능동 콘텐츠·외부 참조·문서 업데이트를 제어하는 기존 다섯 설정과 초기 사이드바 설정은 유지합니다.
- [프로필 검사](../소스/test_document_formats.py): 새 설정도 반드시 정확히 존재하도록 기대 값을 추가하고 전체 항목 수를 6개에서 7개로 명시했습니다. 기존 보안 값·중복키 거부·다섯 모듈의 사이드 바·네임 스페이스·빈 사용자 데이터 검사는 유지합니다. 이전 기대 값과 실패 기록은 보존합니다.
- [변환 엔진](../소스/engine.py): 외부 변환과 RAR 도우미를 작업별 Windows Job으로 소유하고 실제 후손 종료를 확인하는 변경도 이번 출하 코드에 포함됩니다. 취소를 요청한 것과 종료를 확인한 것을 구분합니다.

## 직접 확인한 결과

기존 일 회용 프로필의 ODS 검사 한 건은 53.156초, OpenCL 설정 한 항목만 추가한 비교는 26.985초였습니다.

세 번의 LibreOffice 실행 후 UNO 연결 준비 시간은 각각 12.7250472·11.9658809·13.8556008초에서 4.1388393·4.2383016·3.3805384초로 줄었습니다.

일부 문서 읽기 단계는 오히려 늘었으므로 모든 단계나 모든 문서가 같은 비율로 빨라졌다고 주장하지 않습니다.

순차 비교라 외부 부하와 캐시 영향을 완전히 통제한 실험은 아닙니다.

계측을 제거한 원래 통합 7개는 180초 한도에서 98.188초에 통과했습니다. Word 97·Excel 97·PowerPoint 97 왕복 변환, 한글·표·시트·수식·슬라이드, PDF·이미지 출력, ODS·CSV, 손상 문서 거부와 실제 Office 취소를 확인했습니다.

별도 검증자의 최종 문서 검사 51개도 모두 통과했습니다.

정확한 군별 수행 수·시간·ID·소스 해 시와 원문 보고서 해시는 [공개용 검사 요약](검증/문서51_독립검사_요약.json)에 보관합니다.

앞선 통합 시간 초과와 새 설정을 예상하지 못한 검사 한 개의 실패를 뒤의 통과로 지우지 않습니다.

검사 ID·순서·건너뜀 거부와 시간 한도는 유지했고, 프로필 기대값 두 부분의 변경은 위에 명시했습니다.

## 적용 조건과 한계

Office 변환에는 별도 LibreOffice 설치가 필요합니다. HWP·HWPX는 읽기와 다른 형식 변환을 지원하며 HWP·HWPX 저장은 지원하지 않습니다. 초기 Excel 2007 Beta2 XLSB도 지원 대상에서 제외합니다. 복잡한 문서의 배치·글 꼴·수식은 변환 결과를 직접 확인해야 합니다.

이 기록은 제품 소스와 문서 검사에 관한 내용입니다. 새 설치·물리 탐색기 입력·최종 배포 파일과 GitHub 게시 검증은 각각 해당 산출물의 실제 결과로 구분합니다.


## 설치본 문서 도우미 격리

설치 본의 DOCX →PDF 시험에서 외부 LibreOffice Python 3.13이 앱의 Python 3.12용 `_socket.pyd`를 읽어 버전 충돌이 발생했습니다.

같은 환경·같은 도우미 세 파일에서 시작 모듈 경로만 바꾼 비교로 재현했습니다.

앱의 `_internal` 폴더에서는 충돌했고, 도우미 세 파일만 둔 별도 폴더에서는 UNO와 필요한 표준 확장이 LibreOffice 쪽에서 정상적으로 불러와졌습니다.

[문서 실행 코드](../소스/engine.py)는 이미 만들던 짧은 일회용 프로필 안에 `document_bridge.py`·`document_formats.py`·`document_xlsb.py`의 원문만 배타적으로 복사해 실행합니다. `-B`로 외부 Python의 바이트 코드 쓰기를 막습니다.

전체 앱 폴더나 바이너리 확장은 복사하지 않으며, 기존 문서 보안 값·작업별 Windows Job·취소·시간 제한·프로필 정리는 유지합니다.

기존 파일 충돌과 원문 부재·복사 실패도 숨기지 않습니다.

별도 독립 회귀 6개와 현재 소스의 문서 51개를 직접 재검사해 모두 통과했습니다.

문서 검사의 본문 수행 시간은 약 205.2초이며, 원값과 군별 수행 시간·ID·원문해 시는 [현재 검사 요약](검증/문서51_독립검사_요약.json)에 보관합니다.

이전 설치본 실패와 이후 소스 검사를 구분합니다.

새 실행·설치 파일과 실제 DOCX 변환은 각각 해당 배포 파일에 결합한 결과로 확인합니다.

외부 프로그램을 실행할 때 번들 라이브러리 경로를 함께 확인해야 한다는 배경은 [PyInstaller 공식 문서](https://pyinstaller.org/en/stable/common-issues-and-pitfalls.html#launching-external-programs-from-the-frozen-application)를 참고했습니다.

이번 수정 범위는 위의 실제 모듈 경로 비교에 근거합니다.
