## LEVEL 1 - Beginner · 목적부터 결과 확인까지

[같은 수준 프로젝트](../../%EC%9D%BD%EA%B8%B0%EC%95%88%EB%82%B4/%EB%A0%88%EB%B2%A81.md) · [같은 수준 프로필](https://github.com/PUVKID/PUVKID/blob/main/docs/읽기안내/레벨1.md) · [LEVEL 1 - Beginner](../../versions/1.7.0.md#user-content-reading-level-1) · [LEVEL 2 - Explorer](../../versions/1.7.0.md#user-content-reading-level-2) · [LEVEL 3 - Practitioner](../../versions/1.7.0.md#user-content-reading-level-3) · [LEVEL 4 - Advanced](../../versions/1.7.0.md#user-content-reading-level-4) · [LEVEL 5 - Expert](../../versions/1.7.0.md#user-content-reading-level-5) · [프로젝트 첫 화면](../../../README.md)

1.7.0은 반복해서 입력하던 작업 설정을 프리셋으로 저장하고 파일마다 실행 준비 상태를 보여 줍니다.

프리셋은 자주 쓰는 목표 형식이나 PDF 옵션을 다시 고르는 묶음입니다.

파일 큐는 이번에 처리할 파일들을 순서대로 모은 목록입니다.

예를 들어 사진 여러 장을 같은 형식으로 바꿀 때 파일을 넣고 프리셋을 선택한 뒤 각 파일의 준비 상태를 읽습니다.

사전 점검은 입력을 읽을 수 있는지, 필요한 도구가 있는지, 출력 위치에 쓸 수 있는지, 공간이 있는지를 확인합니다. **준비 완료는 변환 완료가 아닙니다.** 실행 뒤 새 파일을 열어 형식과 내용을 확인해야 합니다. 오류가 난 파일과 먼저 완성된 결과를 구분하고 기록에서 결과 위치를 찾습니다.

<a id="level-1-section-1"></a>
### LEVEL 1 · 목적과 이 차수의 역할


아래 기능과 사용 순서는 **이 버전 폴더의 코드**를 기준으로 읽습니다. 버전 번호는 보존 시점을 구분하는 이름이며 읽기 수준 번호와 다릅니다. 프로그램이 바뀐 부분과 당시 남아 있는 자료의 범위를 함께 확인하세요.

[이 차수 보존 소스](../../../history/1.7.0)

이 자료가 어떤 시점에 무엇을 위해 남았는지부터 확인합니다. **보존 소스**는 당시 코드를 담은 자료이고 **실행 제품**은 필요한 자산·외부 도구까지 갖춘 결과입니다. 아래 설명에 없는 후속 기능을 자동으로 포함시키지 않습니다.


파일별 사전 점검과 사용자 프리셋으로 변환·PDF 작업의 반복 입력을 줄입니다.

<a id="level-1-section-2"></a>
### LEVEL 1 · 핵심 기능과 보존 범위


일반 변환은 파일을 다른 형식으로 만들고 PDF 도구는 쪽을 편집하거나 글자를 읽습니다. 둘 다 **원본을 그대로 두고 새 결과**를 확인하는 흐름입니다. 아래 표의 보존·비교 조건도 기능 범위에 포함되므로 실행 자산이 빠진 점을 함께 읽으세요.

[이 차수 보존 소스](../../../history/1.7.0)

아래 기능은 이 자료에서 읽을 수 있는 역할입니다. 입력을 고르는 일, 변환하는 일, 결과를 살피는 일은 따로 확인합니다. 원본은 남기고 새 결과를 확인하며 기능 이름이 있다는 사실만으로 모든 파일에서 성공하는 것은 아닙니다.


| 항목 | 이 차수에서 확인할 내용 |
| --- | --- |
| 1 | 파일별 사전 점검과 사용자 프리셋으로 변환·PDF 작업의 반복 입력을 줄입니다. |
| 2 | 실제 보존 파일의 공개 가능한 Python·고정 의존성·기존 라이선스만 바이트 그대로 수록했습니다.<br>실행 자산·개인 작업 기록·설치 바이너리는 이 사본에 포함하지 않습니다. |
| 3 | 비교 대상: [1.6.0](../../versions/1.6.0.md#user-content-reading-level-1).<br>확인 가능한 앞선 보존 버전과의 비교이며, 중간 버전 전체가 존재한다는 뜻은 아닙니다. |

<a id="level-1-section-3"></a>
### LEVEL 1 · 입력·처리·출력


예를 들어 사진을 PDF로 묶을 때 사진들이 입력, 묶는 작업이 처리, 새 PDF가 출력입니다. 반대로 PDF를 그림으로 만들면 쪽마다 그림 결과가 생길 수 있습니다. 목표 확장자를 적는 일만으로 변환이 끝나는 것은 아닙니다.

[이 차수 보존 소스](../../../history/1.7.0)

입력은 사용자가 고른 원래 파일, 처리는 선택한 변환이나 페이지 작업, 출력은 새 파일이나 기록입니다. 예를 들어 그림을 PDF로 묶으면 원래 그림과 새 PDF는 다른 파일입니다. 자료를 찾는 보관 문서에서는 입력·출력이 파일 변환이 아니라 출처와 목록을 읽는 과정일 수 있습니다.


| 단계 | 내용 |
| --- | --- |
| 입력 | 사용자가 고른 로컬 파일과 목표 형식·PDF 작업 옵션 |
| 처리 | 파일 분류 → 작업 선택 → 변환 도구·PDF 처리 → 새 결과 저장 |
| 출력 | 새 형식 파일·편집 PDF·OCR 문서·작업 기록 |

<a id="level-1-section-4"></a>
### LEVEL 1 · 화면과 사용 흐름


파일 선택·작업 선택·실행·결과 열기의 순서로 사용합니다. PDF 회전은 돌릴 쪽을 먼저 고르고, 추출은 남길 쪽을 고릅니다. 최근 기록은 결과를 찾는 길이며 기록에서 결과 위치를 여는 것과 파일 자체를 실행하는 것은 다릅니다.

[이 차수 보존 소스](../../../history/1.7.0)

첫째 원본과 필요한 준비물을 확인하고, 둘째 지원하는 작업·형식을 고르며, 셋째 실행 뒤 새 결과를 엽니다. 오류가 나면 이유를 읽고 원본을 그대로 둡니다. 화면이나 파일을 찾는 단계도 동작의 일부이며 확인되지 않은 부분본을 무리하게 실행하지 않습니다.


1. 변환할 원본을 별도로 보존하고 처리할 파일을 선택합니다.
2. 파일별 큐와 프리셋을 선택하고 사전 점검의 입력·도구·쓰기 권한·공간 상태를 읽습니다.
3. 지원하는 목표 형식 또는 PDF 작업을 고르고 출력 위치·페이지·품질을 확인합니다.
4. 상태와 오류를 읽고 완성된 결과 파일을 열어 형식·페이지·내용을 확인합니다.
5. 최근 기록의 경로로 결과를 찾고 개인 파일 경로가 포함된 기록은 소스와 분리합니다.

### LEVEL 1 · 주요 모듈과 코드 읽기


먼저 화면에서 어떤 파일과 작업을 고르는지 app·pdf _panel을 읽고, 결과 만드는 과정은 engine·pdf _tools에서 찾습니다. build·package는 배포 제작용이므로 평소 변환을 하려고 실행할 파일이 아닙니다.

[이 차수 보존 소스](../../../history/1.7.0)

모듈은 비슷한 일을 모아 놓은 코드 파일입니다. 화면을 보이는 부분, 파일을 바꾸는 부분, 오류와 기록을 남기는 부분이 나뉘어 있습니다. 아래 역할을 알고 보면 파일 이름만 읽는 것보다 동작을 찾기 쉽습니다.


| 파일 | 원문에 정의된 역할·구성 |
| --- | --- |

Windows Python 환경에서 이 보존 본의 고정 의존성 목록과 assets 참조를 확인합니다. OCR은 Tesseract 실행 파일과 언어 자료, 미디어는 FFmpeg, Office 변환은 LibreOffice 등 기능별 외부 도구가 필요합니다.

이 차수의 `app.main`은 `python app.py --settings`에서 설정 창을 열고 인자 없는 실행에서는 트레이에 상주합니다. 위 준비와 실행 설명은 당시 코드의 분기 설명이며 이번 편집에서 실제 앱을 재실행한 결과가 아닙니다.

### LEVEL 1 · 프리셋과 실행 전 점검


아래 이름·숫자는 저장할 설정의 허용 범위입니다.

**회전 90/180/270은 쪽을 돌릴 각도**, 품질 20~95는 그림을 다시 압축할 때의 값, DPI60~600은 글자 인식·그림 출력의 해상도입니다.

PSM은 글자 배치를 읽는 방식으로 3은 자동, 6은 한 덩어리 글자 영역(단일 블록), 11은 흩어진 글자에 해당합니다. lossless는 이미지 재압축 없이 정리, images는 이미지 크기·품질을 바꿀 수 있는 압축이므로 작은 글자와 그림을 다시 확인하세요.

`PresetStore`는 UTF-8 JSON 배열을 읽습니다.

이름은 양 끝 공백 제거 후 1~80 자이고 제어 문자를 거부하며 대소문자를 무시한 중복 이름을 허용하지 않습니다.

허용 키는 `name`, `kind`, `format`, `options`이고 일반 변환 프리셋은 빈 options만 받습니다.

입력/출력 경로를 프리셋에 끼워 넣지 않습니다.

PDF 옵션은 `Request`의 기본 값을 합친 뒤 검사합니다.

회전 90/180/270, 품질 20~95, DPI 60~600, PSM 3/6/11, 압축 lossless/images, OCR 언어 kor+eng/kor/eng를 허용합니다.

페이지 문자열은 최대 10,000 자이고 1부터 시작하는 단일 번호·범위·쉼표 목록 형식을 검사합니다.

읽기 오류가 난 프리셋 파일은 `error`에 원문을 남기고 쓰기를 차단합니다. 정상 저장은 같은 폴더의 임시 파일에 UTF-8 JSON을 쓰고 flush/fsync 후 교체합니다. 기본 프리셋은 JPG 변환 `photo_jpg`와 한국어+영어 OCR PDF `scan_pdf`입니다.

`preflight(path, dst)`는 입력 존재 →지원 출력 →외부 도구 →입력 읽기 →여유 공간 →쓰기 가능 순서로 점검합니다.

OCR은 스캔 그림에서 글자를 추정하는 일입니다. `structured_rows`는 글자의 높이·간격으로 표를 추정하므로 열과 숫자를 원본과 대조해야 합니다.

여러 파일 처리 중 취소해도 앞서 완성한 결과는 남고 현재 작업은 오류·취소로 구분됩니다.

기본 요청은 회전 90도·압축 lossless·품질 80·DPI 200·언어 kor+eng·PDF 출력·force_ocr=False·PSM 3입니다. lossless는 PDF 구조 정리로 용량 감소를 보장하지 않고 images는 그림을 줄이거나 다시 압축해 품질을 낮출 수 있습니다.

PSM3/6/11은 자동/단일 블록/흩어진 글자 선택이며 한글·영문 자료에 맞춰 언어를 고릅니다.

검색 PDF는 그림에 검색 글자를 더한 결과이고 DOCX/XLSX의 행·열 추론은 원문 배치를 완전히 복원한다는 보장이 아닙니다.

`preflight_request`는 입력 형식·OCR 도구/언어 자료와 실제 출력 위치를 검사하고 같은 볼륨의 준비 공간을 합산합니다.

일반 작업은 입력 4 배 +64MiB, 래스터·OCR은 8 배 +128MiB와 모델 크기를 포함하는 추정입니다. `preflight_output`의 쓰기·여유 확인은 공간 예약이 아닙니다. `_serialized_pdfium`은 미리보기와 같은 공용 잠금으로 네이티브 호출을 직렬화합니다.

### LEVEL 1 · 처리 결과와 출력 읽기

| 항목 | 동작·확인 |
|---|---|
| 파일 | 변환할 파일을 목록에 넣습니다. |
| 프리셋 | 저장한 형식과 PDF 설정을 선택합니다. |
| 결과 | 준비 상태와 실제 변환 결과를 구분해 확인합니다. |



새 파일이 생기면 원본 옆에서 이름과 내용을 확인합니다. PDF는 쪽 수·순서·방향, 그림은 열림·해상도, 영상·소리는 재생, OCR은 글자·표를 봅니다. **완료 표시와 내용 검수는 다릅니다.** 기록의 경로에는 개인 정보가 들어갈 수 있어 공개 자료에 그대로 붙이지 않습니다.

[이 차수 보존 소스](../../../history/1.7.0)

결과는 파일이 생겼는지만 보지 않고 열어 내용·페이지·형식이 맞는지 봅니다. OCR은 그림에서 글자를 추정하므로 표의 행·열과 배치는 틀릴 수 있습니다. 기록에는 경로·오류가 들어갈 수 있어 그대로 공개하지 않습니다.


결과 파일은 원본과 구분해 확인합니다. 입력·출력 경로와 오류가 기록에 포함될 수 있습니다. PDF OCR의 행·열·배치 복원은 입력 문서에 따라 달라집니다.

## LEVEL 2 - Explorer · 구성과 처리 관계

[같은 수준 프로젝트](../../%EC%9D%BD%EA%B8%B0%EC%95%88%EB%82%B4/%EB%A0%88%EB%B2%A82.md) · [같은 수준 프로필](https://github.com/PUVKID/PUVKID/blob/main/docs/읽기안내/레벨2.md) · [LEVEL 1 - Beginner](../../versions/1.7.0.md#user-content-reading-level-1) · [LEVEL 2 - Explorer](../../versions/1.7.0.md#user-content-reading-level-2) · [LEVEL 3 - Practitioner](../../versions/1.7.0.md#user-content-reading-level-3) · [LEVEL 4 - Advanced](../../versions/1.7.0.md#user-content-reading-level-4) · [LEVEL 5 - Expert](../../versions/1.7.0.md#user-content-reading-level-5) · [프로젝트 첫 화면](../../../README.md)

파일 큐와 프리셋은 app의 선택 흐름을 `flipring_workflow.py`의 검증·점검과 연결합니다. 입력·도구·쓰기·공간 조건을 작업 전에 확인하여 어떤 준비가 부족한지 표시하고, 실제 변환은 엔진·PDF 처리 경로로 이어집니다. 프리셋을 불러온 사실과 특정 파일이 그 설정으로 성공한 사실을 구분합니다.

1.6.0과 비교할 때 공통 UI 위에 반복 작업을 줄이는 흐름이 어떻게 연결되는지 봅니다. PDF 관련 잠금·페이지 처리 등 보존 모듈도 원문과 함께 읽어야 화면에 보이는 준비 상태와 실제 처리 경계를 연결할 수 있습니다.

<a id="level-2-section-1"></a>
### LEVEL 2 · 목적과 이 차수의 역할


버전의 새 화면 구성과 기존 변환·PDF 처리 경로를 구분합니다. 보존 파일과 직전 비교는 변경의 근거이고 테스트 코드 목록은 검사할 동작의 근거입니다. 어느 쪽도 이번 편집에서 과거 실행을 다시 수행했다는 뜻은 아닙니다.

[이 차수 보존 소스](../../../history/1.7.0)

목적과 보존 범위가 기능 해석의 출발점입니다. 같은 파일명이라도 시점과 경로가 다르면 기능 집합과 환경이 달라지므로 자료의 관계를 먼저 고정합니다.

위 관계에 연결되는 원문의 사실과 조건은 다음과 같습니다.

파일별 사전 점검과 사용자 프리셋으로 변환·PDF 작업의 반복 입력을 줄입니다.

<a id="level-2-section-2"></a>
### LEVEL 2 · 핵심 기능과 보존 범위


화면 입력과 엔진 처리는 이어지지만 보존 범위는 별도입니다. 공개 Python·고정 의존성과 라이선스는 코드 재검토 근거이고 실행 자산·개인 작업 기록·설치 바이너리의 제외는 제품 기능 삭제를 뜻하지 않습니다.

[이 차수 보존 소스](../../../history/1.7.0)

기능 목록을 입력·실행·표시·검토로 연결해 읽습니다. 화면 표시 변경은 처리 엔진의 변경과 다르고, 파일 처리 성공도 결과 품질이나 목표 충족과 다릅니다.

행의 항목들이 기능·자료·조건을 어떻게 연결하는지 비교합니다.

| 2 | 실제 보존 파일의 공개 가능한 Python·고정 의존성·기존 라이선스만 바이트 그대로 수록했습니다.<br>실행 자산·개인 작업 기록·설치 바이너리는 이 사본에 포함하지 않습니다. |

<a id="level-2-section-3"></a>
### LEVEL 2 · 입력·처리·출력


파일 분류가 일반 변환 목표를 제한하고 PDF 작업은 요청의 operation으로 나뉩니다. 임시 생성 물과 최종 결과 파일을 구분하며 기록은 그 결과 경로·오류를 나중에 찾는 별도 산출물입니다.

[이 차수 보존 소스](../../../history/1.7.0)

<a id="level-2-section-4"></a>
### LEVEL 2 · 화면과 사용 흐름


파일 선택은 입력 상태를, 형식·PDF 옵션은 요청 상태를, 작업 시작과 종료는 실행 상태를 바꿉니다. 기록과 미리보기는 결과 확인을 돕지만 서로 대신하지 않습니다. 메뉴·버튼의 짧은 반응도 실제 요청과 분리해 읽습니다.

[이 차수 보존 소스](../../../history/1.7.0)

사용 흐름은 입력 선택·옵션 확정·실행·결과 검토의 상태 전이입니다. 표시가 바뀌는 것과 실제 처리가 끝나는 것은 다르며 취소와 완료 결과 보존이 함께 성립할 수 있습니다.

위 관계에 연결되는 원문의 사실과 조건은 다음과 같습니다.

1. 변환할 원본을 별도로 보존하고 처리할 파일을 선택합니다.
2. 파일별 큐와 프리셋을 선택하고 사전 점검의 입력·도구·쓰기 권한·공간 상태를 읽습니다.
3. 지원하는 목표 형식 또는 PDF 작업을 고르고 출력 위치·페이지·품질을 확인합니다.
4. 상태와 오류를 읽고 완성된 결과 파일을 열어 형식·페이지·내용을 확인합니다.
5. 최근 기록의 경로로 결과를 찾고 개인 파일 경로가 포함된 기록은 소스와 분리합니다.

### LEVEL 2 · 프리셋과 실행 전 점검


프리셋 저장은 이름·kind·format·options의 검증, 현재 파일 실행은 preflight의 도구·공간 검증으로 분리됩니다.

Request 기본값은 회전 90·품질 80·DPI 200·PSM 3·kor+eng·lossless·PDF 출력·force_ocr=False입니다.

옵션 일부만 저장해도 기본값과 합쳐 전체 범위를 검사합니다. kor/eng/kor+eng는 인식 언어와 필요한 모델을 결정하고 출력 형식은 OCR의 pdf/txt/docx/xlsx 또는 PDF 그림 변환의 png/jpg로 작업별 제한됩니다.

[이 차수 보존 소스](../../../history/1.7.0)

사용 흐름은 입력 선택·옵션 확정·실행·결과 검토의 상태 전이입니다. 표시가 바뀌는 것과 실제 처리가 끝나는 것은 다르며 취소와 완료 결과 보존이 함께 성립할 수 있습니다.

위 관계에 연결되는 원문의 사실과 조건은 다음과 같습니다.

`PresetStore`는 UTF-8 JSON 배열을 읽습니다.

이름은 양 끝 공백 제거 후 1~80 자이고 제어 문자를 거부하며 대소문자를 무시한 중복 이름을 허용하지 않습니다.

허용 키는 `name`, `kind`, `format`, `options`이고 일반 변환 프리셋은 빈 options만 받습니다.

입력/출력 경로를 프리셋에 끼워 넣지 않습니다.

PDF 옵션은 `Request`의 기본 값을 합친 뒤 검사합니다.

회전 90/180/270, 품질 20~95, DPI 60~600, PSM 3/6/11, 압축 lossless/images, OCR 언어 kor+eng/kor/eng를 허용합니다.

페이지 문자열은 최대 10,000 자이고 1부터 시작하는 단일 번호·범위·쉼표 목록 형식을 검사합니다.

OCR 출력은 pdf/txt/docx/xlsx, 이미지 변환은 png/jpg로 제한합니다.

읽기 오류가 난 프리셋 파일은 `error`에 원문을 남기고 쓰기를 차단합니다. 정상 저장은 같은 폴더의 임시 파일에 UTF-8 JSON을 쓰고 flush/fsync 후 교체합니다. 기본 프리셋은 JPG 변환 `photo_jpg`와 한국어+영어 OCR PDF `scan_pdf`입니다.

`preflight(path, dst)`는 입력 존재 →지원 출력 →외부 도구 →입력 읽기 →여유 공간 →쓰기 가능 순서로 점검합니다.

입력 4 배 +64MiB는 보수적인 준비 공간 추정 값이며 최종 출력 크기가 아닙니다. `missing`, `unsupported`, `helper`, `space`, `write`, `input` 오류 코드를 `error`와 함께 반환하고 통과 때만 `ok=true`, `code=ready`가 됩니다.

### LEVEL 2 · pdf_tools.py


`Request`의 작업·페이지·해상도·출력 형식이 `execute`의 분기를 고릅니다. `source_context`는 실패한 실제 입력 경로를 예외에 연결하고 `page_indices`는 사용자 쪽 번호를 처리 인덱스로 바꿉니다.

OCR 하위 프로세스는 `_ProcessTree`의 Windows Job으로 묶여 종료 시 후손도 함께 정리됩니다.

단어 좌표 → `structured_rows`의 행·열 추론 → TXT/DOCX/XLSX 또는 검색 PDF 생성은 각각 검수해야 하는 단계입니다.

기본 요청은 회전 90도·압축 lossless·품질 80·DPI 200·언어 kor+eng·PDF 출력·force_ocr=False·PSM 3입니다. lossless는 PDF 구조 정리로 용량 감소를 보장하지 않고 images는 그림을 줄이거나 다시 압축해 품질을 낮출 수 있습니다.

PSM3/6/11은 자동/단일 블록/흩어진 글자 선택이며 한글·영문 자료에 맞춰 언어를 고릅니다.

검색 PDF는 그림에 검색 글자를 더한 결과이고 DOCX/XLSX의 행·열 추론은 원문 배치를 완전히 복원한다는 보장이 아닙니다.

`preflight_request`는 입력 형식·OCR 도구/언어 자료와 실제 출력 위치를 검사하고 같은 볼륨의 준비 공간을 합산합니다.

일반 작업은 입력 4 배 +64MiB, 래스터·OCR은 8 배 +128MiB와 모델 크기를 포함하는 추정입니다. `preflight_output`의 쓰기·여유 확인은 공간 예약이 아닙니다. `_serialized_pdfium`은 미리보기와 같은 공용 잠금으로 네이티브 호출을 직렬화합니다.

[pdf_tools.py의 이 차수 코드](../../../history/1.7.0/pdf_tools.py)


- [`_serialized_pdfium`](../../../history/1.7.0/pdf_tools.py#L29)의 역할: PDF 도구와 미리보기가 같은 네이티브 런타임에 동시에 진입하지 않는다. 
- [`source_context`](../../../history/1.7.0/pdf_tools.py#L50)의 역할: 실제로 처리 중인 입력을 예외에 붙인다. 표시 문자열에서 경로를 추정하지 않는다. 
- [`preflight_output`](../../../history/1.7.0/pdf_tools.py#L105)의 역할: 실제 출력 위치를 점검한다. 예상량은 최종 크기나 공간 확보 보장이 아니다. 
- [`preflight_request`](../../../history/1.7.0/pdf_tools.py#L131)의 역할: 출력 경로·같은 볼륨의 준비 공간을 합산하며 무거운 PDF 처리는 시작하지 않는다. 
- [`page_indices`](../../../history/1.7.0/pdf_tools.py#L207)의 역할: 1부터 시작하는 범위를 검증하고 사용자가 쓴 페이지 순서를 유지한다. 예를 들어 1,3-5는 첫 페이지와 3~5쪽을 고르는 표현이며 잘못된 범위를 확인해야 합니다.
- [`_ProcessTree`](../../../history/1.7.0/pdf_tools.py#L257)의 역할: Windows Job Object를 닫아 OCR 프로세스와 그 자식을 함께 종료한다. 
- [`structured_rows`](../../../history/1.7.0/pdf_tools.py#L439)의 역할: 같은 높이의 단어와 큰 가로 간격을 이용해 행·열을 추론한다. 같은 줄·큰 간격을 단서로 표를 추정하므로 실제 표의 칸이 항상 맞는 것은 아닙니다.
- [`execute`](../../../history/1.7.0/pdf_tools.py#L636)의 역할: 결과별 (입력, 출력, 오류) 콜백. 취소/실패 시 완성한 앞선 결과는 유지한다. 여러 파일 중 먼저 끝난 결과는 뒤의 취소나 실패 때문에 사라지지 않습니다.

이 값들은 UI·도구 탐색·저장·검증의 기본 조건을 연결합니다.

## LEVEL 3 - Practitioner · 준비·절차·오류 확인

이번 입력 파일 목록과 적용할 프리셋을 확인한 뒤 파일별 사전 점검의 입력·도구·쓰기·공간 상태를 읽습니다. 실패 원인을 해결하지 않은 파일을 준비 완료로 취급하지 않습니다. PDF 작업은 페이지·출력 형식·품질도 확인하고 실행 뒤 쪽수·문자·표를 원본과 비교합니다.

프리셋 재사용 시 지난 작업의 설정이 이번 문서에도 적합한지 다시 확인합니다. 기록에는 개인 경로가 있을 수 있어 공개 소스와 분리합니다. 이 후보는 사용 절차를 설명하며 새 실행·성능 개선 수치를 만들지 않습니다.

### LEVEL 3 · 목적과 이 차수의 역할


먼저 이 버전의 소스 폴더·앞선 비교 버전을 고정하고 준비물을 확인합니다. 필요한 실행 자산이 빠진 공개 보존본은 그대로 제품 설치본처럼 실행하지 않습니다. 아래 사용 절차와 원문 검증 범위를 나눠 기록합니다.

[이 차수 보존 소스](../../../history/1.7.0)

시작 전에 차수명·원래 경로·필수 자산·외부 도구와 실제 결과 기록을 확인합니다. 부분본은 완전한 실행 환경이 아니므로 준비되지 않은 동작을 성공으로 기록하지 않습니다.

준비·실행·검수에서 적용할 구체 조건은 다음과 같습니다.

파일별 사전 점검과 사용자 프리셋으로 변환·PDF 작업의 반복 입력을 줄입니다.

### LEVEL 3 · 설치 환경과 실행·사용법

준비·실행·검수에서 적용할 구체 조건은 다음과 같습니다.

Windows Python 환경에서 이 보존 본의 고정 의존성 목록과 assets 참조를 확인합니다. OCR은 Tesseract 실행 파일과 언어 자료, 미디어는 FFmpeg, Office 변환은 LibreOffice 등 기능별 외부 도구가 필요합니다.

이 차수의 `app.main`은 `python app.py --settings`에서 설정 창을 열고 인자 없는 실행에서는 트레이에 상주합니다. 위 준비와 실행 설명은 당시 코드의 분기 설명이며 이번 편집에서 실제 앱을 재실행한 결과가 아닙니다.
