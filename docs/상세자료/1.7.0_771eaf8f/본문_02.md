### LEVEL 3 · flipring_workflow.py


JPG 변환용 또는 OCR용 프리셋을 고른 뒤 현재 입력·목표를 대조합니다. missing이면 이동한 입력, unsupported이면 입력과 목표 조합, helper이면 필요한 도구, space이면 원본 옆 볼륨 여유, write이면 저장 권한을 확인합니다. input은 그 밖의 입력 읽기 오류입니다.

손상된 프리셋은 error를 확인하고 원본 JSON을 보존해야하며 빈 목록으로 덮어쓰지 않습니다.

### LEVEL 3 · package.py


포장 전 소스 licenses와 프로그램에 들어갈 고지·상응 소스를 모두 준비합니다. 오류가 출처·경로·중복·크기·해시 중 어디에 속하는지 읽고 원래 출하 목록과 실제 파일을 대조합니다. 생성된 SHA 목록은 실제 실행·설치 확인과 함께 읽되 이번에 과거 설치 본을 다시 실행했다고 기록하지 않습니다.

OCR은 Tesseract와 선택 언어 자료를 준비한 뒤 검색 PDF의 검색·복사, TXT 문장, DOCX 표와 XLSX 셀을 원본에 대조합니다. `execute`의 결과 콜백에서 입력·출력·오류를 파일별로 읽어 일부 완료와 전체 성공을 구분합니다.

PSM3/6/11은 자동/단일 블록/흩어진 글자 선택이며 한글·영문 자료에 맞춰 언어를 고릅니다.

검색 PDF는 그림에 검색 글자를 더한 결과이고 DOCX/XLSX의 행·열 추론은 원문 배치를 완전히 복원한다는 보장이 아닙니다.

일반 작업은 입력 4 배 +64MiB, 래스터·OCR은 8 배 +128MiB와 모델 크기를 포함하는 추정입니다. `preflight_output`의 쓰기·여유 확인은 공간 예약이 아닙니다. `_serialized_pdfium`은 미리보기와 같은 공용 잠금으로 네이티브 호출을 직렬화합니다.

프리셋의 영속 설정과 파일별 준비 관측은 수명이 다릅니다. 저장 당시 유효한 설정이라도 현재 도구·권한·공간이 달라질 수 있으므로 실행 전 점검이 별도로 필요합니다. 점검 성공을 출력 게시 성공과 동일 상태로 합치면 실행 중 오류를 놓치게 됩니다.

### LEVEL 4 · 목적과 이 차수의 역할


차수 경계는 설치 설정·보존 소스·실제 비교 대상으로 정합니다. 내부 설정 스키마 VERSION과 제품 AppVersion을 같은 숫자로 추정하지 않습니다. 후속 문서 엔진이나 HWP 저장 구현을 이 과거 버전에 소급하지 않습니다.

[이 차수 보존 소스](../../../history/1.7.0)

이 절은 변경의 기준과 비목표를 고정합니다. 구현 존재·보존 파일·실제 수행·배포를 분리하고 알려지지 않은 직전 단계는 추정하지 않습니다.

변경 영향 검토에 포함할 원문의 경계와 관측은 다음과 같습니다.

파일별 사전 점검과 사용자 프리셋으로 변환·PDF 작업의 반복 입력을 줄입니다.

### LEVEL 4 · 설치 환경과 실행·사용법


--settings는 argparse 공통 CLI가 아니라 sys.argv 포함 여부로 처리됩니다. setQuitOnLastWindowClosed(False)와 QLockFile의 running.lock이 상주·중복 실행 정책을 구성합니다. app.

[이 차수 보존 소스](../../../history/1.7.0)

변경 영향 검토에 포함할 원문의 경계와 관측은 다음과 같습니다.

Windows Python 환경에서 이 보존 본의 고정 의존성 목록과 assets 참조를 확인합니다. OCR은 Tesseract 실행 파일과 언어 자료, 미디어는 FFmpeg, Office 변환은 LibreOffice 등 기능별 외부 도구가 필요합니다.

이 차수의 `app.main`은 `python app.py --settings`에서 설정 창을 열고 인자 없는 실행에서는 트레이에 상주합니다. 위 준비와 실행 설명은 당시 코드의 분기 설명이며 이번 편집에서 실제 앱을 재실행한 결과가 아닙니다.

### LEVEL 4 · 프리셋과 실행 전 점검


PresetStore.validate는 허용키 밖의 경로 주입을 거부하고 일반 변환의 nonempty options를 막습니다.

PDF는 Request 기본 값을 복사·병합한 뒤 bool과 int를 구분하는 타입 검사, 회전·품질·DPI·PSM 집합, 언어·압축·작업별 출력·최대 10,000자 페이지 문법을 확인합니다.

페이지 수에 맞는 유효성은 실제 PDF 실행에서 추가 확인됩니다.

손상 load의 error가 있으면 쓰기를 막고 정상 쓰기는 임시 파일 fsync →replace로 갱신합니다.

준비 공간 4 배 +64MiB는 예약이나 최종 크기가 아닙니다.

[이 차수 보존 소스](../../../history/1.7.0)

각 조작이 요청·작업자·저장·GUI 슬롯으로 이어지는 경계를 읽습니다. 재진입·중복 실행·숨김·종료와 언어/모션 설정 전환이 요청값을 바꾸지 않아야 합니다.

변경 영향 검토에 포함할 원문의 경계와 관측은 다음과 같습니다.

`PresetStore`는 UTF-8 JSON 배열을 읽습니다.

이름은 양 끝 공백 제거 후 1~80 자이고 제어 문자를 거부하며 대소문자를 무시한 중복 이름을 허용하지 않습니다.

허용 키는 `name`, `kind`, `format`, `options`이고 일반 변환 프리셋은 빈 options만 받습니다.

입력/출력 경로를 프리셋에 끼워 넣지 않습니다.

PDF 옵션은 `Request`의 기본 값을 합친 뒤 검사합니다.

회전 90/180/270, 품질 20~95, DPI 60~600, PSM 3/6/11, 압축 lossless/images, OCR 언어 kor+eng/kor/eng를 허용합니다.

페이지 문자열은 최대 10,000 자이고 1부터 시작하는 단일 번호·범위·쉼표 목록 형식을 검사합니다.

OCR 출력은 pdf/txt/docx/xlsx, 이미지 변환은 png/jpg로 제한합니다.

읽기 오류가 난 프리셋 파일은 `error`에 원문을 남기고 쓰기를 차단합니다. 정상 저장은 같은 폴더의 임시 파일에 UTF-8 JSON을 쓰고 flush/fsync 후 교체합니다. 기본 프리셋은 JPG 변환 `photo_jpg`와 한국어+영어 OCR PDF `scan_pdf`입니다.

`preflight(path, dst)`는 입력 존재 →지원 출력 →외부 도구 →입력 읽기 →여유 공간 →쓰기 가능 순서로 점검합니다.

입력 4 배 +64MiB는 보수적인 준비 공간 추정 값이며 최종 출력 크기가 아닙니다. `missing`, `unsupported`, `helper`, `space`, `write`, `input` 오류 코드를 `error`와 함께 반환하고 통과 때만 `ok=true`, `code=ready`가 됩니다.

현재 값·사각형을 읽은 뒤 새 animation을 시작하므로 빠른 재진입에서도 초기 프레임으로 튀지 않습니다.

늦게 생성되는 팝업에는 MotionSystem의 이벤트 경로가 필요합니다.

파일 모델·선택 필터·표준 버튼 반환 코드는 외형 변경과 분리하며 모 달 반환 후 모션·표면은 지연 해제합니다.

도움말에서 rich text 실행을 허용하거나 투명 레이어가 입력을 먹지 않도록합니다.

`start_motion`은 모션 줄이기에서도 최종 프레임·완료 신호를 적용합니다. 효과를 끄는 것이 작업 완료나 버튼 상태 갱신을 끄는 뜻은 아닙니다.

## 설치 환경과 실행·사용법

Windows Python 환경에서 이 보존 본의 고정 의존성 목록과 assets 참조를 확인합니다. OCR은 Tesseract 실행 파일과 언어 자료, 미디어는 FFmpeg, Office 변환은 LibreOffice 등 기능별 외부 도구가 필요합니다.

이 차수 소스 폴더에서 고정 의존성과 필요한 자산·외부 도구를 준비한 뒤 `python app.py`로 시작합니다. `--settings` 지원 여부는 아래 CLI 표와 해당 차수의 main을 확인합니다. 인자 없는 실행이 트레이로 시작하는 구성에서는 트레이 메뉴로 창을 엽니다.

<a name="-이-차수-원래-안내의-세부-조건"></a>
### 이 차수 원래 안내의 세부 조건

### 코드·화면·설정·검사의 확인 범위

1.6 대비 app.py에 파일별 큐, flipring_workflow.py에 프리셋·사전 점검, preview _panel.py에 실제 이미지 비교, pdf _pages.py에 페이지 편집 모델, pdf_lock.py에 공용 PDFium 잠금을 추가했습니다. app.py는 전용 설정·큐·프리셋·미리 보기와 모션 감소를 연결하며 pdf_panel.py는 썸네일 순서·선택·회전·삭제·추출·확대·저장을 제공합니다. engine.py는 짧은 독립 LibreOffice 프로필과 동봉 7-Zip RAR 처리·취소 회수를 포함합니다. build.py는 1.7.0과 별도 출력 경로를 사용하고 package.py는 새 코드·자산·7-Zip 고지와 상응 소스의 크기·해시를 검증합니다. test_workbench.py·test_pdf_workspace.py·test _conversion _matrix.py가 추가되며 기존 PDF 검사 원문은 변경하지 않았습니다.

화면·설정·실패 경로·검사의 세부 파일 차이와 공백·주석은 아래 전체 패치에 포함됩니다.

실제 보존 파일의 공개 가능한 Python·고정 의존성·기존 라이선스만 바이트 그대로 수록했습니다. 실행 자산·개인 작업 기록·설치 바이너리는 이 사본에 포함하지 않습니다.

### 프리셋과 실행 전 점검

`PresetStore`는 UTF-8 JSON 배열을 읽습니다.

이름은 양 끝 공백 제거 후 1~80 자이고 제어 문자를 거부하며 대소문자를 무시한 중복 이름을 허용하지 않습니다.

허용 키는 `name`, `kind`, `format`, `options`이고 일반 변환 프리셋은 빈 options만 받습니다.

입력/출력 경로를 프리셋에 끼워 넣지 않습니다.

PDF 옵션은 `Request`의 기본 값을 합친 뒤 검사합니다.

회전 90/180/270, 품질 20~95, DPI 60~600, PSM 3/6/11, 압축 lossless/images, OCR 언어 kor+eng/kor/eng를 허용합니다.

페이지 문자열은 최대 10,000 자이고 1부터 시작하는 단일 번호·범위·쉼표 목록 형식을 검사합니다.

OCR 출력은 pdf/txt/docx/xlsx, 이미지 변환은 png/jpg로 제한합니다.

읽기 오류가 난 프리셋 파일은 `error`에 원문을 남기고 쓰기를 차단합니다. 정상 저장은 같은 폴더의 임시 파일에 UTF-8 JSON을 쓰고 flush/fsync 후 교체합니다. 기본 프리셋은 JPG 변환 `photo_jpg`와 한국어+영어 OCR PDF `scan_pdf`입니다.

`preflight(path, dst)`는 입력 존재 →지원 출력 →외부 도구 →입력 읽기 →여유 공간 →쓰기 가능 순서로 점검합니다.

입력 4 배 +64MiB는 보수적인 준비 공간 추정 값이며 최종 출력 크기가 아닙니다. `missing`, `unsupported`, `helper`, `space`, `write`, `input` 오류 코드를 `error`와 함께 반환하고 통과 때만 `ok=true`, `code=ready`가 됩니다.

<a name="️-제약과-문제-해결"></a>
## 제약과 문제 해결

| 항목 | 동작·확인 |
|---|---|
| 보존 범위 | Python·고정 의존성·기존 라이선스를 보존합니다. |
| 비교 | 확인 가능한 직전 보존본 1.6.0과 비교합니다. |
| 제약 | 실행 자산·설치 바이너리와 개인 작업 기록은 이 사본에 없습니다. |


**상황:** 앱 시작 시 자산 오류

**확인할 내용:** 참조하는 글꼴·아이콘·자산 경로를 확인합니다. 역사 소스는 설치 바이너리와 모든 실행 자산을 포함하지 않습니다.

**상황:** 변환 도구를 찾지 못함

**확인할 내용:** 선택 형식에 필요한 FFmpeg·Pandoc·LibreOffice·Tesseract와 검색 경로를 확인합니다.

**상황:** 페이지 선택이 거부됨

**확인할 내용:** 실제 페이지 수와 1부터 시작하는 범위를 확인합니다. 암호화 PDF의 처리 정책도 확인합니다.
