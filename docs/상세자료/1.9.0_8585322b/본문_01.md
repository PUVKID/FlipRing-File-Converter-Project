## LEVEL 1 - Beginner · 목적부터 결과 확인까지

[같은 수준 프로젝트](../../%EC%9D%BD%EA%B8%B0%EC%95%88%EB%82%B4/%EB%A0%88%EB%B2%A81.md) · [같은 수준 프로필](https://github.com/PUVKID/PUVKID/blob/main/docs/읽기안내/레벨1.md) · [LEVEL 1 - Beginner](../../versions/1.9.0.md#reading-level-1) · [LEVEL 2 - Explorer](../../versions/1.9.0.md#reading-level-2) · [LEVEL 3 - Practitioner](../../versions/1.9.0.md#reading-level-3) · [LEVEL 4 - Advanced](../../versions/1.9.0.md#reading-level-4) · [LEVEL 5 - Expert](../../versions/1.9.0.md#reading-level-5) · [프로젝트 첫 화면](../../../README.md)

여러 파일을 모아 **처리 순서와 목표**를 정하는 작업 공간 버전입니다. 레시피는 반복할 단계의 저장 목록입니다. 예를 들어 이미지를 모아 PDF로 만들고 이름을 정한 새 결과를 확인합니다. Ctrl +K 명령 검색, 이름 바꾼 복사 본, 기록 검색/필터, 클립 보드와 직접 시작한 영역 캡처도 연결합니다.

<a id="level-1-section-1"></a>
### LEVEL 1 · 목적과 이 차수의 역할

파일을 모아 레시피로 처리 순서를 구성하고, OCR 교정과 개인정보 후보 검토까지 한 작업 공간에서 이어 가도록 확장했습니다. 원본을 보존한 결과 저장과 사용자 확인을 유지합니다.

| 3 | - Ctrl+K 명령 검색, 이름 규칙에 따른 복사본 생성, 기록 검색·필터·복사·탐색기 선택. - 카드 조합, 목표 형식·용량·A4·품질·해상도, 순서가 있는 레시피 저장·가져오기·내보내기·실행. - 사용자가 켠 감시 폴더의 안정된 파일 처리, 결과·임시 파일·재처리 루프 제외, 휠 순서·숨김·레시피 호출. - 클립보드 이미지·텍스트, 사용자가 시작한 영역 캡처, 결과 파일 드래그. - PDF·이미지 동기 비교, 실제 인식 위치·확신도와 OCR 텍스트 교정, TXT·PDF·DOCX·XLSX 저장. - PDF 합치기·이미지 PDF·콜라주·GIF·문자와 이미지 워터마크·영수증 OCR 표. - 흐림·가장자리·빈/중복 페이지·개인정보 후보 검토와 사용자가 확인한 영역의 실제 픽셀 가림. |
| 4 | 개인정보·흐림 등의 후보는 검토 보조이며 완전 탐지 보장이 없습니다.<br>가림은 사용자가 확인한 영역에만 적용합니다.<br>OCR과 표 열 복원은 문서에 따라 달라집니다.<br>달성 불가능한 압축 목표를 성공으로 표시하지 않습니다.<br>지원하지 않는 입력·조합은 오류로 알립니다. |

<a id="level-1-section-3"></a>
### LEVEL 1 · 입력·처리·출력

| 단계 | 내용 |
| --- | --- |
| 입력 | 사용자가 고른 로컬 파일과 목표 형식·PDF 작업 옵션 |
| 처리 | 파일 분류 → 작업 선택 → 변환 도구·PDF 처리 → 새 결과 저장 |
| 출력 | 새 형식 파일·편집 PDF·OCR 문서·작업 기록 |

<a id="level-1-section-4"></a>
### LEVEL 1 · 화면과 사용 흐름

1. 파일을 모으고 카드·목표 형식·품질·용량 등의 순서를 레시피로 구성합니다.
2. Ctrl+K 명령 검색 또는 작업 공간에서 변환·PDF·OCR·이름 변경 작업을 선택합니다.
3. 감시 폴더는 사용자가 직접 켜며 결과·임시 파일 제외와 반복 처리 방지를 확인합니다.
4. OCR 교정과 개인정보 후보 검토는 실제 결과를 읽고 사용자가 확인한 영역에만 적용합니다.
5. 결과 파일을 열어 확인하고 기록 검색·필터·탐색기 선택으로 찾아갑니다.

<a id="level-1-section-7"></a>
### LEVEL 1 · 설치 환경과 실행·사용법

Windows Python 환경에서 이 보존 본의 고정 의존성 목록과 assets 참조를 확인합니다. OCR은 Tesseract 실행 파일과 언어 자료, 미디어는 FFmpeg, Office 변환은 LibreOffice 등 기능별 외부 도구가 필요합니다.

이 차수 소스 폴더에서 고정 의존성과 필요한 자산·외부 도구를 준비한 뒤 `python app.py`로 시작합니다. `--settings` 지원 여부는 아래 CLI 표와 해당 차수의 main을 확인합니다. 인자 없는 실행이 트레이로 시작하는 구성에서는 트레이 메뉴로 창을 엽니다.

<a id="level-1-section-8"></a>
### LEVEL 1 · 이 보관본의 의존성 목록

의존성은 제품 코드와 함께 쓰는 부품입니다.

PySide6·shiboken은 Qt 화면, Pillow·pi-heif는 그림 처리, pypdf·pypdfium2는 PDF 처리와 렌더링, python-docx·python-pptx·openpyxl·xlsxwriter는 문서·발표·표 파일을 다루는 계열입니다. lxml·et _xmlfile은 XML 자료, ReportLab·svglib·cssselect2·tinycss2는 PDF·SVG 관련 처리를 뒷받침합니다.

PyInstaller·hooks·altgraph·pefile·pywin32-ctypes·setuptools·packaging은 빌 드·패키지·실행 구성 계열이며 사용자가 고르는 출력 형식 목록이 아닙니다.

문자 인코딩·타입 보조·압축 관련 부품도 아래 정확한 이름과 판본으로 보존합니다.

목록을 설치했다고 글 꼴·아이콘·Tesseract·FFmpeg·Pandoc·LibreOffice가 자동으로 모두 준비되는 것은 아닙니다.

### LEVEL 1 · 프리셋과 실행 전 점검

**프리셋은 다음 작업 때 다시 쓰는 설정 묶음**입니다. 사진을 JPG로 바꾸는 `photo_jpg`, 한글과 영어가 섞인 스캔을 검색 가능한 PDF로 만드는 `scan_pdf`가 기본으로 준비됩니다. 원본 파일 경로는 저장하지 않으므로, 프리셋을 고른 뒤 이번에 처리할 파일을 따로 선택합니다.

PDF 옵션 묶음인 `Request`에는 회전 90도, 압축 `lossless`, 품질 80, DPI 200, 언어 `kor+eng`, 출력 `pdf`, 강제 OCR 꺼짐, PSM 3이 기본값으로 들어갑니다.

페이지 칸의 빈 문자열은 별도 페이지 목록을 지정하지 않은 상태입니다.

예를 들어 세 쪽짜리 PDF에서 `1,3`을 추출하면 첫째·셋째 쪽을 담은 새 PDF를 확인합니다.

번호는 1부터 세며 `3,1`처럼 쓰면 그 순서를 확인해야 합니다.

**DPI는 PDF 한 쪽을 그림으로 만들 때의 촘촘함**입니다. 200에서 400으로 높이면 같은 길이에 더 많은 픽셀이 생깁니다.

작은 글자를 살펴볼 때 도움이 될 수 있지만 처리 량과 메모리도 늘며 OCR 정답을 보장하지 않습니다.

허용 범위는 60~600입니다.

JPG 품질은 20~95이며 기본 80입니다.

숫자를 낮춘 결과는 글자 가장자리와 사진의 뭉개짐을 원본과 비교하세요.

압축 `lossless`는 그림의 재압축 단계를 추가하지 않는 쪽입니다.

사진이 많은 PDF를 더 줄이려면 `images`를 검토할 수 있지만, 이 방식은 그림을 줄이고 다시 저장하므로 작은 글자·사진을 확대해 확인해야 합니다.

어느 방식도 목표 크기 달성을 약속하지 않습니다.

회전은 90·180·270 도 중 고르고 출력에서 글자의 위아래 방향을 확인합니다.

OCR은 그림 속 글자를 문자로 읽는 기능입니다.

언어 `kor`는 한글, `eng`는 영어, `kor+eng`는 둘 다 대상으로 하며 선택한 언어 자료가 필요합니다.

PSM은 글자 배치를 읽는 방식으로, 3은 자동 배치 분석, 6은 한 덩어리의 본문, 11은 흩어진 글자를 위한 선택입니다.

일반 문서부터 3으로 확인하고, 한 블록을 잘라 낸 입력은 6, 여기저기 떨어진 짧은 글은 11을 비교할 수 있습니다.

이 선택은 정확도 순위가 아닙니다. [Tesseract의 배치 설명](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html)을 참고했습니다.

예를 들어 한 영 스캔 PDF를 입력하고 `scan_pdf`를 선택하면 새 PDF에서 문장 검색과 복사를 해 보고 원본 그림도 대조합니다. TXT는 읽힌 글, DOCX와 XLSX는 문단·표 추정까지 확인합니다. 표의 칸이나 읽는 순서가 틀리면 저장 성공과 내용 정확성을 구분해야 합니다.

`PresetStore`는 UTF-8 JSON 배열을 읽습니다.

이름은 양 끝 공백 제거 후 1~80 자이고 제어 문자를 거부하며 대소문자를 무시한 중복 이름을 허용하지 않습니다.

허용 키는 `name`, `kind`, `format`, `options`이고 일반 변환 프리 셋은 빈 options만 받습니다.

입력/출력 경로를 프리 셋에 끼워 넣지 않습니다.

PDF 옵션은 `Request`의 기본 값을 합친 뒤 검사합니다. 회전90/180/270, 품질 20~95, DPI60~600, PSM3/6/11, 압축 lossless/images, OCR 언어 kor +eng/kor/eng를 허용합니다.

페이지 문자열은 최대 10,000 자이고 1부터 시작하는 단일 번호·범위·쉼표 목록 형식을 검사합니다. OCR 출력은 pdf/txt/docx/xlsx, 이미지 변환은 png/jpg로 제한합니다.

읽기 오류가 난 프리셋 파일은 `error`에 원문을 남기고 쓰기를 차단합니다. 정상 저장은 같은 폴더의 임시 파일에 UTF-8 JSON을 쓰고 flush/fsync 후 교체합니다. 기본 프리 셋은 JPG 변환 `photo_jpg`와 한국어+영어 OCR PDF `scan_pdf`입니다.

`preflight(path, dst)`는 입력 존재 →지원 출력 →외부 도구 →입력 읽기 →여유 공간 →쓰기 가능 순서로 점검합니다.

입력 4 배 +64MiB는 보수적인 준비 공간 추정 값이며 최종 출력 크기가 아닙니다. `missing`, `unsupported`, `helper`, `space`, `write`, `input` 오류 코드를 `error`와 함께 반환하고 통과 때만 `ok=true`, `code=ready`가 됩니다.

### LEVEL 1 · workspace_core.py

작업 공간의 레시피는 **여러 작업을 순서대로 적은 목록**입니다.

파일을 넣고 이름 바꾸기·형식 변환 같은 단계를 정하면 앞 단계의 새 결과가 다음 단계로 넘어갑니다.

이름 바꾸기도 원본 이름을 바꾸는 대신 복사본에 새 이름을 붙입니다.

예를 들어 사진 두 장에 `{name}_{index}`를 적용하면 원래 이름 부분과 번호를 합친 복사본을 얻습니다.

저장할 폴더에 같은 이름이 있으면 기존 파일을 덮어쓰지 않고 번호를 붙여 다른 이름을 찾습니다.

앞 단계가 끝난 뒤 다음 단계에서 취소하거나 오류가 나도 이미 만들어진 결과는 남습니다.

따라서 오류 화면을 보았다고 출력 폴더가 비었다고 생각하면 안 됩니다.

단계별 기록에서 어디까지 끝났는지, 결과 파일이 실제로 열리는지 확인하세요.

실행이 끝났다는 표시와 원하는 용량을 달성했다는 표시는 다릅니다.

용량 제한보다 큰 결과가 남으면 ‘목표 용량 미달성’ 경고와 실제 바이트 수를 읽고 결과를 검토합니다.

투명한 그림을 투명을 지원하지 않는 형식으로 바꾸면 흰 배경에 합칩니다.

움직이는 그림은 첫 장만 확인하지 말고 프레임·재생 간격·반복도 확인합니다.

레시피 파일이 손상되었다는 메시지가 나오면 빈 목록으로 덮어 쓰지 말고 파일을 보존합니다.

### LEVEL 1 · workspace_ui.py

폴더 감시는 사용자가 명시적으로 켠 한 폴더만 대상으로 합니다. 파일이 두 번 관측될 때 같은 서명이 확인된 뒤 전달하므로 쓰는 중인 파일을 곧바로 처리하지 않기 위한 확인입니다. **결과 폴더는 감시 폴더와 분리**해야 합니다. 그렇지 않으면 새 결과를 또 입력으로 읽는 문제가 생길 수 있습니다.

화면 카드 모션은 파일 수와 실제 단계에 반응합니다. 파일 선택창에서 취소한 것은 빈 정상 작업 완료가 아닙니다. 문서·텍스트 출력에 품질 목표를 붙일 때에는 그 목표의 의미를 사용자에게 안내합니다.

- **StableFolderWatch**: 명시적으로 켠 한 폴더에서 두 차례 같은 서명이 관측된 파일만 전달한다. 파일을 복사하는 중간 상태를 바로 완성된 새 입력으로 처리하지 않습니다. [`StableFolderWatch`](../../../history/1.9.0/workspace_ui.py#L22)
- **WorkspaceVisual**: 파일 수와 실제 단계에 반응하는 유한 입체 카드 모션. [`WorkspaceVisual`](../../../history/1.9.0/workspace_ui.py#L62)
- **choose_paths**: 기존 공통 선택창의 모델·모션·현지화와 취소 의미를 재사용한다. [`choose_paths`](../../../history/1.9.0/workspace_ui.py#L390)
- **validate_quality_target**: 명시 품질 목표가 문서·텍스트 출력에 붙기 전에 사용자에게 안내한다. 문서나 텍스트처럼 같은 방식으로 화질을 적용할 수 없는 출력은 안내를 확인합니다. [`validate_quality_target`](../../../history/1.9.0/workspace_ui.py#L524)

### LEVEL 2 · 소스에서 제공하는 CLI 옵션

빌 드 명령은 출력 폴더를, 변환 매트릭스 명령은 검사 실행 경로를, PDF 검사 명령은 검사 묶음을 선택합니다.

같은 ‘경로 옵션’이라도 역할이 다릅니다.

매트릭스는 fixtures 분기, worker 분기를 먼저 처리하고 그 둘이 아니면 root를 요구합니다.

부모 검사 실행이 새 root 아래 fixtures를 만들고 형식별 worker를 시작하는 구조입니다.

개별 35초와 전체 1200초 기본 한도는 서로 연결됩니다.

### LEVEL 2 · 프리셋과 실행 전 점검

프리셋 파일 → `PresetStore` 검증 → `Request` 기본값 병합 → 실행 전 점검 → PDF/OCR 작업으로 설정이 전달됩니다.

프리셋은 `name`, `kind`, `format`, `options`만 보관하므로 이전 입력 경로가 다음 작업 대상으로 되살아나지 않습니다.

예를 들어 `scan_pdf`를 고른 뒤 오늘의 스캔을 선택해야 오늘 문서를 처리합니다.

회전·품질·DPI·PSM은 서로 다른 단계의 값입니다.

회전은 페이지 방향, DPI는 렌더링 해상도, 품질은 그림 인코딩, PSM은 Tesseract의 배치 분석에 관여합니다.

DPI 200·품질 80·PSM 3이 기본이며 하나를 바꿔도 다른 값의 의미가 바뀌지 않습니다.

압축 `images`를 선택해야 그림 축소·재인코딩 경로가 추가됩니다. `lossless`를 선택했다고 모든 문서의 파일 크기가 줄어드는 것은 아닙니다.

준비 점검은 입력 존재, 출력 형식, 외부 도구, 읽기, 공간, 쓰기를 순서대로 확인합니다.

준비 통과는 실행 가능성을 점검한 결과이며 아직 변환 결과가 아닙니다. `space`가 나오면 준비 공간 조건에서 멈춘 것이고, OCR 언어 자료가 없으면 글자를 읽기 전 도구 준비를 해결해야 합니다.

잘못 읽힌 문장은 실행 전 점검으로 발견할 수 없으므로 출력 내용 검수가 이어집니다.

`PresetStore`는 UTF-8 JSON 배열을 읽습니다.

이름은 양 끝 공백 제거 후 1~80 자이고 제어 문자를 거부하며 대소문자를 무시한 중복 이름을 허용하지 않습니다.

허용 키는 `name`, `kind`, `format`, `options`이고 일반 변환 프리 셋은 빈 options만 받습니다.

입력/출력 경로를 프리 셋에 끼워 넣지 않습니다.

PDF 옵션은 `Request`의 기본 값을 합친 뒤 검사합니다. 회전90/180/270, 품질 20~95, DPI60~600, PSM3/6/11, 압축 lossless/images, OCR 언어 kor +eng/kor/eng를 허용합니다.

페이지 문자열은 최대 10,000 자이고 1부터 시작하는 단일 번호·범위·쉼표 목록 형식을 검사합니다. OCR 출력은 pdf/txt/docx/xlsx, 이미지 변환은 png/jpg로 제한합니다.

읽기 오류가 난 프리셋 파일은 `error`에 원문을 남기고 쓰기를 차단합니다. 정상 저장은 같은 폴더의 임시 파일에 UTF-8 JSON을 쓰고 flush/fsync 후 교체합니다. 기본 프리 셋은 JPG 변환 `photo_jpg`와 한국어+영어 OCR PDF `scan_pdf`입니다.

`preflight(path, dst)`는 입력 존재 →지원 출력 →외부 도구 →입력 읽기 →여유 공간 →쓰기 가능 순서로 점검합니다.

입력 4 배 +64MiB는 보수적인 준비 공간 추정 값이며 최종 출력 크기가 아닙니다. `missing`, `unsupported`, `helper`, `space`, `write`, `input` 오류 코드를 `error`와 함께 반환하고 통과 때만 `ok=true`, `code=ready`가 됩니다.

### LEVEL 2 · workspace_ui.py

StableFolderWatch가 안정 관측한 파일을 전달하고 WorkspaceVisual이 실제 파일 수·단계를 표현합니다. 선택 입력은 기존 공통 선택 창 모델·현지화·취소 의미를 재사용합니다. validate _quality _target은 목표 형식과 품질 설정의 의미를 작업 시작 전에 연결합니다.

감시 폴더 부재와 출력 폴더 동일성은 시작 조건에서 거부됩니다. `_ACTIVE_PANELS`는 패널을 관리하는 집합이지 동시에 처리할 파일 수나 성능 한도가 아닙니다.

- [`StableFolderWatch`](../../../history/1.9.0/workspace_ui.py#L22): 명시적으로 켠 한 폴더에서 두 차례 같은 서명이 관측된 파일만 전달한다. 파일을 복사하는 중간 상태를 바로 완성된 새 입력으로 처리하지 않습니다.
- [`WorkspaceVisual`](../../../history/1.9.0/workspace_ui.py#L62): 파일 수와 실제 단계에 반응하는 유한 입체 카드 모션.
- [`choose_paths`](../../../history/1.9.0/workspace_ui.py#L390): 기존 공통 선택창의 모델·모션·현지화와 취소 의미를 재사용한다.
- [`validate_quality_target`](../../../history/1.9.0/workspace_ui.py#L524): 명시 품질 목표가 문서·텍스트 출력에 붙기 전에 사용자에게 안내한다. 문서나 텍스트처럼 같은 방식으로 화질을 적용할 수 없는 출력은 안내를 확인합니다.

### LEVEL 3 · 프리셋과 실행 전 점검

먼저 검수용 원본 사본과 결과를 비교할 위치를 정합니다. `photo_jpg`에는 사진을, `scan_pdf`에는 한 영 스캔을 선택합니다. 프리 셋 이름은 1~80 자이며 중복 이름과 제어 문자를 피합니다. 일반 변환에는 PDF 전용 options를 끼워 넣지 않습니다.

PDF 추출은 `1,3-5`처럼 1부터 시작하는 범위를 넣고 출력 쪽 수와 순서를 확인합니다.

회전은 90·180·270중 하나, DPI는 60~600, 품질은 20~95, OCR 배치는 3·6·11중 하나만 허용됩니다.

처음에는 기본 DPI 200·품질 80·PSM 3을 기록하고, 한 번에 한 항목을 바꾼 결과를 비교하면 차이 원인을 좁히기 쉽습니다. `images` 압축 결과는 파일 크기뿐 아니라 확대했을 때 글자와 그림도 확인합니다.

OCR 전에 선택한 `kor`·`eng`의 traineddata와 Tesseract 준비를 확인합니다.

PDF 결과는 검색·복사, TXT는 글자와 줄 순서, DOCX는 문단·표, XLSX는 셀 위치를 원본과 대조합니다.

성공 파일이 생겼어도 오 인식은 남을 수 있습니다.

설정 파일 읽기 오류가 있으면 저장 차단을 해제하려고 덮어쓰지 말고 원본 오류와 파일을 보존합니다.

이 절은 재현 절차이며 이번 문서 편집에서 검사를 실행했다는 기록이 아닙니다.

`PresetStore`는 UTF-8 JSON 배열을 읽습니다.

이름은 양 끝 공백 제거 후 1~80 자이고 제어 문자를 거부하며 대소문자를 무시한 중복 이름을 허용하지 않습니다.

허용 키는 `name`, `kind`, `format`, `options`이고 일반 변환 프리 셋은 빈 options만 받습니다.

입력/출력 경로를 프리 셋에 끼워 넣지 않습니다.

PDF 옵션은 `Request`의 기본 값을 합친 뒤 검사합니다. 회전90/180/270, 품질 20~95, DPI60~600, PSM3/6/11, 압축 lossless/images, OCR 언어 kor +eng/kor/eng를 허용합니다.

페이지 문자열은 최대 10,000 자이고 1부터 시작하는 단일 번호·범위·쉼표 목록 형식을 검사합니다. OCR 출력은 pdf/txt/docx/xlsx, 이미지 변환은 png/jpg로 제한합니다.

읽기 오류가 난 프리셋 파일은 `error`에 원문을 남기고 쓰기를 차단합니다. 정상 저장은 같은 폴더의 임시 파일에 UTF-8 JSON을 쓰고 flush/fsync 후 교체합니다. 기본 프리 셋은 JPG 변환 `photo_jpg`와 한국어+영어 OCR PDF `scan_pdf`입니다.

`preflight(path, dst)`는 입력 존재 →지원 출력 →외부 도구 →입력 읽기 →여유 공간 →쓰기 가능 순서로 점검합니다.

입력 4 배 +64MiB는 보수적인 준비 공간 추정 값이며 최종 출력 크기가 아닙니다. `missing`, `unsupported`, `helper`, `space`, `write`, `input` 오류 코드를 `error`와 함께 반환하고 통과 때만 `ok=true`, `code=ready`가 됩니다.

### LEVEL 3 · flipring_workflow.py

프리 셋을 저장할 때 이름 길이·표시 가능한 문자·중복을 확인합니다. convert에 PDF 전용 options를 넣거나 JSON에 경로를 끼워 넣지 않습니다. `photo_jpg`와 `scan_pdf`를 선택한 뒤 실제 입력·출력 형식·OCR 언어를 대조합니다. 준비 공간 추정과 실제 최종 크기는 별도로 기록합니다.
