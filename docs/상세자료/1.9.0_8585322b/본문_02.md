<a id="level-3-section-16"></a>
### LEVEL 3 · i18n.py

동일한 표준 오류를 한국어·영어 표시에서 비교하고 입력 경로·외부 진단 원문이 바뀌지 않는지 확인합니다. 모르는 외부 메시지를 임의의 성공 안내로 바꾸지 않으며, 화면에 짧은 설명이 있어도 상세 원문을 실패 분석 근거로 보존합니다.

- [`error_text`](../../../history/1.9.0/i18n.py#L279): 기록된 표준 오류를 현재 언어로 표시하고 외부 진단은 원문으로 구분한다. 외부 도구의 진단 원문과 앱이 번역하는 표준 오류를 구분합니다.

<a id="level-3-section-17"></a>
### LEVEL 3 · inspection_tools.py

입력이 실제 파일이고 출력이 실제 폴더인지 먼저 확인합니다. OCR 후보와 원문을 대조해 교정한 뒤 새 문서의 문자열과 표를 확인합니다. 확신도 값을 정확도 측정처럼 보고하지 않습니다. 가림은 선택 영역과 실제 새 결과의 픽셀, 전체 페이지 수와 비가림 내용까지 검수하며 원본을 보존합니다.

- [`render_page`](../../../history/1.9.0/inspection_tools.py#L80): 독립 RGB 사본을 반환하고 PDFium 객체는 공용 잠금 안에서 모두 닫는다.
- [`recognize_editable`](../../../history/1.9.0/inspection_tools.py#L118): 확신 도는 실제 Tesseract TSV의 conf 값만 사용한다. 확신도는 OCR이 낸 단어별 값이며 전체 문서 정확도나 개인 정보 탐지율이 아닙니다.
- [`export_edited_text`](../../../history/1.9.0/inspection_tools.py#L158): 교정 문자열은 번역하지 않으며 수식으로 실행하지 않는 새 문서로 저장한다. 고친 글자를 새 문서로 내보내며 셀의 수식처럼 실행하지 않습니다.
- [`redact_file`](../../../history/1.9.0/inspection_tools.py#L338): 원본 객체를 복사하지 않고 모든 페이지를 래스터화하여 새 결과만 만든다. 가릴 영역을 새 페이지의 픽셀에 반영하며 원본·다른 사본을 지우는 기능은 아닙니다.

- 오류를 확인할 항목: 입력 파일이 아닙니다. 해당 조건을 바로잡은 허용 입력/설정인지 확인하고 실패를 성공으로 기록하지 않습니다. [조건 코드](../../../history/1.9.0/inspection_tools.py#L27)
- 오류를 확인할 항목: 출력 폴더가 아닙니다. 해당 조건을 바로잡은 허용 입력/설정인지 확인하고 실패를 성공으로 기록하지 않습니다. [조건 코드](../../../history/1.9.0/inspection_tools.py#L39)

<a id="level-3-section-18"></a>
### LEVEL 3 · inspection_ui.py

확대·축소한 화면에서 같은 문서 영역을 선택하고 정규화 좌표와 출력 위치가 일치하는지 대조합니다. 선택 사각형을 그린 단계와 결과를 저장한 단계를 별도로 기록합니다. 미리보기 가림 표시만 캡처해 실제 파일 가림 성공 근거로 사용하지 않습니다.

- [`PageCanvas`](../../../history/1.9.0/inspection_ui.py#L36): 표시 좌표를 원본의 정규화 좌표로 변환하며 선택만 표시한다. 화면에서 고른 영역을 실제 페이지의 비율 좌표로 바꿉니다.

### LEVEL 3 · package.py

licenses와 출하 목록을 확보하고 각 항목의 상대 경로·실제 파일·바이트·SHA를 대조합니다.

### LEVEL 3 · workspace_core.py

이름 미리보기에서 확장자·금지 문자·예약 이름을 먼저 확인합니다.

원본과 다른 검수 폴더에 같은 이름의 기존 파일을 미리 두고 복사 결과가 별도 번호 이름으로 생기는지 확인하는 절차로 충돌 정책을 검토할 수 있습니다.

원본과 기존 파일의 내용·해시를 비교해야 단지 새 파일이 보인다는 사실보다 보존 여부를 명확히 판단할 수 있습니다.

여기서는 이 절차를 새로 실행하지 않았습니다.

다단계 작업은 단계별 outputs와 최종 outputs를 함께 기록합니다.

첫 단계 완료 후 두 번째 단계의 실패·취소 상황에서는 원본, 첫 단계 결과, 현재 단계에서 이미 게시된 결과를 각각 확인합니다.

결과 목록 하나만으로 출력 폴더의 모든 이전 단계 파일을 설명하지 않습니다.

용량 목표를 주었으면 status뿐 아니라 constraints_met·warnings와 실제 바이트 수를 검사합니다.

투명 PNG를 JPG로 바꾼 검 수는 배경 색을, 움직이는 이미지 검수는 프레임 수·간격·반복을 포함합니다. 손상 레시피의 읽기 오류를 만나면 기존 파일을 보존하고 오류를 기록합니다. 잘못된 JSON을 지우고 통과한 결과만 남기면 저장소 실패 경로의 근거를 잃습니다.

- [`validate_recipe`](../../../history/1.9.0/workspace_core.py#L148): 코드·셸·임의 필드를 허용하지 않는 버전 1 JSON 레시피를 정규화한다. 레시피는 허용된 작업 목록이며 임의 명령이나 코드를 실행하는 파일이 아닙니다.
- [`preview_names`](../../../history/1.9.0/workspace_core.py#L201): 규칙에 확장자를 붙여 미리 보여 주며 경로 탈출과 Windows 예약 이름을 거부한다. 잘못된 규칙·예약 이름·경로 문자는 거부하며 자동으로 고쳐 주지 않습니다.
- [`_publish`](../../../history/1.9.0/workspace_core.py#L224): 배타적 생성으로 충돌을 회피하고 현재 호출이 만든 미완료 파일만 정리한다. 정상 이름 충돌은 번호를 붙인 새 이름으로 피하며 원본과 기존 결과를 덮어쓰지 않습니다.
- [`rename_copies`](../../../history/1.9.0/workspace_core.py#L252): 이름 변경은 복사본에만 적용하며 원본 이름과 내용은 보존한다. 예를 들어 사진에 번호를 붙여도 원래 이름의 사진은 남습니다.

### LEVEL 4 · 프리셋과 실행 전 점검

프리셋의 허용 키와 `Request` 검증은 저장된 JSON을 실행 인자로 옮기는 경계입니다. 경로를 프리셋 스키마에서 제외하고 일반 변환 options를 비워 두어, 파일 선택과 작업 설정을 분리합니다. 기본 값을 합친 뒤 범위를 검증하므로 누락된 값과 금지된 값이 같은 상태가 되지 않습니다.

PDF 렌더링의 DPI는 `dpi / 72` 배율로 적용됩니다.

해상도를 올리면 래스터 처리량이 늘어나므로 품질 상한만 확인해서 자원 사용을 설명할 수 없습니다. `images` 압축은 페이지 크기와 DPI로 그림의 최대 변을 계산하고 품질 값으로 교체 그림을 인코딩합니다. `lossless` 경로와 달리 그림 데이터 자체가 바뀌는 절충입니다.

PSM은 OCR 프로세스로 전달되는 별도 인자이며 렌더링의 선명 도 문제와 배치 분석 문제를 혼동하지 않아야합니다.

준비 공간 `입력 크기 × 4 + 64 MiB`는 실행 전에 적용하는 추정치입니다.

실제 결과 크기 보증이나 공간 예약이 아니므로 준비 성공과 출력 게시 성공을 별도 상태로 유지합니다.

프리셋 저장은 임시 파일 기록·flush·fsync 후 교체하고, 읽기 실패는 쓰기 차단으로 연결합니다.

손상된 설정을 빈 기본값으로 조용히 덮어쓰지 않는 것이 이 저장 경계의 핵심입니다.

`PresetStore`는 UTF-8 JSON 배열을 읽습니다.

이름은 양 끝 공백 제거 후 1~80 자이고 제어 문자를 거부하며 대소문자를 무시한 중복 이름을 허용하지 않습니다.

허용 키는 `name`, `kind`, `format`, `options`이고 일반 변환 프리셋은 빈 options만 받습니다.

입력/출력 경로를 프리셋에 끼워 넣지 않습니다.

PDF 옵션은 `Request`의 기본값을 합친 뒤 검사합니다. 회전 90/180/270, 품질 20~95, DPI 60~600, PSM 3/6/11, 압축 lossless/images, OCR 언어 kor+eng/kor/eng를 허용합니다.

페이지 문자열은 최대 10,000 자이고 1부터 시작하는 단일 번호·범위·쉼표 목록 형식을 검사합니다. OCR 출력은 pdf/txt/docx/xlsx, 이미지 변환은 png/jpg로 제한합니다.

읽기 오류가 난 프리셋 파일은 `error`에 원문을 남기고 쓰기를 차단합니다. 정상 저장은 같은 폴더의 임시 파일에 UTF-8 JSON을 쓰고 flush/fsync 후 교체합니다. 기본 프리셋은 JPG 변환 `photo_jpg`와 한국어+영어 OCR PDF `scan_pdf`입니다.

`preflight(path, dst)`는 입력 존재 →지원 출력 →외부 도구 →입력 읽기 →여유 공간 →쓰기 가능 순서로 점검합니다.

입력 4 배 +64MiB는 보수적인 준비 공간 추정 값이며 최종 출력 크기가 아닙니다. `missing`, `unsupported`, `helper`, `space`, `write`, `input` 오류 코드를 `error`와 함께 반환하고 통과 때만 `ok=true`, `code=ready`가 됩니다.

### LEVEL 4 · workspace_core.py

작업 실행과 출력 게시는 다른 책임입니다. `_single`·`_combined`가 작업 폴더에서 만든 결과를 `_publish`가 배타적 생성 모드 `xb`로 최종 경로에 복사합니다.

이미 존재하는 경로는 번호 후보로 건너뛰고, 복사 도중 실패하면 해당 호출이 만든 미완료 파일만 삭제합니다.

이는 기존 파일을 교체하는 트랜잭션과 다르며, 앞 단계 게시 파일을 전체 롤백하지 않습니다.

`complete` 콜백이 게시 성공 뒤 active.outputs와 result.outputs를 갱신하므로, 최종 outputs는 전체 단계의 모든 산출물 누적 목록이 아닙니다.

단계별 목록은 steps에 남습니다.

취소 예외는 cancelled, 다른 예외는 failed로 바꾸고 constraints _met를 false로 설정합니다.

반면 유한 압축 후보를 모두 시도해도 용량을 넘으면 completed 상태에서 조건 미달을 표현합니다.

호출자는 status 한 필드만 보고 요구 충족으로 처리하면 안 됩니다.

`_size_candidate`는 요청 품질, 요청보다 20 낮춘 값, 하한 20의 중복 제거 후보를 비교하며 더 작은 결과만 best로 선택합니다.

후보가 실제로 작아지지 않으면 원 입력도 best로 남을 수 있습니다.

PDF와 지원 이미지 외의 형식에는 이 재인코딩 탐색을 계속하지 않습니다.

레시피 저장소는 잠금 안에서 기존 내용을 읽고 검증한 후 같은 폴더의 임시 파일을 fsync 하고 교체합니다.

손상 읽기와 정상 빈 저장소를 구분하는 것이 기존 레시피 보존의 경계입니다.

파일을 모아 레시피로 처리 순서를 구성하고, OCR 교정과 개인정보 후보 검토까지 한 작업 공간에서 이어 가도록 확장했습니다. 원본을 보존한 결과 저장과 사용자 확인을 유지합니다.

<a name="features"></a>

<a name="-핵심-기능과-보존-범위"></a>
## 핵심 기능과 보존 범위

**항목:** 1

**이 차수에서 확인할 내용:** 파일별 사전 점검과 사용자 프리셋으로 변환·PDF 작업의 반복 입력을 줄입니다.

**항목:** 2

**이 차수에서 확인할 내용:** 파일을 모아 처리 순서를 조합하고, 원본을 보존한 결과를 만드는 Windows 앱입니다. 무료 배포이며 제작자는 PUVKID입니다. 기존 버전과 보존 본은 유지합니다.

**항목:** 3

**이 차수에서 확인할 내용:** - Ctrl+K 명령 검색, 이름 규칙에 따른 복사본 생성, 기록 검색·필터·복사·탐색기 선택. - 카드 조합, 목표 형식·용량·A4·품질·해상도, 순서가 있는 레시피 저장·가져오기·내보내기·실행. - 사용자가 켠 감시 폴더의 안정된 파일 처리, 결과·임시 파일·재처리 루프 제외, 휠 순서·숨김·레시피 호출. - 클립보드 이미지·텍스트, 사용자가 시작한 영역 캡처, 결과 파일 드래그. - PDF·이미지 동기 비교, 실제 인식 위치·확신도와 OCR 텍스트 교정, TXT·PDF·DOCX·XLSX 저장. - PDF 합치기·이미지 PDF·콜라주·GIF·문자와 이미지 워터마크·영수증 OCR 표. - 흐림·가장자리·빈/중복 페이지·개인정보 후보 검토와 사용자가 확인한 영역의 실제 픽셀 가림.

**항목:** 4

**이 차수에서 확인할 내용:** 개인정보·흐림 등의 후보는 검토 보조이며 완전 탐지 보장이 없습니다. 가림은 사용자가 확인한 영역에만 적용합니다. OCR과 표 열 복원은 문서에 따라 달라집니다. 달성 불가능한 압축 목표를 성공으로 표시하지 않습니다. 지원하지 않는 입력·조합은 오류로 알립니다.

**항목:** 5

**이 차수에서 확인할 내용:** 흑백·회색과 SUIT 글꼴, 1160×820 논리 크기를 유지합니다.

화면이 작으면 작업 영역을 스크롤합니다.

파일·폴더 선택창, PDF·OCR, 팝업과 설정의 표면·간격·포커스를 통일했습니다.

한국어·영어와 모션 축소를 제공합니다.

파일 카드·단계·완료 모션은 실제 처리 상태와 연결되며 정지 이미지를 작업 화면처럼 사용하지 않습니다.

### 프리셋과 실행 전 점검

`PresetStore`는 UTF-8 JSON 배열을 읽습니다.

이름은 양 끝 공백 제거 후 1~80 자이고 제어 문자를 거부하며 대소문자를 무시한 중복 이름을 허용하지 않습니다.

허용 키는 `name`, `kind`, `format`, `options`이고 일반 변환 프리셋은 빈 options만 받습니다.

입력/출력 경로를 프리셋에 끼워 넣지 않습니다.

PDF 옵션은 `Request`의 기본값을 합친 뒤 검사합니다. 회전 90/180/270, 품질 20~95, DPI 60~600, PSM 3/6/11, 압축 lossless/images, OCR 언어 kor+eng/kor/eng를 허용합니다.

페이지 문자열은 최대 10,000 자이고 1부터 시작하는 단일 번호·범위·쉼표 목록 형식을 검사합니다. OCR 출력은 pdf/txt/docx/xlsx, 이미지 변환은 png/jpg로 제한합니다.

읽기 오류가 난 프리셋 파일은 `error`에 원문을 남기고 쓰기를 차단합니다. 정상 저장은 같은 폴더의 임시 파일에 UTF-8 JSON을 쓰고 flush/fsync 후 교체합니다. 기본 프리셋은 JPG 변환 `photo_jpg`와 한국어+영어 OCR PDF `scan_pdf`입니다.

`preflight(path, dst)`는 입력 존재 →지원 출력 →외부 도구 →입력 읽기 →여유 공간 →쓰기 가능 순서로 점검합니다.

입력 4 배 +64MiB는 보수적인 준비 공간 추정 값이며 최종 출력 크기가 아닙니다. `missing`, `unsupported`, `helper`, `space`, `write`, `input` 오류 코드를 `error`와 함께 반환하고 통과 때만 `ok=true`, `code=ready`가 됩니다.

<a name="-처리-결과와-출력-읽기"></a>
## 처리 결과와 출력 읽기

결과 파일은 원본과 구분해 확인합니다. 입력·출력 경로와 오류가 기록에 포함될 수 있습니다. PDF OCR의 행·열·배치 복원은 입력 문서에 따라 달라집니다. 1.9.0 검증 기록은 기존 163개·확장 86개, 합계 249개 회귀와 설치 제품 626 파일의 크기·SHA-256 대조를 구분합니다.

<a name="️-제약과-문제-해결"></a>
## 제약과 문제 해결

| 항목 | 동작·확인 |
|---|---|
| 실행 경로 | 레시피·작업 공간·검토 도구의 소스와 직전 1.8.0 비교를 읽습니다. |
| 출력 | OCR 교정과 후보 확인 후 선택한 픽셀을 새 사본에 가립니다. |
| 한계 | 개인정보 후보는 완전 탐지를 보장하지 않습니다. |


**상황:** 앱 시작 시 자산 오류

**확인할 내용:** 참조하는 글꼴·아이콘·자산 경로를 확인합니다. 역사 소스는 설치 바이너리와 모든 실행 자산을 포함하지 않습니다.

**상황:** 변환 도구를 찾지 못함

**확인할 내용:** 선택 형식에 필요한 FFmpeg·Pandoc·LibreOffice·Tesseract와 검색 경로를 확인합니다.

**상황:** 페이지 선택이 거부됨

**확인할 내용:** 실제 페이지 수와 1부터 시작하는 범위를 확인합니다. 암호화 PDF의 처리 정책도 확인합니다.
