# HWP·HWPX 양방향 변환 요구사항

## 목표와 현재 상태

플립링에서 HWP·HWPX 문서를 다른 문서 형식으로 변환하고, 지원하는 문서에서 실제 HWP·HWPX 파일을 만들 수 있도록 확장합니다. 기존 파일 선택과 형식 선택, 탐색기 Shift 원형 메뉴를 유지합니다.

현재 제품은 HWP·HWPX 입력 변환을 제공하지만 역 방향 저장은 제공하지 않습니다.

기본 HWP5·HWPX 표본의 문자와 표 일부는 기존 검사에서 확인했습니다.

알려진 복잡한 HWP 표본의 변환 실패도 있습니다.

구형 HWP3의 입력 헤더는 허용되지만 변환 필터가 HWP 2002용으로 고정돼 있어 별도 검증이 필요합니다.

이 문서는 지원 완료를 선언하는 문서가 아닙니다.

## 구현 조건

- 무료 배포에 포함할 수 있는 의존성과 원본 라이선스·고지를 확인합니다. 계정 로그인, 유료 서비스나 문서의 외부 업로드를 필수로 하지 않습니다.
- HWP·HWPX 출력은 실제 해당 파일 형식이어야 합니다. 다른 형식의 확장자만 바꾸지 않습니다.
- 기존 입력 파일을 수정하거나 덮어쓰지 않습니다. 결과 이름 충돌, 실패와 취소는 기존 엔진의 결과 생성 규칙을 따릅니다.
- 외부 LibreOffice Python과 앱의 Python 확장 모듈을 섞지 않습니다. 순수 도우미 세 파일의 일 회용 격리와 바이트 코드 쓰기 방지, 기존 작업별 프로세스 소유·후손 정리를 유지합니다.
- 암호·보호 설정, 손상된 구조, 과도한 압축 해제나 외부 참조 같은 기존 안전 경계를 약화하지 않습니다. 지원하지 않는 구조를 경고 없이 지우거나 오류를 숨겨 성공으로 처리하지 않습니다.
- 문자·문단·표·그림·서식의 보존 범위와 제한을 각각 확인합니다. 기능이 일부 존재한다는 이유로 모든 버전과 모든 문서가 완전히 보존된다고 표현하지 않습니다.

## 입력과 출력

우선 HWP5·HWPX 상호 변환과 기존 문서 변환 경로에서 사용하는 편집 가능한 문서의 HWP·HWPX 출력을 확인합니다. DOCX를 기본 연결 표본으로 사용하고, 다른 입력은 실제 정규화 경로와 결과가 검증된 경우에만 선택 가능한 대상으로 노출합니다.

HWP·HWPX에서 PDF·이미지·Word 등으로 나가는 기존 경로는 유지합니다. PDF나 사진에서 편집 가능한 문서를 만드는 과정은 문자 인식과 배치 복원이 필요한 별도 동작입니다. 이를 일반 문서의 서식 변환이나 손실 없는 원본 복원으로 설명하지 않습니다.

구형 HWP, 암호·배포용 문서, 수식·그림·겹친 표와 복잡한 배치는 각각 성공·거부·미검증을 구분합니다. 지원이 확인되지 않은 경로를 전체 지원이라고 안내하지 않습니다.

## 화면

기존 파일 선택·형식 선택·변환 흐름에서 지원하는 HWP·HWPX 목표를 고르게 합니다. 추가 설정이 필요하면 기존 고급 옵션 구조를 사용합니다. 작업에 필요한 도구와 지원 조건은 실제 준비 상태와 일치해야 합니다. 현재 구현과 향후 목표를 같은 목록에서 혼동하지 않습니다.

## 검증 기준

1. 한글·영문·숫자 문단과 제목, 굵은 글자, 3 행 3 열 표, 자체 생성 PNG를 포함한 표본을 사용합니다. 외부 표본은 공개 근거와 독립 기대 값을 확인한 경우에만 사용합니다.
2. HWP·HWPX 출력을 다시 열어 문자·표의 행열과 내용·그림을 확인합니다. 가능하면 생성기와 다른 파서나 문서 프로그램으로 확인합니다. 같은 라이브러리로 재저장한 것만으로 외부 호환성을 증명하지 않습니다.
3. DOCX의 한글·표가 출력에 남는지 확인하고, 서식·개체를 옮기지 못하는 경우 손실 목록과 오류를 확인합니다. 엄격 검증을 끄거나 기대 값을 낮추는 방식으로 통과시키지 않습니다.
4. 원본 해시, 결과의 실제 형식, 결과 이름 충돌, 손상 입력, 취소와 프로세스 정리를 확인합니다. 기존 이미지·Office·PDF·OCR 동작에 영향을 주는 검사도 실행합니다.
5. 구현, 빌드, 실제 Windows 설치·동작 확인, 전체 소스·빌드 안내 보관, 독립 검토, 최종 폴더 교체와 GitHub 공개 검증을 구분합니다. 확인하지 않은 단계는 완료로 기록하지 않습니다.

## 후속 구현 계획의 근거

무료 로컬 문서 라이브러리의 정확한 버전·원본·라이선스와 실제 저장 API를 먼저 실증합니다. 실증 결과에 따라 수정할 모듈·의존성·검사·화면·배포 구성을 구체적인 구현 계획에 고정합니다. 한컴 프로그램 설치 여부나 실험적인 쓰기 API의 존재만으로 무료 배포 권한 또는 전체 문서 호환성이 확인됐다고 판단하지 않습니다.
