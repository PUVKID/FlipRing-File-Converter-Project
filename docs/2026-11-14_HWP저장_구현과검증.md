# HWP·HWPX 제한 저장 구현과 검증

플립링 1.11 소스에 **DOCX·TXT·HWP5·HWPX에서 HWP·HWPX로 저장하는 기능**을 추가했습니다.

새 저장은 로컬에서 처리하며 계정·문서 업로드·별도 LibreOffice를 요구하지 않습니다.

기존 HWP·HWPX를 PDF·Word 등으로 읽어 변환하는 경로는 LibreOffice·H2Orestart·Java를 계속 사용합니다.

## 사용 범위

단순한 문단, 굵게·기울임, 병합하지 않은 직사각형 표와 PNG/JPEG 그림을 지원 범위로 삼습니다. 같은 확장자는 변환 목표에서 제외합니다. 병합·중첩 표, 수식·주석·필드, 떠 있거나 회전한 그림 등 지원하지 않는 구조는 내용을 지운 채 성공으로 처리하지 않고 거부합니다. 원본과 기존 결과를 덮어쓰지 않습니다.

**글꼴·쪽 배치의 완전한 재현을 보장하지 않습니다.** HWP5 쓰기는 사용 라이브러리에서도 실험적인 기능입니다. HWP3 저장이나 모든 보호·배포용 문서, 모든 HWPX 사용자 부품에 대한 무손실 보존을 제공한다고 설명하지 않습니다.

## 구현과 안전 경계

`document_hwp.py`가 형식과 내용을 검사하고 `hwp_worker.py`가 앱과 별도 프로세스에서 요청을 처리합니다. 앱 시작의 worker 분기는 화면과 엔진을 불러오기 전에 실행됩니다. 앱 Python과 LibreOffice Python의 바이너리 모듈을 섞지 않습니다.

ZIP/XML·외부 참조·크기와 그림 제한을 검사합니다.

HWP5에서는 실제 지원 스트림과 DocInfo가 참조한 그림 집합을 대조해 알려지지 않은 내용을 조용히 버리는 경우를 거부합니다.

표준 메타데이터의 선택 매핑·미리 보기 텍스트 정규화·미리 보기 그림 생략은 입력별 결과로 구분하며 원 메타데이터 전체 바이트 보존이라고 표현하지 않습니다.

구조 검사와 내용 손실 거부는 독립 문서 프로그램에서의 시각적 일치 검사가 아닙니다. 같은 라이브러리 재개방, 코드 검토, 실제 프로세스 검사와 외부 뷰어의 렌더 결과를 구분합니다.

## 직접 확인한 결과

| 검사 | 실제 수 | 결과와 범위 |
| --- | ---: | --- |
| HWP 저장 코어 | 20 | 제한 입력·출력, 구조·손실·외부 참조·스트림 거부 검사 통과 |
| worker | 12 | 정상 요청과 실제 소유 프로세스 취소·후손 종료·손상 결과·출력 경계 검사 통과 |
| 한글·표·그림 고정 표본 | 1 | HWP/HWPX 두 출력의 문단 순서·3×3 셀·PNG 원 바이트·64×48 RGB와 마지막 행 대조 통과 |
| 미지 스트림 회귀 | 2 | 새 생성 표본과 이전 실제 실패 원본을 각각 저장 전에 거부·출력 없음·원본 보존 확인 |

위 **35개는 구현자와 다른 검증 담당이 직접 실행**했습니다. HWP 재개방은 같은 라이브러리이며 외부 뷰어 검증으로 표현하지 않습니다. worker 시간 초과는 제어한 시계로 분기를 시험했으며 실제 30분을 기다린 시험이 아닙니다.

현재 소스에서 기존 문서 51·기존 기능 163·확장 기능 86도 각각 다시 실행해 통과했고, 독립 담당은 저장된 ID·통계·현재 소스 해시를 대조했습니다.

이를 독립 담당이 모든 검사를 다시 실행한 결과나 전체 문서의 정확도로 합산하지 않습니다.

과거 입력 표본 경로 누락과 미 지 스트림 유 실 실패도 후속 통과 로 지우지 않습니다.

## 배포 상태와 의존성

이 기록 시점에는 **새 실행·설치 파일의 빌드와 실제 설치본 시험, 최종 납품 교체와 원격 게시가 남아 있습니다.** 기존 설치본의 사용자 시험을 새 HWP 빌드의 시험으로 재사용하지 않습니다.

python-hwpx 6.12.0을 고정하고 Apache-2.0 LICENSE·NOTICE·METADATA와 정확한 상응 소스를 포함하도록 구성했습니다. lxml과 기존 의존성 고지는 유지합니다.

전체 소스 ZIP에는 제품 코드·검사·빌드 안내·자산·라이선스와 상응 소스를 보관합니다.

GitHub가 자동 생성한 저장소 ZIP과 이 전체 배포 소스는 구분합니다.

## 새 빌드 후 확인한 상태

위 배포 상태 문단은 빌드 전의 기록입니다. 이후 **새 실행 파일·설치 파일·전체 소스 ZIP을 만들고 실제 설치와 기동을 확인**했습니다. 실행 구성은 1,207 파일이며, 전체 소스 ZIP의 948 항목은 현재 제품 소스와 전량 대조했습니다. 실행 파일에 포함된 21 모듈의 코드도 현재 소스와 대조했습니다.

새 실행 파일과 실제 설치된 실행 파일에서 각각 같은 한글·표·그림 고정 표본을 HWP와 HWPX로 저장했습니다.

문단 순서·표의 3×3 셀·굵게 와 기울임·그림 원 바이트와 64×48 RGB를 확인했습니다.

이는 실제 실행 파일의 별도 처리기를 통한 검사이며, 탐색기에서 사람이 Shift를 누른 시험이나 외부 문서 뷰어의 시각적 비교를 대신하지 않습니다.

사용자는 새 설치본에서 이미지 변환·원본 보존·중앙 취소가 정상이라고 확인했습니다.

실제 생성 파일과 기록에서는 **PNG와 HWP**를 확인했고, 원본 두 파일의 SHA-256과 PNG 픽셀, HWP의 본문·표·그림도 대조했습니다.

사용자 응답에는 HWPX라고 적혀 있었으나 실제 결과 확장자가 HWP였으므로, HWPX의 직접 Shift 드래그 확인은 별도로 대기합니다.

이를 HWPX의 물리 조작 검증 완료라고 기록하지 않습니다.

새 배포 후보는 D 드라이브에 보관했습니다. 이 후속 기록 시점에도 **이전 최종본 교체·공개 문서의 독립 검토·GitHub 게시와 원격 확인은 진행 중**입니다. 준비된 파일과 공개 완료 상태를 구분합니다.


## 납품 파일 교체 후 확인

새 배포 후보와 같은 실행 파일·설치 파일·전체 소스 ZIP·빌드 안내를 최종 폴더에 반영했습니다.

**최종 1,212 파일과 개발 납품 경계 1,211 파일, 이전 백업 1,183 파일을 실제 전량 크기·SHA-256으로 다시 대조**했습니다.

이전 최종 안내를 먼저 보존했으며 삭제한 경로는 없습니다.

전체 소스 ZIP의 948 항목과 내부 `소스/빌드방법.md` 존재도 확인했습니다.

다섯 수준 프로젝트·차수 설명 22개는 별도 담당자의 의미 검토를 통과했습니다. 이 절은 로컬 납품 교체 뒤의 기록이며, 최종 중앙 검사와 GitHub 게시·게이트·원격 연결 확인은 별도 후속 단계입니다. HWPX의 사용자 직접 Shift 시험은 여전히 실제 결과 파일을 확인한 범위와 구분합니다.
