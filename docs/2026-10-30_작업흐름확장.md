# 플립링 작업 흐름 확장 명세와 실행 계획

사용자는 바로 앞에서 제안한 기능·디자인 개선을 모두 실제 구현하도록 2026-10-30 승인했습니다. 추가 선호 질문 없이 기존 PySide6 앱에서 수행합니다. 이전 1.6의 작은 소스·실패·검증 이력과 사용자 데이터는 보존합니다. 프로젝트 한 폴더 납품이라는 기존 개별 지시는 유지합니다.

## 요구와 성공 조건

1. 결과 미리보기: 실제 이미지 원본/결과를 나란히 보고 크기·파일 용량을 확인합니다. 실제 PDF의 페이지 썸네일·선택 페이지 미리보기를 제공합니다. 지원하지 않는 결과는 이유와 탐색기 선택을 제공하며 변환 성공으로 숨기지 않습니다.
2. 프리셋: 사진→JPG, 스캔→검색 PDF와 사용자 지정 이름/출력 형식/관련 PDF 옵션을 저장·호출·삭제합니다. 빈 이름·잘못된 형식·원본 경로 재사용을 검증하며 즉시 변환보다 선택된 파일에 명시 실행합니다. 언어 전환과 재시작 후 유지합니다.
3. 일반 변환 작업 큐: 파일별 대기/처리/완료/실패/취소를 표시하고 실패한 항목만 재시도합니다. 대기 및 실행 중 취소를 제공하며 원본·이미 완료된 다른 결과를 보존합니다. 실제 진행을 알 수 없는 동안 임의 백분율을 만들지 않습니다. PDFium 작업은 PDF 도구와 동시 접근하지 않습니다.
4. PDF 시각 편집: 실제 페이지 썸네일을 불러와 드래그 재정렬, 다중 선택, 회전·삭제·추출을 수행합니다. 편집은 메모리 모델로 보관하고 새 파일로 저장합니다. 모든 페이지 삭제/잘못된 PDF/암호화·누락 입력/중간 취소를 처리합니다. 기존 PDF·OCR 기능과 원본 보존을 유지합니다.
5. 사전 점검: 지원 형식·실제 도우미 도구·입력 존재·출력 폴더 쓰기·현재 디스크 여유와 예상 필요 공간을 확인합니다. 정확한 최종 용량을 예측한다고 표현하지 않습니다. 낮은 공간·쓰기 거부·지원 불가·도우미 누락을 파일별로 안내합니다.
6. 설정 분리: 언어·키·시작·알림 등의 기본 설정은 전용 화면으로 이동하고 메인에는 파일·출력·실행·상태를 우선합니다. 큰 장식 없이 차분한 흑백·SUIT와 분명한 파일 형식/아이콘을 유지합니다. 기존 정보·도우미·기록·트레이·Shift/OLE·중앙 취소를 유지합니다.
7. 화면 상태: 빈 상태에는 작은 드롭 안내, 파일 추가 후에는 목록·출력·실행을 보여줍니다. 진행·완료·실패 상태는 실제 작업과 연결하고 선택·추가·완료의 짧은 유한 모션을 사용합니다.
8. 모션 줄이기: 설정에서 저장하고 열린 창/팝업/휠/PDF 화면에도 적용합니다. 효과가 줄어도 입력·진행·상태·작업 의미는 유지합니다. 애니메이션 시간 단축만으로 기존 실행을 누락하지 않습니다.
9. 기존 변환 지원표의 실제 실행 검증을 확대하고 모든 조합의 성공·실패·도우미 부재·입력 fixture 부재를 구분합니다. 형식 목록 존재만으로 전수 검증 완료라 하지 않습니다.

## 구조와 책임

- 일반 작업 구현자: `소스/app.py`, `engine.py`, `studio_ui.py`, `ui_motion.py`, `i18n.py`, 새 `flipring_workflow.py`, `preview_panel.py`, 관련 새 검사. 기존 변환 인터페이스는 호환성을 유지합니다. 프리셋을 위한 `flipring_workflow.PresetStore`와 `flipring_workflow.preflight`를 제공합니다. 최초 이름 workflow.py는 다른 배포판의 PyInstaller 규칙과 충돌한 실제 빌드 실패 뒤 수리15에서 구분했습니다.
- PDF 구현자: `소스/pdf_panel.py`, `pdf_tools.py`, 새 `pdf_pages.py`, `test_pdf_workspace.py`. 번역은 해당 패널의 기존 TEXT에 추가합니다. 공통 모듈은 수정하지 않습니다. `PdfToolsPanel.set_reduced_motion(enabled)`와 `apply_preset(dict)`를 제공하고 `preset_requested = Signal(dict)`로 메인에 저장 요청을 전달합니다.
- 부모: 문서·라우팅·검사 명세·버전·빌드/포장·고지·공개용 소스 정리·저장소 반영. 구현자와 다른 독립 검증자가 최종 요구·소스·실제 검사를 대조합니다.

## 검토 초점과 선택

기존 네이티브 앱을 유지합니다. 전체 WebView 교체는 설치 용량과 Explorer/OLE 회귀 범위를 늘려 제외합니다. 정지 그림을 UI로 붙이지 않습니다. 이미 승인된 이번 기능과 차분한 화면 흐름을 실제 위젯으로 구현합니다. 일부 원래 정적 레이아웃 검사는 설정 분리 때문에 변경이 필요할 수 있으나 기능 수락 기준과 파일 보존 기준을 약화하지 않으며 원문을 보존합니다. 중앙 검사30초/전체45초와 후손 종료·UTF-8 출력 제한은 유지합니다.

시각 검사에서 작은 창·긴 한글 이름·삭제된 원본·PDF 전체 삭제·취소 직후 재시도·손상된 프리셋 저장·저장 공간 부족·열린 창의 모션 감소 전환을 특히 확인합니다. 실행하지 못한 물리 Shift/실제 창 항목은 자동 Qt 시험으로 대체했다고 표현하지 않습니다.
