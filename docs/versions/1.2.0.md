이 자료는 설치 설정의 AppVersion으로 확인한 **이전 Mono 소스**입니다.

예를 들어 그림 파일을 선택해 다른 지원 형식의 새 파일을 만드는 도구를 이해할 수 있습니다.

화면의 설정 창·트레이·Shift 원형 메뉴와 파일을 처리하는 엔진은 역할이 다릅니다.

파일을 드래그해 형식을 고르는 흐름과 PDF·OCR 처리가 보존돼 있지만 지금의 작업 공간·레시피가 모두 들어 있다고 보면 안 됩니다.

원본은 작업 전 파일, 출력은 새로 만든 결과입니다.

### LEVEL 1 · 설치 환경과 실행·사용법

Windows Python 환경에서 이 보존 본의 고정 의존성 목록과 assets 참조를 확인합니다. OCR은 Tesseract 실행 파일과 언어 자료, 미디어는 FFmpeg, Office 변환은 LibreOffice 등 기능별 외부 도구가 필요합니다.

이 차수 소스 폴더에서 고정 의존성과 필요한 자산·외부 도구를 준비한 뒤 `python app.py`로 시작합니다. `python app.py --settings`로 설정창을 바로 엽니다. 인자 없는 실행이 트레이로 시작하는 구성에서는 트레이 메뉴로 창을 엽니다.

### LEVEL 1 · 코드·화면·설정·검사의 확인 범위

실제 보존 파일의 공개 가능한 Python·고정 의존성·기존 라이선스만 바이트 그대로 수록했습니다. 실행 자산·개인 작업 기록·설치 바이너리는 이 사본에 포함하지 않습니다.

<a id="level-1-section-12"></a>
### LEVEL 1 · app.py

이 차수의 app은 Windows 알림 영역에 머무르는 트 레이와 작은 설정 창, 파일 변환을 고르는 원형 메뉴를 연결합니다. `python app.py`로 시작하며 `python app.py --settings`는 설정창을 바로 엽니다.

창을 닫아도 앱이 종료되도록 만들지 않은 구성이고, 이미 실행 중이면 같은 설정 폴더의 잠금을 확인해 중복 실행 안내를 표시합니다.

`VERSION=3`은 제품 3.0이라는 뜻이 아니라 `settings-3.ini` 설정 파일 이름에 쓰는 값입니다.

설정 폴더 DATA는 Windows의 LOCALAPPDATA 아래 `PUVKID/DragWheel`이며, LOCALAPPDATA가 없으면 사용자 홈을 기준으로 합니다. `APPNAME`은 화면에 쓰는 앱 이름, `AUTOSTART_NAME`은 자동 시작 등록에 쓰는 이름입니다.

이 이름을 보고 파일 변환 품질이나 지원 형식을 추측하지 않습니다.

원형 메뉴를 여는 키 후보는 Shift·Alt·Ctrl·Windows·Space·F8·직접 지정입니다. `0x10` 같은 값은 Windows가 키를 구별하는 번호이고 `custom=-1`은 별도 지정 키를 사용한다는 표식입니다.

일반 사용자는 코드 숫자를 고치기보다 설정에서 키를 고릅니다.

USER32는 Windows의 창·키 상태를 읽기 위한 연결이며 변환 옵션이 아닙니다.

예를 들어 결과 기록을 왼쪽으로 두 번 누르면 해당 파일의 위치를 찾는 흐름을 읽을 수 있습니다. 파일 자체를 실행하는 동작과 구분합니다. 드롭은 존재하는 로컬 파일·폴더인지 확인하며 웹 주소를 같은 파일 입력으로 취급하지 않습니다. 화면 언어를 바꾸어도 사용자 파일 이름까지 번역하지 않습니다.

### LEVEL 1 · pdf_tools.py

OCR은 글자의 위치로 행과 열을 추정하므로 표의 칸이 항상 맞지는 않습니다. 여러 파일에서 앞 파일이 끝난 뒤 뒤 파일에 오류·취소가 생겨도 이미 완성한 앞 결과는 보존합니다. 어떤 입력에서 오류가 났는지는 실제 처리 중인 경로로 기록합니다.

- **page_indices**: 1부터 시작하는 범위를 검증하고 사용자가 쓴 페이지 순서를 유지한다. 예를 들어 1,3-5는 첫 페이지와 3~5쪽을 고르는 표현이며 잘못된 범위를 확인해야 합니다. [`page_indices`](../../history/1.2.0/pdf_tools.py#L94)

### LEVEL 2 · app.py

시작 시 QApplication을 만들고 DATA 폴더의 running.lock으로 중복 실행을 확인합니다.

설정은 `settings-{VERSION}.ini`에 연결됩니다.

VERSION 3, 앱 이름, 자동 시작 이름, 사용자 데이터 경로는 각각 다른 용도의 값입니다.

### LEVEL 3 · app.py

같은 시점의 실행 환경을 갖춘 뒤 기본 실행과 `--settings` 실행을 구분해 확인합니다.

기본 실행은 상주 시작, `--settings`는 설 정 창 열기입니다.

중복 실행 검수에서는 같은 DATA 경로의 running.lock에 의해 안내가 나오는지 확인하고, 사용 중인 설정 파일을 지워 통과시키지 않습니다.

VERSION 3을 제품 버전 번호로 기록하지 않습니다.

키 선택은 Shift·Alt·Ctrl·Windows·Space·F8·직접 지정 중 실제 선택을 기록합니다.

탐색기 드래그·키·이동 조건은 물리 조작 근거가 필요하며 Qt 모형 검사와 구분합니다.

유효 로컬 파일 드롭, 없는 항목, 웹 주소를 나누어 입력 거부를 검수할 수 있습니다.

결과 기록의 왼쪽 더블클릭과 다른 클릭을 구별하고, 표시 언어 변경 뒤에도 원래 파일명이 유지되는지 대조합니다.

이 후보 작성에서는 위 실제 조작을 실행하지 않았습니다. 소스에서 확인한 설정 경로와 시작 분기, 검사해야 할 동작을 설명한 것입니다.

- [`DialogTranslator`](../../history/1.2.0/app.py#L82): 앱에서 사용하는 Qt 표준 대화상자의 짧은 문구만 현지화한다. 파일 선택창의 짧은 버튼 문구를 한국어로 읽더라도 선택한 파일 이름은 번역하지 않습니다.
- [`file_urls`](../../history/1.2.0/app.py#L142): 드롭에 포함된 모든 항목이 존재하는 로컬 파일/폴더인지 확인한다. 없는 파일이나 웹 주소를 파일 드롭으로 처리하지 않아야 합니다.
- [`HistoryList`](../../history/1.2.0/app.py#L159): 결과 선택은 왼쪽 더블클릭으로만 실행한다. 기록의 결과를 고르는 조작과 결과 파일 자체를 실행하는 조작을 구분합니다.
- [`MainWindow`](../../history/1.2.0/app.py#L453): 상주 컨트롤러와 작은 설정창. 변환 선택은 원형 메뉴에서 수행한다. 메뉴·설정·현재 작업을 연결하는 창이며 실제 변환 엔진과 구분합니다.
- [`append_record`](../../history/1.2.0/app.py#L921): 두 변환 경로의 결과를 기존 기록 스키마로 저장한다. 성공·오류와 입력/결과의 대응을 남겨 나중에 찾도록 합니다.

### LEVEL 3 · pdf_tools.py

페이지 범위는 1부터 시작하는 번호·범위·목록을 넣고 결과 순서를 확인합니다. PDF 합치기·나누기·추출·삭제·회전은 쪽 내용과 방향을, 이미지 변환은 해상도와 내용을, OCR은 글자·줄·표를 검수합니다. 처리 중 취소하거나 뒤 입력이 실패한 경우 앞선 완료 파일과 실제 실패 입력 경로를 각각 확인합니다.

OCR 종료 확인은 부모 프로세스만 끝났는지가 아니라 묶인 자식도 종료했는지를 포함합니다. 코드의 Job Object 사용과 실제 취소 시험 결과를 구분하고, 표 추정 결과를 원본과 대조하지 않은 채 보존 성공으로 판정하지 않습니다.

- [`source_context`](../../history/1.2.0/pdf_tools.py#L39): 실제로 처리 중인 입력을 예외에 붙인다. 표시 문자열에서 경로를 추정하지 않는다.
- [`page_indices`](../../history/1.2.0/pdf_tools.py#L94): 1부터 시작하는 범위를 검증하고 사용자가 쓴 페이지 순서를 유지한다. 예를 들어 1,3-5는 첫 페이지와 3~5쪽을 고르는 표현이며 잘못된 범위를 확인해야 합니다.
- [`_ProcessTree`](../../history/1.2.0/pdf_tools.py#L144): Windows Job Object를 닫아 OCR 프로세스와 그 자식을 함께 종료한다.
- [`structured_rows`](../../history/1.2.0/pdf_tools.py#L325): 같은 높이의 단어와 큰 가로 간격을 이용해 행·열을 추론한다. 같은 줄·큰 간격을 단서로 표를 추정하므로 실제 표의 칸이 항상 맞는 것은 아닙니다.
- [`execute`](../../history/1.2.0/pdf_tools.py#L519): 결과별 (입력, 출력, 오류) 콜백. 취소/실패 시 완성한 앞선 결과는 유지한다. 여러 파일 중 먼저 끝난 결과는 뒤의 취소나 실패 때문에 사라지지 않습니다.

### LEVEL 4 · 설치 환경과 실행·사용법

Windows Python 환경에서 이 보존 본의 고정 의존성 목록과 assets 참조를 확인합니다. OCR은 Tesseract 실행 파일과 언어 자료, 미디어는 FFmpeg, Office 변환은 LibreOffice 등 기능별 외부 도구가 필요합니다.

이 차수 소스 폴더에서 고정 의존성과 필요한 자산·외부 도구를 준비한 뒤 `python app.py`로 시작합니다. `python app.py --settings`로 설정창을 바로 엽니다. 인자 없는 실행이 트레이로 시작하는 구성에서는 트레이 메뉴로 창을 엽니다.

### LEVEL 4 · 소스에서 제공하는 CLI 옵션

CLI는 `output`을 ROOT로 확정한 뒤 OCR 여부로 하나의 테스트 클래스를 선택하고 GUI 여부로 패널 클래스를 합성합니다.

두 bool은 같은 축이 아닙니다. `--ocr` 변경은 기본 PDF 테스트를 대체하고 `--gui` 변경은 추가하므로, CI에서 옵션 한 조합만 실행하면 다른 클래스가 빠질 수 있습니다.

보고서의 `passed`는 실행 수에서 실패·오류·건너뜀을 뺀 수입니다. `failfast=True`는 최초 실패 뒤의 미실행 검사를 별도 성공으로 세지 않게 하며, 종료 코드는 `not result.wasSuccessful()`에서 정해집니다.

이 CLI 계약을 바꾸는 경우 실행 집합·보고서 해석·호출자의 종료 판정을 함께 검토해야 합니다.

이번 문서 수정은 검사 구현과 기대값을 변경하지 않습니다.

### LEVEL 4 · app.py

상주 앱 수명은 `setQuitOnLastWindowClosed(False)`와 단일 실행 QLockFile로 관리되고, 사용자 설정은 DATA와 VERSION으로 식별됩니다.

VERSION 변경은 설정 파일 경로를 바꾸므로 단순 표시 버전 수정과 다릅니다.

LOCALAPPDATA 대체 경로까지 포함해 잠 금·설정이 같은 기준을 쓰는지 검토해야 합니다.

원형 메뉴 트리 거는 Explorer 드래그 상태·키 상태·이동 거리 조건을 함께 사용합니다.

TRIGGER_KEYS는 입력 정책의 후보이고 USER32는 해당 Windows 상태를 읽는 수단입니다.

표시 문구 번역은 이 입력 정책을 바꾸지 않아야합니다.

드롭 검증과 기록 선택은 외부 경로가 앱 안으로 들어오는 경계이므로 파일 존재·로컬 여부와 파일 실행 의미를 구별합니다.

설정창 진입 플래그 `--settings`는 일반 argparse 옵션 목록이 아니라 sys.argv 포함 여부로 처리됩니다. 검사 CLI의 `--ocr`·`--gui`와 섞어 app의 변환 옵션이라고 문서화하면 실제 실행 계약이 달라집니다.

- [`DialogTranslator`](../../history/1.2.0/app.py#L82): 앱에서 사용하는 Qt 표준 대화상자의 짧은 문구만 현지화한다. 파일 선택창의 짧은 버튼 문구를 한국어로 읽더라도 선택한 파일 이름은 번역하지 않습니다.
- [`file_urls`](../../history/1.2.0/app.py#L142): 드롭에 포함된 모든 항목이 존재하는 로컬 파일/폴더인지 확인한다. 없는 파일이나 웹 주소를 파일 드롭으로 처리하지 않아야 합니다.
- [`HistoryList`](../../history/1.2.0/app.py#L159): 결과 선택은 왼쪽 더블클릭으로만 실행한다. 기록의 결과를 고르는 조작과 결과 파일 자체를 실행하는 조작을 구분합니다.
- [`MainWindow`](../../history/1.2.0/app.py#L453): 상주 컨트롤러와 작은 설정창. 변환 선택은 원형 메뉴에서 수행한다. 메뉴·설정·현재 작업을 연결하는 창이며 실제 변환 엔진과 구분합니다.
- [`append_record`](../../history/1.2.0/app.py#L921): 두 변환 경로의 결과를 기존 기록 스키마로 저장한다. 성공·오류와 입력/결과의 대응을 남겨 나중에 찾도록 합니다.

상수·필드·허용 집합의 변경은 해당 호출 경로와 수락 조건에 영향을 줍니다.

- [`execute`](../../history/1.2.0/pdf_tools.py#L519): 결과별 (입력, 출력, 오류) 콜백. 취소/실패 시 완성한 앞선 결과는 유지한다. 여러 파일 중 먼저 끝난 결과는 뒤의 취소나 실패 때문에 사라지지 않습니다.

<a name="-처리-결과와-출력-읽기"></a>
## 처리 결과와 출력 읽기

결과 파일은 원본과 구분해 확인합니다. 입력·출력 경로와 오류가 기록에 포함될 수 있습니다. PDF OCR의 행·열·배치 복원은 입력 문서에 따라 달라집니다.

<a name="️-제약과-문제-해결"></a>
## 제약과 문제 해결

**상황:** 앱 시작 시 자산 오류

**확인할 내용:** 참조하는 글꼴·아이콘·자산 경로를 확인합니다. 역사 소스는 설치 바이너리와 모든 실행 자산을 포함하지 않습니다.

**상황:** 변환 도구를 찾지 못함

**확인할 내용:** 선택 형식에 필요한 FFmpeg·Pandoc·LibreOffice·Tesseract와 검색 경로를 확인합니다.

**상황:** 페이지 선택이 거부됨

**확인할 내용:** 실제 페이지 수와 1부터 시작하는 범위를 확인합니다. 암호화 PDF의 처리 정책도 확인합니다.
