## LEVEL 1 - Beginner · 목적부터 결과 확인까지

[같은 수준 프로젝트](../읽기안내/레벨1.md) · [같은 수준 프로필](https://github.com/PUVKID/PUVKID/blob/main/docs/읽기안내/레벨1.md) · [LEVEL 1 - Beginner](#reading-level-1) · [LEVEL 2 - Explorer](#reading-level-2) · [LEVEL 3 - Practitioner](#reading-level-3) · [LEVEL 4 - Advanced](#reading-level-4) · [LEVEL 5 - Expert](#reading-level-5) · [프로젝트 첫 화면](../../README.md)

1.11.0은 **파일 선택 → 형식 선택 → 변환**으로 시작하고, PDF나 OCR의 세부 설정은 고급 옵션에서 펼치는 화면을 제공합니다.

OCR은 그림 속 글자를 읽는 기능입니다.

예를 들어 그림 파일을 고르고 PNG로 변환한 뒤 새 PNG를 열어 보고 원본이 그대로 남았는지 확인합니다.

보존 기록에는 사용자가 새 설치 본에서 Shift 드래그·PNG 변환·원본 보존·중앙 취소를 확인한 사실이 있습니다.

모든 버튼과 화면을 자동으로 시험했다는 뜻은 아닙니다.

당시 직접 검사에는 기존 회귀 163개, 확장 회귀 86개, 문서 엔진 51개 통과가 기록되어 있습니다. 회귀 검사는 변경 뒤 기존 동작이 유지되는지 확인하는 검사입니다. 자체 HEIC 시험 자료도 포함하지만 모든 외부 사진의 변환 품질을 보증하지 않습니다.

Office 변환은 LibreOffice가 따로 필요하고, 일부 영상·오디오·문서에는 FFmpeg 또는 Pandoc이 필요합니다.

복잡한 글꼴·수식·페이지 배치는 변환 뒤 열어 확인하세요.

당시 배포에서는 HWP/HWPX 읽기·다른 형식 변환을 다루며 저장은 지원하지 않았고, 초기 Excel 2007 Beta2 XLSB도 지원하지 않았습니다.

이후 HWP 저장 코어를 제한적으로 구현·검사했지만 **이전 후보 작성 당시에는 새 빌드와 실제 설치본 조작 확인이 미완료**였습니다.

이후 확인은 이 수준 끝의 보완절을 따릅니다.

아래 보존 표의 바이트는 파일 크기, SHA256은 같은 파일인지 대조하는 식별 값입니다.

실행 프로그램·설치 파일·전체 소스 ZIP은 용도가 다릅니다.

코드 서명 인증서는 적용되지 않았습니다.

전체 ZIP에는 Temurin Java·GCC·winpthreads·Qt·PySide·HEIC·OCR 관련 상응 소스 10개도 보존합니다.

이 자료는 동봉 부품의 원문을 추적하기 위한 것이며 새 성능 시험 결과가 아닙니다.

### LEVEL 1 · 새 배포와 실제 확인 범위

**2026년 11월 14일 확인:** 새 실행 프로그램과 설치 파일을 만들었고, 설치된 앱에서도 문서를 HWP로 저장한 결과를 확인했습니다.

HWP는 한글 문서 파일, HWPX는 내용을 XML 형태로 담는 다른 한글 문서 형식입니다.

새 저장 기능은 DOCX·TXT·HWP5·HWPX 입력을 제한적으로 받아 HWP 또는 HWPX를 만듭니다.

지원하지 않는 내용이 있으면 조용히 지우지 않고 오류로 중단합니다.

실제 사용자는 Shift 드래그로 JPG를 PNG로, 한글 표와 그림이 있는 DOCX를 HWP로 변환했습니다.

새 결과를 만들고 원본 두 파일이 그대로 남은 것을 확인했으며 중앙 취소도 정상이라고 답했습니다.

기록과 파일을 대조한 결과 문서 출력은 **HWP**였습니다.

HWPX는 자동 실행 검사에서 성공했지만 사용자가 직접 만든 HWPX 확인은 아직 대기 중입니다.

복잡한 문서를 모두 같은 모양으로 보존한다고 보장하지 않습니다.

프로그램 생성·설치·위 표본 확인과 최종 납품 폴더 교체·GitHub 공개는 서로 다른 단계입니다. 이 후보 작성 시점에는 최종 교체와 공개 반영, 전체 완료 검사가 남아 있습니다.

## LEVEL 2 - Explorer · 구성과 처리 관계

[같은 수준 프로젝트](../읽기안내/레벨2.md) · [같은 수준 프로필](https://github.com/PUVKID/PUVKID/blob/main/docs/읽기안내/레벨2.md) · [LEVEL 1 - Beginner](#reading-level-1) · [LEVEL 2 - Explorer](#reading-level-2) · [LEVEL 3 - Practitioner](#reading-level-3) · [LEVEL 4 - Advanced](#reading-level-4) · [LEVEL 5 - Expert](#reading-level-5) · [프로젝트 첫 화면](../../README.md)

기본 화면은 파일과 목표 형식을 받고, 고급 옵션은 PDF·OCR 설정을 연결합니다.

HWP/HWPX 입력을 읽는 문서 경로와 일반 이미지 변환 경로가 같은 지원 범위를 갖는 것은 아닙니다.

문서 변환은 별도 LibreOffice 설치에 의존하며, 영상·오디오 등의 일부 경로는 FFmpeg·Pandoc 준비 상태에 따라 달라집니다.

보존된 증거는 코드 회귀 163개·확장 회귀 86개·문서 엔진 51개와 사용자의 Shift 드래그/PNG/취소 확인으로 나뉩니다. 자동 검사 통과가 물리 조작 전체를 대신하지 않고, 한 번의 사용자 확인도 모든 문서 배치를 대신하지 않습니다. 생성 PNG·기록·원본 SHA·픽셀 비교는 해당 입력과 동작의 근거입니다.

프로그램과 설치 파일은 실행용, 전체 소스 ZIP은 구현과 상응 소스 추적용입니다.

크기·SHA 표는 이 셋을 정확히 구별합니다. 10개 상응 소스의 개별 해시는 동 봉 라이브러리 원문과 연결되며 실행 파일 해시와 바꿔 쓰지 않습니다.

후속 HWP 저장 구현 검사는 이 보존 배포의해 시를 바꾸지 않으며 당시 새 배포 연결은 미완료였습니다.

아래 보완 절은 이후 확인을 별도로 설명합니다.

### LEVEL 2 · 새 배포와 실제 확인 범위

새 배포 확인은 소스 → 실행 파일 → 설치된 실행 파일 → 출력 문서 순서로 연결했습니다.

실행 파일 안의 앱 및 모듈 21개를 현재 소스에서 컴파일 한 코드와 대조했고, 실행 폴더 1,207개 파일은 설치된 1,207개 파일과 크기·해시가 일치했습니다.

설치 폴더에는 제거기 파일 2개가 추가됩니다.

전체 소스 ZIP의 948개 항목은 실행 폴더의 파일 수와 다른 집합입니다.

단독 실행 파일과 설치된 실행 파일에서 각각 고정 DOCX 한 개로 HWP·HWPX 두 결과를 만들었습니다.

결과를 다시 읽어 한글, 문단과 표의 순서, 3×3 셀, 굵기·기울임, PNG 바이트와 픽셀을 대조했습니다.

다시 읽는 도구는 저장에 쓰인 python-hwpx 계열이므로 다른 한글 프로그램의 화면 대조와 구별합니다.

사용자의 Shift 시험은 PNG와 HWP 및 원본 보존·중앙 취소를 확인했고, HWPX 직접 조작은 아직 확인 중입니다.

기존 51·163·86회귀와 35개 독립 검사의 이력은 보존합니다. 이번 새 배포 확인 때 그 전체 검사를 다시 실행한 것으로 합산하지 않습니다. 최종 폴더 교체와 새 파일의 GitHub 원격 일치는 아직 완료되지 않았습니다.

## LEVEL 3 - Practitioner · 준비·절차·오류 확인

[같은 수준 프로젝트](../읽기안내/레벨3.md) · [같은 수준 프로필](https://github.com/PUVKID/PUVKID/blob/main/docs/읽기안내/레벨3.md) · [LEVEL 1 - Beginner](#reading-level-1) · [LEVEL 2 - Explorer](#reading-level-2) · [LEVEL 3 - Practitioner](#reading-level-3) · [LEVEL 4 - Advanced](#reading-level-4) · [LEVEL 5 - Expert](#reading-level-5) · [프로젝트 첫 화면](../../README.md)

보존 설치 본을 확인할 때 먼저 프로그램·설치 파일·전체 소스 ZIP 중 목적에 맞는 파일을 선택하고 아래 크기·SHA256 표와 대조합니다.

Office 작업을 하려면 LibreOffice, 해당 영상·오디오·문서 작업을 하려면 요구되는 FFmpeg·Pandoc을 준비합니다.

파일을 선택하고 목표 형식을 정한 뒤 필요한 PDF·OCR 고급 옵션을 확인합니다.

출력 파일을 열어 페이지·문자·글꼴·수식과 원본 보존을 점검합니다. PNG 변환은 크기와 픽셀을, 취소는 완료 여부와 남은 기록을 구분합니다. 보존된 사용자 시험 범위는 Shift 드래그, PNG, 원본 보존, 중앙 취소입니다. 나머지 상태를 확인하려면 별도 실제 조작 증거가 필요합니다.

회귀 163·86·51의 보존 결과를 새 HWP 저장 배포의 검사 결과로 복사하지 않습니다.

후속 제한 저장 경로는 구현 검사까지 진행되었으며 당시 설치 파일 재빌드·패키지 검증·물리 시험은 미완료였습니다.

이후 확인 범위는 다음 보완 절에 구분합니다.

상응 소스 10개의 파일명·바이트·SHA는 전체 ZIP의 원문 목록과 대조해야하며 코드 서명이 없다는 조건도 배포 안내에 유지합니다.

### LEVEL 3 · 새 배포와 실제 확인 범위

새 파일을 사용할 때에는 아래 전문 보완 절의 실행 파일·설치 파일·소스 ZIP 크기와 SHA-256을 각각 확인합니다.

설치 실행은 14.25초에 종료 코드 0으로 끝났고, 설치 후 창 응답과 앱 잠금 확인도 통과했습니다.

파일을 선택하고 HWP 또는 HWPX를 목표로 고른 뒤 결과의 한 글·표·그림과 원본 보존을 함께 확인하세요.

알 수 없는 HWP 스트림, 외부 연결, 실행 코드를 포함하는 문서는 지원 오류가 날 수 있습니다.

고정 표본에서는 단독·설치 실행 파일 모두 두 형식을 만들었고, 각각 한 개의 고정 검사가 결과를 확인했습니다.

사용자 시험에서 확인된 파일은 PNG와 HWP입니다.

JPG와 PNG의 RGB가 같았고 HWP의 한글·3×3 표·서식·그림도 기대 값과 맞았습니다.

HWPX 사용자 응답만으로 물리 완료를 처리하지 않았으며 별도 확인을 기다립니다.

중앙 취소는 사용자 직접 확인 근거입니다.

자동 검사나 사용자 표본에 없는 입력은 별도로 열어 검수해야 합니다. 기존 회귀의 과거 통과를 이번에 전부 재실행한 것으로 읽지 마세요. 최종 납품 교체·원격 게시·전체 완료 검사는 아직 남아 있습니다.

## LEVEL 4 - Advanced · 구현 경계와 변경 영향

[같은 수준 프로젝트](../읽기안내/레벨4.md) · [같은 수준 프로필](https://github.com/PUVKID/PUVKID/blob/main/docs/읽기안내/레벨4.md) · [LEVEL 1 - Beginner](#reading-level-1) · [LEVEL 2 - Explorer](#reading-level-2) · [LEVEL 3 - Practitioner](#reading-level-3) · [LEVEL 4 - Advanced](#reading-level-4) · [LEVEL 5 - Expert](#reading-level-5) · [프로젝트 첫 화면](../../README.md)

기본 화면 단순화는 입력·형식·실행 경로를 앞에 두고 PDF·OCR의 세부 설정을 뒤로 옮기는 구성입니다. 이를 엔진의 지원 확대나 변환 충실도 보증으로 해석하지 않습니다. LibreOffice·FFmpeg·Pandoc 의존 경로와 자체 HEIC 시험 자료의 범위를 구분해야 UI 노출과 실행 가능성을 혼동하지 않습니다.

검증 근거는 소스 회귀, 문서 엔진, 사용자 물리 조작, 배포 바이트 식별로 분리됩니다. 163·86·51 통과와 PNG 픽셀 대조는 각각 해당 조건에 결합하며, 전체 조작 상태나 복잡한 문서의 동등성을 증명하지 않습니다. 코드서명 미적용과 초기 XLSB 제한도 시험 성공으로 사라지지 않습니다.

상응 소스 10개의 개별 해시와 실행/설치/전체 ZIP해시는 서로 다른 공급 물 경계를 나타냅니다.

후속 HWP 저장 코어는 지원 입력과 거부 정책을 가진 별도 구현이며 기존 배포 바이트에 포함되었다고 추정할 수 없습니다.

새 소스·의존성·빌드·설치·실제 조작의 연결을 검증하기 전에는 보존 배포와 현재 구현 상태를 분리하여 설명합니다.

### LEVEL 4 · 새 배포와 실제 확인 범위

새 빌드는 종료 코드 0, 관측 경과 173.625초로 끝났습니다. 내장 코드 21개와 현재 소스 컴파일 결과는 파일명 메타데이터를 정규화한 뒤 일치했습니다. Python 48개와 도구 6개의 SHA도 독립 동결과 맞습니다. 이는 해당 소스·빌드의 결합 근거이며 모든 입력의 문서 충실도 증명은 아닙니다.

그 검토는 빌드·설치·작업자를 새로 실행하지 않고 실제 파일과 기존 실행 근거를 결합했습니다.

능동 부품·외부 연결·미지 HWP 스트림 거부와 원본 보존 정책을 유지합니다.
