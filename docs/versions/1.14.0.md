# 플립링 1.14.0 · 화면 간격과 테마 엔진

파일 선택·변환·PDF·OCR·기록·설정의 기존 작업 흐름을 유지하면서 화면의 간격과 조작 상태를 통일하는 차수입니다. 화면에 쓰는 Qt 스타일을 Rust 실행 프로그램에서 생성하고 앱 기동과 테마 변경에 연결합니다.

| 구분 | 적용 내용 | 현재 확인 범위 |
|---|---|---|
| 화면 구조 | 기존 8개 작업 페이지와 3개 배포 탭의 기능과 이동을 보존 | 소스 및 Qt 조작 검사 |
| 간격과 입력 | 4px 단위 간격, 화면 24px·패널 20px, 컨트롤 간 8~12px | 실제 Qt 오프스크린 화면과 조작 상태 |
| 글꼴과 테마 | 공식 나눔고딕 Bold 700, 기존 프로젝트 팔레트, 라이트·다크·시스템 선택 저장 | 실제 9개 위젯의 글꼴과 굵기, 두 테마와 설정 저장 |
| 파일 아이콘 | 테마와 선택 상태에 맞는 아이콘 색상 | 네 조합의 확인한 아이콘 대비 11.65 이상 |
| 문서 처리 연결 | 격리 문서 도우미가 앱 전용 경로 모듈을 초기 로딩하지 않게 보완 | 실제 HWPX→PDF, 한글·표와 원본 보존 확인 |
| Rust 연결 | 기동·테마 전환에서 현재 색상으로 QSS 생성, 같은 팔레트의 결과를 메모리에 보관 | 실제 Rust 호출과 제어된 오류 전달 |
| 배포 | 전체 소스 ZIP 생성·동결, 실행·설치 파일 생성과 Windows 재설치 완료 | 설치 배포 파일 1,232개 SHA 일치; 새 설치본의 물리 Shift 드래그는 미실행 |

화면 검사에는 796px 오프스크린 환경과 기존 화면 맞춤·스크롤 정책을 사용했습니다. 물리 마우스와 키보드, 큰 화면, 새 실행 프로그램과 설치 프로그램의 확인을 이 결과로 대신하지 않습니다. 속도 개선의 전후 실측은 수행하지 않았습니다.

## 차분한 마우스 피드백

| 조작 | 변경 | 확인 |
|---|---|---|
| 박스 근처로 이동 | 수동 컨테이너의 진입 반짝임을 제거 | 일반 박스는 고정 상태 유지 |
| 입력 칸·메뉴로 이동 | 낮은 강조가 420ms 동안 나타나고 220ms로 사라짐 | 현재 밝기부터 이어지고 즉시 이탈은 중지 |
| 선택·클릭 | 칸 안의 고정 테두리와 옅은 배경 | 실제 위젯 위치를 움직이지 않고 입력 전달 유지 |

새 실행본 JPG→PNG와 새 설치본 HWPX→DOCX를 실제 화면에서 실행했습니다. 원본 SHA와 문서 전체 텍스트를 대조했습니다. 소스 및 독립 모션 검사는 각각 7개가 통과했습니다. 초기 동시간대 프로세스 충돌 관측과 단독 재개 결과, 미확정 원인은 [배포 확인 범위](../1.14.0_배포확인.md)에 구분해 적었습니다.

## 기존 기능과 사용 순서

| 작업 | 사용 순서 | 결과와 주의 |
|---|---|---|
| 파일 변환 | 파일을 고르고 출력 형식과 결과 위치를 정한 뒤 실행 | 원본을 보존하며 생성 결과를 확인 |
| Shift 드래그 | 탐색기에서 파일을 끌며 Shift를 누르고 원형 메뉴의 형식에 놓기 | 중앙에 놓으면 취소; 새 배포본의 실제 시험 필요 |
| PDF·OCR | PDF·OCR 화면에서 작업과 입력을 선택하고 필요한 옵션 펼치기 | 일부 처리는 외부 도우미가 필요하며 결과 내용 확인 |
| 기록과 설정 | 기록의 결과 확인, 언어·테마·모션 선택 저장 | 파일 위치 열기는 기존 동작 유지 |

HWP5 저장의 실험적 범위, 복잡한 문서 구조의 제한과 외부 도우미 요구는 이전 차수의 지원 범위를 유지합니다. 코드 서명과 모든 환경·미래 입력의 무결함을 보장하는 차수가 아닙니다.

## 구현 연결

| 구성 | 역할 | 실패 처리 |
|---|---|---|
| Python·PySide6 | 창, 작업 페이지, 파일 처리 연결과 테마 선택 | 기존 변환·취소·원본 보존 경계 유지 |
| Rust 테마 생성기 | 현재 팔레트를 Qt QSS로 변환 | 실행 파일 부재·잘못된 인수·빈 출력·생성 실패를 정상으로 표시하지 않음 |
| 배포 자원 탐색 | 함께 배포한 도우미와 테마 엔진 탐색 | 포함 파일은 최종 배포·설치 SHA 목록으로 대조 |

[현재 배포 확인 범위](../1.14.0_배포확인.md)에서 소스·빌드·Windows 조작을 구분합니다. 속도 전후 비교와 모든 미래 입력의 무결함은 보장하지 않습니다.

## LEVEL 1 - Beginner · 처음 사용하기

[프로젝트 같은 수준](../읽기안내/레벨1.md) · [이전 차수 같은 수준](1.13.0.md#user-content-reading-level-1)

| 항목 | 동작·조건 | 확인·한계 |
|---|---|---|
| 파일 선택 | 입력 파일과 결과 폴더를 지정 | 원본은 보존하고 결과 파일을 열어 확인 |
| 화면 선택 | 왼쪽 메뉴에서 한 작업으로 이동 | 기존 변환·기록·PDF·OCR 흐름 유지 |
| 테마 | 라이트·다크·시스템 중 선택 | 색상 변경과 글자 대비를 함께 확인 |

파일을 고르고 형식과 저장 위치를 정한 뒤 변환합니다. PDF·OCR과 설정은 왼쪽 메뉴에서 이동합니다. 테마는 설정에서 고르며 앱을 다시 열어도 선택을 유지합니다. 화면이 작으면 기존 스크롤을 사용합니다.

### 이번 화면을 쉽게 사용하기

| 해볼 동작 | 달라진 반응 | 알아둘 점 |
|---|---|---|
| 빈 박스에 마우스 가져가기 | 큰 반짝임 없이 화면이 고정됩니다. | 버튼과 글자의 위치는 움직이지 않습니다. |
| 입력 칸이나 메뉴에 마우스 가져가기 | 칸 안의 옅은 테두리가 나타났다가 사라집니다. | 바로 벗어나면 뒤늦게 켜지지 않습니다. |
| 파일 선택 후 변환 실행 | 새 결과 파일을 원본 옆에 만듭니다. | 실제 JPG→PNG와 한글 HWPX→Word DOCX를 확인했고 원본은 그대로였습니다. |

문서 도우미의 첫 준비는 최대 120초까지 기다릴 수 있습니다. 이 시간이 모든 문서의 전체 처리 시간은 아닙니다. 앱을 설치하기 전에는 실행·설치 파일과 전체 소스가 함께 있는 배포 폴더를 보관하세요. 이전 버전은 제거하고 1.14로 새로 설치해 확인했습니다. 새 버전의 실제 Shift 드래그는 이번에 다시 시험하지 않았습니다. 빌드 중 앱과 설치 도구가 한 번 충돌한 뒤 단독 실행은 정상으로 확인했으나, 첫 충돌의 원인은 아직 확정하지 않았습니다.

<a id="reading-level-2"></a>
## LEVEL 2 - Explorer · 동작 이해하기

[프로젝트 같은 수준](../읽기안내/레벨2.md) · [이전 차수 같은 수준](1.13.0.md#user-content-reading-level-2)

| 항목 | 동작·조건 | 확인·한계 |
|---|---|---|
| 입력 | 설정의 테마와 현재 팔레트 | Rust에 필요한 색상 인수를 전달 |
| 처리 | Rust가 Qt 스타일을 생성 | Python이 결과를 받아 실제 창에 적용 |
| 출력 | 간격·글꼴·조작 상태가 연결된 화면 | 기존 작업 결과 형식과 지원 제한 유지 |

입력 파일의 변환 엔진은 기존 구성을 유지합니다. Python이 창과 사용자 선택을 관리하고 Rust가 현재 색상에 맞는 Qt 스타일 문자열을 만듭니다. 같은 색상 조합은 메모리에서 재사용합니다. 이 연결이 문서 변환 자체를 Rust로 옮겼다는 뜻은 아닙니다.

### 강조·문서 처리·배포의 연결

| 단계 | 이어지는 동작 | 조건 |
|---|---|---|
| 입력 상태 | 일반 박스는 추가 강조를 만들지 않고 입력 칸·메뉴만 약하게 반응합니다. | 실제 칸 크기와 입력 대상은 유지합니다. |
| 이탈 상태 | 현재 밝기에서 사라지고, 밝기가 아직 0이면 애니메이션을 중지합니다. | 빠른 재진입은 새 상태에서 이어집니다. |
| 문서 준비 | HWP·HWPX 도우미를 준비한 뒤 선택한 출력 형식으로 변환합니다. | 준비 상한 120초와 전체 작업 총기한 30분은 서로 다릅니다. |
| 설치 결과 | 새 실행부와 도우미를 함께 설치하고 배포 원문과 해시를 맞춥니다. | 설치 파일 1,232개 일치와 실제 PNG·DOCX 생성은 해당 구성의 근거입니다. |

이번 확인은 동작 연결의 근거이며 모든 입력의 무결함을 뜻하지 않습니다. 최초 동시간대 충돌은 원인 미확정으로 남겼고, 단독 재개·설치·변환 성공과 분리했습니다. 물리 Shift 드래그의 이전 사용자 확인과 이번 설치본의 미실행 상태도 구분합니다.

## LEVEL 3 - Practitioner · 직접 실행하기

[프로젝트 같은 수준](../읽기안내/레벨3.md) · [이전 차수 같은 수준](1.13.0.md#user-content-reading-level-3)

| 항목 | 동작·조건 | 확인·한계 |
|---|---|---|
| 준비 | 지원 Python·Qt와 필요한 도우미 | 빌드 안내의 실제 구성 확인 |
| 실행 | 앱 시작 후 테마와 페이지 이동 | 테마 엔진 오류를 숨기지 않고 표시 |
| 확인 | 변환 결과와 원본·취소 동작 대조 | 기존 소스 검사와 실제 Windows 조작 구분 |

소스 실행에는 지원 Python과 잠금 의존성, 변환 도우미, Rust 테마 실행 프로그램이 필요합니다. 확정한 전체 소스와 빌드 방법을 배포 폴더에 함께 제공합니다. 기동과 테마 전환을 확인한 뒤 변환·취소·원본 보존을 새 배포본에서 확인해야 합니다.

### 새 배포본 실행과 확인

| 순서 | 준비·조작 | 결과 확인 |
|---|---|---|
| 1 | 설치 파일로 설치하거나 프로그램 폴더 전체를 보관해 실행합니다. | `_internal`과 고지 폴더를 실행 파일 옆에 유지합니다. |
| 2 | 파일 선택으로 JPG를 불러와 PNG로 실행합니다. | 시험 결과는 80×60 PNG였고 JPG 해시는 변하지 않았습니다. |
| 3 | HWPX를 불러와 DOCX로 실행합니다. | 새 설치본의 8,149바이트 DOCX와 원본 전체 텍스트가 일치했습니다. |
| 4 | 칸 진입·빠른 이탈·재진입과 원형 미리보기의 중앙 취소를 봅니다. | 뒤늦은 강조 없이 칸은 고정되고 취소하면 대기 상태를 유지합니다. |

재빌드에는 전체 소스 ZIP과 빌드 방법의 Python·잠금 의존성·Rust·문서 도우미가 필요합니다. 도우미 준비는 최대 120초, 전체 문서 작업은 기존 30분 총기한을 적용하며 취소와 오류를 숨기지 않습니다. 최초 빌드 시 프로세스 충돌이 한 번 있었고 단독 재개 후 설치·변환은 성공했습니다. 재발이 없다고 보장하지 않습니다. 이번 확인에는 새 설치본의 물리 Shift 드래그와 모든 복잡한 HWP 문서가 포함되지 않습니다.

## LEVEL 4 - Advanced · 구조 분석하기

[프로젝트 같은 수준](../읽기안내/레벨4.md) · [이전 차수 같은 수준](1.13.0.md#user-content-reading-level-4)

| 항목 | 동작·조건 | 확인·한계 |
|---|---|---|
| 화면 계층 | 8개 작업 페이지·3개 배포 탭 | 기존 처리 연결을 유지하며 스타일 적용 |
| 테마 경계 | 기동·테마 변경의 Rust 호출 | 팔레트별 결과 캐시와 오류 전달 |
| 자원 경계 | 배포에 포함한 실제 파일 탐색 | 운영 PC의 개인 경로를 배포 의존성으로 사용하지 않도록 확인 |

테마 생성 경계는 subprocess 인수 배열과 엄격 UTF-8 출력입니다. 현재 팔레트별 결과를 메모리에 저장하여 같은 선택의 중복 생성을 줄입니다. 실행 실패·시간 초과·잘못된 출력은 예외로 전달하며 정상 화면으로 가장하지 않습니다. 파일 처리와 저장 경계는 기존 구현을 보존합니다.

### 상태와 배포 경계

| 구성 | 최종 구현 | 유지한 경계 |
|---|---|---|
| SurfaceMotion | Enter/Focus 반응을 입력 위젯으로 제한하고 420ms 낮은 피드백을 사용합니다. | 수동 컨테이너의 중복 pulse 제거, 기존 버튼 입력 유지 |
| FeedbackOverlay | 1px 안쪽의 고정 테두리·옅은 배경, 위치 보간 OutCubic | 마우스 입력 투명·NoFocus, 실제 위젯 geometry 불변 |
| fade_out | 양수 밝기는 220ms 감쇠, 0 밝기는 stop()으로 대기 애니메이션까지 종료 | 빠른 이탈·재진입과 축소 모션·수명 정리 유지 |
| 문서 bridge | 준비 제한 120초와 문서 총기한 30분을 분리 | 취소·소유 후손 회수·원본 보존·오류 전파 유지 |
| 배포 | PYZ 변경에 맞춰 실행부 전체를 재생성하고 설치 후 1,232개 SHA 대조 | 실패한 Inno 원문 보존 후 동일 입력으로 설치 단계만 분리 재개 |

테마 QSS의 Rust 호출과 Python/Qt의 이벤트 처리는 다른 경계입니다. 최초 ISCC·실행본의 동시간대 접근 위반은 기동 원인으로 단정하지 않고 관측과 후속 성공을 따로 기록했습니다. 물리 Shift/OLE와 전후 성능은 새 근거가 없으며 해당 기능의 개선·재검증으로 확대하지 않습니다.

기존 화면 검사와 이후 패키징 검사는 서로 다른 확인 범위입니다. 최종 전체 소스와 실행·설치 파일은 각자의 고정 해시와 실제 검사 결과로 대조합니다. 이전 소스 검사만으로 새 설치본의 동작을 확인했다고 표시하지 않습니다. 796px Qt 오프스크린·두 테마·설정 저장·Rust 실제 호출·제어된 오류 전달과 네이티브 입력·전체 지원 기능 검사를 구분합니다.

### 최종 후속 수정의 재현 범위

| 근거 | 분모·관측 | 해석 |
|---|---|---|
| 회귀 검사 | 제품 관련 7개 PASS, 별도 독립 7개 PASS | 즉시 이탈·실제 이벤트 루프 재진입·입력 전달·수명과 geometry 경계 |
| 고정 입력 | 전체 소스 1,007파일과 고객용 소스 ZIP | 공개 Git 선택 소스와 도우미 상응 소스 ZIP의 범위 구분 |
| 배포·설치 | 공식 배포 1,235파일 검사, 설치 후 배포 파일 1,232개 SHA 일치 | 설치 관리 파일은 배포 실행부 비교 분모와 다름 |
| 실제 GUI | JPG→PNG 디코드와 HWPX→DOCX 전체 텍스트 일치 | 시험 입력 원본 SHA 보존, 복잡한 문서 전체 보존 보장 아님 |
| 실패와 미측정 | 동시간대 접근 위반 1회, 첫 도우미 준비 지연의 원인·자연 완료 시간 미확정 | 후속 단독 재개 성공이 최초 원인 해결의 증명은 아님 |

즉시 이탈 회귀는 실제 실행 중 애니메이션이 중지되고 overlay가 숨겨지는지를 확인합니다. 정지된 애니메이션에 검사 코드가 setCurrentTime을 강제로 호출해 내부 값을 바꾸는 것과 실제 타이머의 재점등을 구분했습니다. 시험 DOCX 내용은 파일명으로 추정한 단어가 아니라 원본 section 전체 텍스트와 정확 일치로 대조했습니다. 초기 준비 120초의 모의 회귀 3개와 취소·30분 총기한은 기존 확인을 재사용합니다. 새 설치본의 물리 Shift 드래그는 재실행하지 않았고, 처리 성능 개선과 절대 무결함을 주장하지 않습니다.

## 문서 도우미와 고지 보완

| 변경 | 실제 동작과 근거 | 제한 |
|---|---|---|
| HWP·HWPX 초기 준비 | 준비 상한을 45초에서 120초로 조정하고 60·80초 완료, 120초 초과와 비정상 종료의 모의 회귀 3개를 확인했습니다. | 최초 45초 초과의 근본 원인과 계속 대기했을 때의 자연 완료 시간은 미측정입니다. |
