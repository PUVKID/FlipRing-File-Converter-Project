<a id="reading-level-1"></a>
## LEVEL 1 - Beginner · 문서 변환을 시작하는 방법

[같은 수준 프로젝트](../읽기안내/레벨1.md) · [같은 수준 프로필](https://github.com/PUVKID/PUVKID/blob/main/docs/읽기안내/레벨1.md) · [같은 수준 이전 차수](1.12.0.md#user-content-reading-level-1)

| 순서 | 할 일 | 결과 확인 |
|---|---|---|
| 1 | ABW 또는 DIF 문서 선택 | 원본 문서·표 확인 |
| 2 | 출력 형식을 고르고 변환 | 필요할 때 임시 사본 사용 |
| 3 | 결과 문서 열기 | 글자·표와 원본 보존 확인 |

ABW는 AbiWord 문서이고 DIF는 표를 옮기는 파일 형식입니다.  
파일을 선택해 원하는 출력 형식을 고르고 변환합니다.  
원본은 그대로 두고 필요한 경우 임시 사본을 사용합니다.  
변환 뒤 글자와 표가 원하는 대로 보이는지 확인하세요.

<a id="reading-level-2"></a>
## LEVEL 2 - Explorer · 입력과 안전한 사본

[같은 수준 프로젝트](../읽기안내/레벨2.md) · [같은 수준 프로필](https://github.com/PUVKID/PUVKID/blob/main/docs/읽기안내/레벨2.md) · [같은 수준 이전 차수](1.12.0.md#user-content-reading-level-2)

| 입력 | 처리 | 보존·거부 |
|---|---|---|
| ABW | 허용된 정형 DTD만 사본에서 제거 | 다른 DTD·엔터티 거부 |
| DIF | 문자 인코딩을 해석해 UTF-8 사본 생성 | 원본 유지, 이름 충돌 시 덮어쓰기 거부 |

ABW의 정해진 DTD 선언만 안전 사본에서 제거하고 나머지 DTD와 엔터티는 거부합니다.  
DIF는 문자 인코딩을 순서대로 해석해 UTF-8 사본을 만듭니다.  
파일 이름이 충돌하면 기존 파일을 덮어쓰지 않습니다.

<a id="reading-level-3"></a>
## LEVEL 3 - Practitioner · 사용과 오류 확인

[같은 수준 프로젝트](../읽기안내/레벨3.md) · [같은 수준 프로필](https://github.com/PUVKID/PUVKID/blob/main/docs/읽기안내/레벨3.md) · [같은 수준 이전 차수](1.12.0.md#user-content-reading-level-3)

| 확인 시점 | 사용·설정 | 오류·한계 |
|---|---|---|
| 변환 전 | 형식에 맞는 LibreOffice 등 외부 도구 준비 | 도구 미설치 여부 확인 |
| 변환 중 | ABW·DIF와 출력 형식 선택 | 지원하지 않는 DTD·잘못된 바이트·사본 이름 충돌 거부 |
| 변환 후 | 글자와 표 확인 | 문자셋 정보 없는 DIF 자동 판별의 한계 |

문서 변환에는 형식에 따라 LibreOffice 등 외부 도구가 필요합니다.  
ABW 또는 DIF를 선택하고 출력 형식을 지정한 후 결과를 확인하세요.  
지원하지 않는 DTD, 잘못된 문자 바이트, 사본 이름 충돌은 오류로 처리합니다.  
DIF의 문자셋 식별이 없는 경우 자동 판별의 한계가 있습니다.


</details>

<summary>LEVEL 4 · Advanced — 구현·설계·실패 처리</summary>

<a id="reading-level-4"></a>
## LEVEL 4 - Advanced · 구현 경계와 조건

[같은 수준 프로젝트](../읽기안내/레벨4.md) · [같은 수준 프로필](https://github.com/PUVKID/PUVKID/blob/main/docs/읽기안내/레벨4.md) · [같은 수준 이전 차수](1.12.0.md#user-content-reading-level-4)

| 모듈·형식 | 구현 조건 | 처리 경계 |
|---|---|---|
| document_formats · ABW | Expat으로 DTD·엔터티 검사 | 정확한 정형 선언만 격리 사본에서 제거 |
| document_formats · DIF | BOM UTF-16 → UTF-8-sig → CP949 → CP1252 | 필요할 때 배타적으로 UTF-8 사본 생성 |
| document_bridge · DIF | DIF 필터에 문자집합 옵션 76 | UTF-8 입력으로 읽기 |

document_formats는 Expat으로 인코딩과 무관하게 DTD·엔터티를 검사하고 정확한 AbiWord 정형 선언만 격리 사본에서 제거합니다.  
DIF는 BOM UTF-16, UTF-8-sig, CP949, CP1252 순으로 해석하고 필요할 때 배타적으로 UTF-8 사본을 만듭니다.  
document_bridge는 DIF 필터에 UTF-8 문자집합 옵션 76을 지정합니다.


</details>

<a id="reading-level-5"></a>
## LEVEL 5 - Expert · 검사와 남은 한계

[같은 수준 프로젝트](../읽기안내/레벨5.md) · [같은 수준 프로필](https://github.com/PUVKID/PUVKID/blob/main/docs/읽기안내/레벨5.md) · [같은 수준 이전 차수](1.12.0.md#user-content-reading-level-5)

| 근거 | 실제 관측 | 범위·이력 |
|---|---|---|
| 기존 전체 기능 검사 | 서로 다른 377개 통과 | 화면 계약 보완 104개 포함, 중복 횟수 제외 |
| 신규 문서 입력 | 단위 검사 6개 | BOM UTF-16은 단위 검사 범위 |
| 실제 템플릿 | 12개 통과 | 4개 최초 실패는 생성기 XML 표기 원인, 정정 후 통과 |
| 실제 DIF | UTF-8·CP949 한글 셀 보존 | 모든 문자셋의 자동 식별 보장 아님 |

서로 다른 기존 전체 기능 검사 377개가 통과했고 그중 104개는 현행 화면 계약 보완 결과입니다.  
문서 입력 신규 단위 검사 6개, 실제 템플릿 12개와 DIF UTF-8·CP949 한글 셀을 확인했습니다.  
템플릿 4개 최초 실패는 입력 생성에서 XML 네임스페이스 표기가 바뀐 원인이었고 원문 속성만 치환한 후 통과했습니다.  
BOM UTF-16은 단위 검사로 확인했습니다.

## HWP·HWPX 그림 경계

HWP·HWPX의 전체 그림에서 마지막 줄이 잘리던 문제를 고쳤습니다.  
64×48 전체 그림과 32×24 부분 자르기를 두 형식으로 다시 읽은 **4개 경로**에서 원본 픽셀과 일치했습니다.  
전체 그림은 원본 그래픽을 유지하며 부분 자르기는 기존 계산을 사용합니다.  
[수정 출처·소스·재빌드 안내](../../소스/licenses/H2Orestart/수정과_재빌드안내.md)

전체 영역의 높이가 부동소수점 오차로 47.9982376이 된 뒤 정수 47로 줄어들던 원인을 구분했습니다.  
수정된 Java 소스에서 재빌드한 OXT와 검사에 사용한 OXT의 바이트가 일치합니다.  
모든 그림 구조나 외부 뷰어의 시각적 일치를 보장하지 않습니다.
