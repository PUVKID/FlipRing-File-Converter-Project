## LEVEL 3 · 실행 전에 준비할 항목

플립링은 무료 로컬 Windows 파일 도구입니다.

먼저 실행 폴더를 유지한 채 `프로그램/FlipRing/FlipRing.exe`를 실행하거나 `설치파일/FlipRing-Setup.exe`를 사용합니다.

EXE 한 개만 떼어 옮기지 마세요.

코드 서명은 없으며, 검증한 새 개발 배포 68 과 아직 교체하지 않은 최종 납품은 다릅니다. canonical70의 metadata 정 합 승격과 최종 납품 교체도 별도입니다.

현재 공개·최종 교체는 미완료입니다.

| 사용할 작업 | 준비·확인 | 빠지면 확인할 부분 |
|---|---|---|
| OCR | 배포 물의 Tesseract와 한국어·영어 모델, 읽을 언어 | 모델·엔진 파일 누락, 언어 선택, 입력 선명 도 |
| RAR 등 압축 | 동봉 7-Zip 실행 구성요소와 지원 출력 | `7z.exe`만 있고 `7z.dll`이 빠지지 않았는지, 안전 경로 오류 |
| Office | 별도 설치한 LibreOffice와 그 설치의 UNO Python | 앱 도구 화면의 준비 상태, 손상 문서 여부 |
| HWP·HWPX 입력 | 별도 LibreOffice와 동봉 H2Orestart·Java, 같은 비트 수 | 준비 정상과 실제 호환은 다르며 복잡 HWP 실패 가능 |
| 전자책·일부 문서 | 해당 작업의 별도 Pandoc | Office만 설치해 모든 문서가 되는 것은 아님 |
| 영상·음성 | 별도 FFmpeg | 실행 도구 발견 상태와 지원 형식 |

입력 존재·읽기 가능, 저장할 폴더의 쓰기 권한과 여유 공간도 확인합니다. 사전 공간 추정은 보수적인 예상이며 최종 크기 보장이 아닙니다. 중요한 파일은 복사본으로 시험하고 원본과 결과를 구분해 두세요. 소스 실행은 Python·고정 의존성·자산을 별도로 준비하는 개발 절차이므로 설치본 사용과 섞지 않습니다.

## LEVEL 3 · 일반 변환을 수행하고 검수하기

1. 기본 파일 변환 화면에서 입력을 선택합니다. 지원 형식이 서로 다른 여러 입력을 골랐다면 공통으로 가능한 출력이 있는지 확인합니다.
2. 출력 형식을 고릅니다. 저장한 프리셋을 쓰더라도 현재 입력·옵션을 다시 확인합니다. 프리셋 선택은 과거 파일을 자동 재실행하지 않습니다.
3. 변환을 실행하고 파일별 대기·처리·완료·실패·취소를 봅니다. 처리량을 알 수 없는 구간은 불확정 진행으로 표시될 수 있습니다.
4. 일반 변환은 원본 폴더의 새 이름 결과를 확인합니다. 지원 이미지 미리보기로 원본·결과와 크기·용량을 비교하고, 지원되지 않는 형식은 실제 파일을 열어 확인합니다.
5. 실패 이유를 해결한 뒤 실패 항목만 재시도합니다. 취소 뒤에도 원본과 이미 완료한 결과는 남으므로 재시도 전에 위치를 확인합니다.

탐색기 Shift 드래그는 선택해서 쓰는 빠른 경로입니다. 파일을 끌며 Shift를 눌러 원형 메뉴의 형식에 놓거나 가운데로 가져가 취소합니다. **파일 선택 → 형식 → 변환**의 기본 절차를 대신할 수 있지만 필수는 아닙니다. 오프스크린 자동 검사와 Windows 탐색기의 실제 물리 조작은 별도입니다.

창을 닫은 뒤 트레이에 남을 수 있으며 완전 종료는 트레이 메뉴에서 합니다.

언어·모션 축소·키·자동 시작·알림은 설정 화면에서 확인합니다.

기록의 결과를 왼쪽 더블클릭하면 실행 대신 탐색기에서 선택하며 이동·삭제된 파일은 안내를 따릅니다.

기록 검색·상태/형식 필터·파일/경로 복사도 사용할 수 있지만 경로와 오류가 담긴 기록은 공개 전에 검토하세요.

## LEVEL 3 · 문서 형식별 출력 선택표

| 입력·작업 목적 | 선택 가능한 대표 출력 | 결과 확인·제한 |
|---|---|---|
| Word DOC·DOCX·ODT·RTF 등 | DOCX·DOC·ODT·RTF·TXT·HTML·EPUB·PDF·페이지 이미지 등 지원 경로 | DOC↔DOCX 왕복에서도 표·그림·쪽 나눔·글꼴 대조 |
| Excel XLS·XLSX·ODS 등 | XLSX·XLS·ODS·CSV·TSV·PDF·HTML | XLS ↔XLSX의 시트·셀·수식·계산 값·차트 대조 |
| PowerPoint PPT·PPTX·ODP 등 | PPTX·PPT·ODP·PDF·페이지 이미지·TXT | PPT ↔PPTX의 텍스트·슬라이드·그림 대조; TXT는 텍스트만 |
| XLSB·DOCM/PPTM/XLSM·DOT/POT/XLT 계열 등 | 계열별 지원 출력 | **XLSB·매크로·템플릿은 입력 전용**, 같은 형식 저장이나 매크로 실행 아님 |
| HWP·HWPX | DOCX·ODT·PDF 등 지원 경로 | 기존 다른 형식 읽기와 새 제한 저장을 구분; DOCX/TXT/HWP5/HWPX 만 HWP/HWPX 저장 |
| 텍스트·Markdown·HTML·전자책·일부 iWork/WordPerfect/AbiWord | 앱에 표시되는 계열별 출력 | Pandoc 등 경로별 조건과 전용 기능 손실 확인 |

두 시트가 든 표에서 CSV·TSV를 고르면 **첫 시트의 표시값만** 저장합니다.

수식·서식·여러 시트가 필요하면 XLSX·XLS·ODS를 선택하세요.

초기 Excel 2007 Beta2 XLSB는 지원 완료 대상이 아니며 빈 시트로 잘못 읽으면 오류로 거부합니다.

원래 작성 프로그램에서 최신 XLSX로 저장한 복사 본을 사용하세요.

HWP를 PDF·Word로 읽어 변환하다 그림 개체 등으로 실패하면 원본을 보존하고 원 작성 앱에서 HWPX·DOCX·PDF 복사 본을 만들어 다시 시험합니다.

**새 HWP·HWPX 저장은 DOCX·TXT·HWP5·HWPX 네 입력에 한정**합니다.

DOCX에 단순한 3×3 표와 PNG를 넣고 HWPX를 선택하는 방식이며, 같은 확장자는 목표에서 제외됩니다.

새 저장 자체에는 LibreOffice가 필요하지 않습니다.

병합·중첩 표, 수식·주석·떠 있는 그림 등 미지원 구조가 있으면 지원하지 않는다는 오류를 확인하고 원본이 남았는지 봅니다.

글꼴·쪽 배치의 완전 재현이나 구형 HWP3 저장은 지원하지 않습니다.

소스 35 독립 검사와 새 68의 portable/installed 고정 DOCX 각 1 시험은 통과했고 새 사용자 PNG/HWP를 확인했습니다.

HWPX Shift 추가 확인은 대기입니다.

## LEVEL 3 · PDF 페이지 작업 절차

PDF 작업을 고르고 입력 목록과 순서를 확인합니다. 합치기는 파일 순서, 나누기·추출·삭제·회전은 페이지 범위가 기본 화면에 있습니다. 회전 각도도 기본에서 선택합니다. 예를 들어 `1,3-5`를 입력한 뒤 실제 대상이 1 쪽과 3~5 쪽인지 확인하세요. 모든 페이지 삭제는 거부합니다.

썸네일에서는 드래그 순서 변경·다중 선택·회전/삭제/추출과 확대 보기를 사용합니다. 저장은 새 파일이며 메모리에서 바꾼 순서가 원본에 바로 덮어써지는 것은 아닙니다. 완료 결과의 페이지 수·순서·각도를 열어 확인합니다. 저장이 이미 끝난 뒤의 취소가 그 파일을 없애는 것은 아닙니다.

PDF →이미지는 기본 출력 PNG/JPG를 확인하고 **고급 옵션**에 서 페이지 범위·DPI·품질을 조정합니다. 이미지 →PDF는 목록 순서와 필요한 DPI를 확인합니다. 압축은 무손실 정리와 이미지 방식의 의미를 구분합니다. 이미지 방식은 손실이 있을 수 있고 무손실 방식도 용량 감소를 보장하지 않습니다.

## LEVEL 3 · OCR 교정·비교·후보와 가림 검수

OCR은 한국어·영어·한영 중 언어와 TXT·검색 PDF·DOCX·XLSX 등의 출력을 고릅니다. 범위·DPI·인식 배치와 강제 인식은 해당 작업의 고급에서 조절합니다. 검색 PDF는 페이지 이미지와 글자 층이며 원래 편집 구조를 복원하는 결과가 아닙니다.

교정 화면에서 단어 위치·확신도와 낮은 확신도 후보를 원본과 대조하고 텍스트를 고친 뒤 TXT·PDF·DOCX·XLSX로 따로 저장합니다. 숫자·고유 명사·표 행 열·병합 셀·수식·다 단 배치를 특히 확인하세요. 교정한 텍스트의 저장과 원본 배치 유지 여부는 다릅니다.

두 파일 비교에서는 같은 페이지·배율의 미리보기와 페이지 수·크기·텍스트 차이를 봅니다. 검사 기능의 빈/중복 페이지·흐림·가장자리 내용·개인정보 후보는 사람이 확인할 목록입니다. 후보를 임의 확정해 지우지 않으며 완전 탐지 보장은 없습니다.

가림은 사용자가 페이지와 영역을 정한 뒤 **새 복사본**을 만듭니다. 가려진 픽셀과 남은 텍스트·다른 페이지를 확인한 다음 공유하세요. 원본·다른 사본은 그대로 있으므로 이 기능만으로 자료 전체의 비공개 처리가 끝났다고 판단하면 안 됩니다.

## LEVEL 3 · 작업 공간의 반복 작업 구성

파일 카드를 추가하고 순서를 정한 뒤 변환·크기 조절·PDF 합치기·이미지 PDF·콜라주·GIF·워터마크·영수증 OCR XLSX 등의 필요한 작업을 선택합니다. Ctrl +K로 명령을 찾을 수 있습니다. 클립 보드 파일·이미지·텍스트 또는 직접 시작 한 화면 영역 캡처를 가져온 경우 의도한 내용인지 먼저 확인합니다.

이름 복사는 `{name}`·`{index}`·`{date}` 규칙을 미리 보고 적용합니다.

잘못된 이름 규칙·경로 문자·예약 이름은 오류로 거부하며 자동으로 고쳐 주지 않습니다.

정상 이름이 기존 파일과 겹치면 번호를 붙인 새 이름으로 충돌을 피하고 원본과 기존 결과를 덮어쓰지 않습니다.

레시피는 허용 단계 추가·삭제·재정렬 뒤 저장하고 JSON 가져오기·내보내기로 재사용합니다.

실행 문자열을 넣는 임의 코드 실행기가 아닙니다.

가져온 레시피도 단계와 출력 위치를 확인합니다.

형식·품질·DPI·용량 상한·A4 목표를 필요한 만큼 지정합니다.

목표 용량은 KiB 조건이며 불가능할 수 있습니다.

미달성 경고가 나면 생성 결과를 보존한 상태에서 크기·화질을 비교하고 목표 달성과 구분합니다.

기본 결과 폴더는 앱 데이터 아래 `results`이며 고급에서 바꿀 수 있습니다.

완료 파일/경로 복사와 결과 드래그를 사용할 수 있습니다.

감시 폴더는 폴더와 레시피를 정하고 직접 켭니다. 쓰기가 안정된 새 파일만 처리하는지, 결과·임시 파일이 다시 입력되지 않는지 확인하고 사용하지 않을 때 정지합니다. 휠 순서·숨김·레시피 개인화는 지원 항목 안에서 설정하고 필요하면 기본값으로 복구합니다.

## LEVEL 3 · 오류를 읽는 순서

| 현상 | 먼저 볼 것 | 처리 범위 |

| 형식 선택 불가 | 입력 계열과 공통 출력 목록 | 확장자만 바꾸지 말고 지원 경로 사용 |
| 외부 도구 누락 | 도구 화면의 설치·UNO·Java 상태 | 필요한 도구만 준비; 동봉 자료를 임의 삭제하지 않음 |
| 암호·손상·본문 누락 오류 | 입력 실제 형식과 원작성 앱 | 암호 해제 등 허용된 복사본 사용, 보안 제한 우회 안 함 |
| LibreOffice 연결 종료 오류 | 작업 오류와 결과 완료 여부 | 임시 파일 존재만으로 성공 처리하지 않음 |
| 저장·용량 오류 | 권한·여유 공간·목표 미달성 경고 | 원본과 완료 결과를 보존하고 실패만 재시도 |
| 취소 뒤 남은 결과 | 이미 완료된 파일인지 | 취소가 모든 완료물을 되돌리는 동작이 아님 |

Office 작업은 격리 프로필·OpenCL 비활성화·순수 도우미 세 파일의 별도 경로·외부 Python `-B` 실행을 사용합니다.

사용자 LibreOffice 전역 설정을 바꾸지 않습니다.

과거 설치본 Python 버전 충돌을 다룬 조치이며 모든 문서의 성공 보장이 아닙니다.

외부 도구는 소유 작업별 종료 확인을 하며 타 앱을 정리 대상으로 삼지 않습니다.

## LEVEL 3 · 검사와 배포 결과 읽기

개발자는 전체 소스의 `소스/빌드방법.md`와 `검사도구`의 실제 명령·고정 의존성을 따릅니다.

## LEVEL 3 · HWP 제한 저장의 선택·절차·검증 경계

1. 중요한 원본을 따로 남기고 단순 문단·굵게/기울임·비병합 표·PNG/JPEG가 든 DOCX 등 지원 입력을 선택합니다.
2. 현재 기본 변환 화면에서 HWP/HWPX 중 다른 확장자를 고르고 실행합니다. 새 저장은 별도 LibreOffice가 필요 없으며 기존 HWP →PDF/DOCX 읽기는 외부 도구 준비를 따로 확인합니다.
3. 미지원 수식·주석·필드·병합/중첩표·떠 있거나 회전한 그림은 거부돼야 합니다. 오류를 빈 결과의 성공으로 바꾸지 말고 원본·이전 결과가 보존됐는지 확인합니다.
4. 성공한 결과도 문단 순서·표 행열·셀·그림을 열어 확인합니다. HWP3 저장·모든 보호/배포용·글꼴/쪽배치 동일성은 지원 주장에 넣지 않습니다.

독립 35 검 사와 portable/installed 고정 DOCX 각 1 시험의 HWP/HWPX 출력은 제한 표본의 근거입니다. worker timeout은 시계 주입으로 분기를 확인한 것이며 실제 30분 대기 시험이 아닙니다.

### LEVEL 3 · 파일 선택부터 결과 보존까지

PDF와 사전 점검: `pdf_panel.py`와 `pdf_tools.py`는 PDF 요청을 구성·실행하며, `flipring_workflow.py`는 이름별 프리셋과 파일별 사전 점검을 맡습니다.

### LEVEL 3 · 주요 기술과 처리 방식

이 항목을 사용할 때는 다음 조건·파일·입출력을 실제 환경과 대조합니다.

파일 종류에 따라 처리 도구가 달라집니다. Pillow·pi-heif는 이미지, pypdfium2·pypdf는 PDF 읽기와 편집, python-docx·ReportLab은 문서 생성을 맡습니다. 표 형태의 OCR 출력은 글자의 위치에서 행·열을 추정하므로 복잡한 표를 완전히 복원한다고 보장하지 않습니다.

`engine.convert()`는 원본과 같은 드라이브의 임시 폴더에서 변환한 뒤 새 이름으로 이동합니다. 압축 내부의 상위 경로·절대 경로와 링크를 검사합니다. PDF 출력은 배타적 파일 생성으로 기존 결과 덮어쓰기를 피하도록 구성합니다.

기본 조합은 **Shift를 누른 채 탐색기·바탕 화면에서 파일을 끌기**입니다. 앱은 30ms 간격으로 입력 상태를 확인하고 10px보다 큰 이동에서 원형 메뉴를 띄웁니다. 메뉴에 실제로 전달된 로컬 파일을 확인하고 복사 동작으로 드롭을 받아 변환합니다. 중앙·지원하지 않는 영역에서는 변환하지 않습니다.

## 파일 선택부터 결과 보존까지

- 앱과 변환: `app.py`가 창·트레이·파일 선택을 연결하고 `engine.py`는 입력 종류와 가능한 목표 형식·외부 변환 도구를 판별합니다.
- PDF와 사전 점검: `pdf_panel.py`와 `pdf_tools.py`는 PDF 요청을 구성·실행하며, `flipring_workflow.py`는 이름별 프리셋과 파일별 사전 점검을 맡습니다.
- 미리보기와 작업 공간: `preview_panel.py`·`pdf_pages.py`는 미리보기와 페이지 작업을, 후속 `workspace_core.py`·`workspace_ui.py`는 레시피·감시 폴더·검색 중심의 작업 공간을 구성합니다.

파일을 선택하고 목표 형식이나 작업, 페이지와 품질을 지정합니다. 필요한 도구와 입력·출력 공간을 확인한 뒤 작업 큐에서 처리하고 결과 파일을 엽니다. 변환 성공 표시가 OCR 문맥이나 행·열 복원 품질까지 보증하지는 않으므로 결과를 직접 확인합니다. 입력·출력 경로가 작업 기록에 남을 수 있습니다.

1.7.0부터 보존된 프리 셋 검증 조건은 다음과 같습니다.

- 이름은 1~80 자이며 대소문자를 무시한 중복 이름을 거부합니다. convert/pdf 종류와 허용 옵션만 저장합니다.
- PDF 회전 90/180/270·품질 20~95·DPI 60~600·PSM 3/6/11·OCR 언어 kor +eng/kor/eng를 검사합니다.
- 손상된 프리 셋은 오류를 보존하고 덮어 쓰지 않습니다. 정상 저장만 임시 JSON의 flush/fsync·교체를 사용합니다.

사전 점검의 공간 값은 입력 4 배 +64MiB라는 보수적 추정입니다.

입력 부재·미지원 형식·외부 도우미 부재·공간 부족·쓰기 실패를 서로 다른 코드로 돌려 주므로 같은 오류로 뭉뚱그려 재시도하지 않습니다.

FFmpeg·LibreOffice·Tesseract 등은 선택한 기능에 필요한 경우 준비하고 원본은 별도 보존합니다.

1.9.0은 레시피·Ctrl +K 검색·사용자가 켜는 감시 폴더·OCR 교정·개인 정보 후보 검토를 확장합니다.

검증 기록의 249개 회귀와 설치 제품 626 파일 대조는 당시 범위의 검사이며 모든 문서의 변환 품질 측정은 아닙니다.

화면 수정 전 부분 본은 독립 설치 패키지가 아니므로 차수 표의 자료 성격을 먼저 확인합니다.

## 주요 기술과 처리 방식

파일 종류에 따라 처리 도구가 달라집니다. Pillow·pi-heif는 이미지, pypdfium2·pypdf는 PDF 읽기와 편집, python-docx·ReportLab은 문서 생성을 맡습니다. 표 형태의 OCR 출력은 글자의 위치에서 행·열을 추정하므로 복잡한 표를 완전히 복원한다고 보장하지 않습니다.

`engine.convert()`는 원본과 같은 드라이브의 임시 폴더에서 변환한 뒤 새 이름으로 이동합니다. 압축 내부의 상위 경로·절대 경로와 링크를 검사합니다. PDF 출력은 배타적 파일 생성으로 기존 결과 덮어쓰기를 피하도록 구성합니다.

<a name="️-트레이와-원형-메뉴"></a>
<a id="source-section-12"></a>
### 트레이와 원형 메뉴

기본 조합은 **Shift를 누른 채 탐색기·바탕 화면에서 파일을 끌기**입니다. 앱은 30ms 간격으로 입력 상태를 확인하고 10px보다 큰 이동에서 원형 메뉴를 띄웁니다. 메뉴에 실제로 전달된 로컬 파일을 확인하고 복사 동작으로 드롭을 받아 변환합니다. 중앙·지원하지 않는 영역에서는 변환하지 않습니다.

창의 닫기 버튼은 앱을 트레이로 숨깁니다. 종료는 트레이 메뉴에서 선택하며, 변환 작업이 남아 있으면 완료를 기다리도록 안내합니다. 일반 변환과 PDF 작업은 각각 단일 작업 스레드를 사용하고 두 큐를 동시에 실행하지 않습니다. 도움 도구 화면은 설치 명령을 클립보드에 복사하며 자동 설치하지 않습니다.

<a name="-화면과-기록"></a>
<a id="source-section-13"></a>
### 화면과 기록

화면은 PySide6와 QPainter로 그리며 앱 전용 SUIT Regular·Medium·SemiBold 글꼴을 읽습니다. 버튼·선택·상태 피드백은 유한 애니메이션이며 숨긴 화면에서는 멈춥니다. 도구팁은 파일 명과 오류를 일반 텍스트로 표시합니다.

최근 변환 기록은 최대 200개이며 입력·출력 경로와 오류를 포함합니다. 기록 파일이 손상되면 오류 표시와 함께 기존 파일을 덮어쓰지 않도록 처리합니다. 기록의 결과를 더블 클릭하면 해당 파일을 실행하지 않고 탐색기에서 선택합니다.

<a name="-pdf-작업과-인식-옵션"></a>

### PDF 작업과 인식 옵션

| 옵션 | 화면의 실제 값 |
| --- | --- |
| 페이지 선택 | 전체 또는 `1,3-5`; 삭제에는 명시 범위 필요 |
| 회전 | 90°·180°·270° |
| 이미지 품질 | 20~95, 기본 80 |
| 해상도 | 60~600 DPI, 기본 200 |
| OCR 언어 | 한국어+영어, 한국어, 영어 |
| OCR 배치 | 자동 PSM 3, 단일 블록 6, 흩어진 글자 11 |
| 인식 결과 | 검색 PDF·TXT·DOCX·XLSX |

검색 PDF는 페이지를 이미지로 재구성하고 인식 텍스트 층을 추가합니다. Word·Excel은 글자 좌표로 행과 열을 추정하므로 원래 배치나 병합 셀을 완전히 복원하지 않습니다. 이미지 재압축은 손실 방식이며 무손실 정리도 파일 크기 감소를 보장하지 않습니다. 취소 요청은 작업에 전달하고 이미 완성한 결과를 유지합니다.

## 빠른 시작

Windows Python 환경에서 의존성을 준비합니다.

```powershell
cd "소스"
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements-lock.txt
```

이 공개 사본에는 `소스/assets/fonts/`의 SUIT Regular·Medium·SemiBold 글꼴과 `소스/assets/NanumGothicBold.ttf`, 일부 화면 자산 및 `소스/vendor/tesseract/tessdata/`의 eng·kor·osd 언어 자료가 포함되어 있습니다.

OCR·압축 기능에 필요한 `tesseract.exe`와 7-Zip 실행 바이너리는 포함되어 있지 않습니다.

필요한 실행 환경과 기능별 도구를 따로 준비해야 하며, 소스만으로 배포 앱과 동일한 실행이나 재빌드를 보장하지 않습니다.

필요한 자산을 정당한 배포 원본에서 준비한 개발 환경의 진입점은 다음과 같습니다.

```powershell
.\.venv\Scripts\python app.py --settings
```

`--settings`는 작업 창을 표시합니다. 인자 없는 일반 실행은 트레이에 상주합니다. UI 글꼴 3 종을 읽지 못하면 시작 단계에서 오류가 발생하므로 `assets/fonts/` 입력도 필요합니다.

빌드 스크립트는 PyInstaller와 Inno Setup을 사용하며 기존 출력 폴더가 있으면 중단합니다. `build.py`는 추가 배포 자산·고지 파일도 참조하므로 빌드 전에 해당 입력을 함께 준비해야 합니다.
