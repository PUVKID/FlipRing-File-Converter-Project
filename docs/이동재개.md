# D드라이브 이동 후 작업 재개

확인일: 2026-10-24. 사용자는 자료를 D드라이브로 옮기고 있으며 D의 2026 폴더에서 프로젝트를 찾아 이어 작업하도록 명시했다.

현재 실제 프로젝트는 `D:\2026\FilpRing Project`다. 이전 `C:\Users\PUVKID\Desktop\플립링`은 존재하지 않는다. 앞선 문서의 바탕화면 저장 규칙보다 이 최신 제품별 경로 지시를 우선한다. 새 프로그램·설치 파일·전체 소스·빌드 방법·라이선스도 이 프로젝트 한 폴더에서 관리한다. 프로젝트 폴더 이름은 사용자가 옮긴 실제 이름을 유지한다.

`docs/내부모션.md`의 승인 범위와 `studio-redesign-20261021` 작업을 이어간다. 재개 시 수리8·입력보정7·검증실패0·종료검사실패0이며 이전 실패·예정 RED·영수증 이력을 초기화하거나 새 통과로 지우지 않는다. 이전 구현자가 사용량 오류로 멈춰 남긴 `ui_motion.py`와 신규 검사70~72를 검토하고 기존 화면 연결부터 완성한다.

활성 검사·빌드 명세의 프로젝트 절대 경로는 D의 실제 경로로 갱신한다. 원본 실패 로그·과거 명령·이력의 C경로는 기록이므로 일괄 치환하지 않는다. 옮겨진 가상환경의 Python3.12.14·Qt6.12.0 실행을 확인했으며, `pyvenv.cfg`의 공용 Python 기본 런타임은 현재 존재하는 C의 Codex 런타임을 참조한다. 이를 존재하지 않는 D경로로 바꾸지 않는다.

다른 자료가 이동 중이라는 사용자 상태를 존중한다. 프로젝트 파일의 변경 시간·크기·해시를 확인하고 작업하며 프로젝트 밖 파일을 정리하거나 C의 이전 프로젝트를 다시 만들지 않는다. 운영체제의 표준 앱 설정 위치는 프로젝트 저장 위치와 구분하고 기존 사용자 설정·기록을 임의로 옮기지 않는다.

이전 생성 실행·설치 파일은 새 생성물의 검사 후 교체한다. 대형 중복 납품은 만들지 않으며 작은 소스 기준본과 실패·검증 기록을 보존한다. 새 코드의 실제 실행·설치·물리 Shift 검증과 기존 1.5 릴리스의 검증을 구분해 보고한다.
