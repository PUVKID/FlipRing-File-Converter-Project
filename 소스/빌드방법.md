## 새 경로에서 재현

ZIP을 새로운 입력 폴더에 풀어 `소스`와 `검사도구`를 나란히 유지합니다.  
개발 환경·캐시·출력은 입력 트리 밖에 만드세요.  
아래는 풀어 놓은 `소스`에서 실행하는 예입니다.  
Inno 컴파일러 경로는 실제 설치 위치로 지정합니다.  
새 작업과 출력 폴더는 아직 존재하지 않아야 하며, 실패한 산출물은 보존하고 다른 새 경로로 원인을 해결한 뒤 다시 실행합니다.

```powershell
py -3.12 -m venv ..\..\플립링-재현환경\venv
..\..\플립링-재현환경\venv\Scripts\python.exe -m pip install -r requirements-lock.txt
..\..\플립링-재현환경\venv\Scripts\python.exe -m pip install -r requirements-documents-test.txt
..\..\플립링-재현환경\venv\Scripts\python.exe -B -X utf8 -m unittest test_배포도구 -v
..\..\플립링-재현환경\venv\Scripts\python.exe -B -X utf8 배포빌드.py --output-root ..\..\플립링-새배포 --work-root ..\..\플립링-새빌드 --iscc 'C:\Program Files (x86)\Inno Setup 6\ISCC.exe'
```

`배포빌드.py`는 이미 준비된 환경만 사용합니다.  
자동 패키지 설치·도구 다운로드·로그인·업로드를 수행하지 않습니다.  
위 pip 명령은 개발자가 명시적으로 실행하는 준비 작업입니다.  
고객 실행·설치에는 Python이 필요하지 않습니다.

1.11의 Office 도우미는 `document_bridge.py`·`document_formats.py`·`document_xlsb.py`를 일회용 프로필로 복사한 뒤 LibreOffice Python의 `-B -X utf8`로 실행합니다.  
앱 번들의 Python 확장 모듈 경로와 별도 도우미의 실행 위치를 분리하며 사용자 LibreOffice 설정은 바꾸지 않습니다.

순서는 고지·아이콘·1.11 버전·이동 가능한 spec/iss 준비, 외부 준비 manifest, 전체 소스 ZIP 동결, 외부 소스 manifest, PyInstaller, 실행 고지, Inno, package 검증입니다.  
spec/iss는 실행 시 FLIPRING_SOURCE·FLIPRING_PROGRAM·FLIPRING_INSTALLER 환경값을 받으므로 이동 후 절대경로를 SOURCE에 다시 쓰지 않습니다.  
Python 바이트코드·PyInstaller 캐시·임시 파일도 외부 작업 폴더를 사용합니다.

분리 실행이 필요하면 `build.py --prepare-only --output-root <새출력> --work-root <새작업> --iscc <실제ISCC> --manifest <외부준비JSON>`으로 준비만 수행할 수 있습니다.  
Python에서 `배포빌드.freeze_source`를 호출하는 동일 규칙으로 ZIP을 동결하고 외부 소스 JSON을 저장한 뒤 `build.py --prepared <준비JSON> --source-manifest <소스JSON> --output-root <출력> --work-root <작업> --iscc <동일ISCC>`로 컴파일합니다.  
일반 재현에는 위 한글 진입점 한 명령을 사용하세요.

`package.py --release-root <실제staging> --source-manifest <외부소스JSON> --prepared <외부준비JSON>`은 별도 출력 경로를 직접 검사합니다.  
준비 manifest에는 전체 입력 트리와 도구의 실제 버전·SHA를 기록하며 로컬 경로 등 실행 정보를 포함하므로 공개 소스 ZIP에 넣지 않습니다.  
소스 ZIP SHA는 외부 소스 manifest·실행 고지에만 기록하며 SOURCE에 되돌려 쓰지 않습니다.

목록 밖의 개발 조사 파일을 필수 배포 자료로 취급하지 않습니다.

## 1.10 문서 변환 구성

`document_formats.py`는 입력·출력 형식과 검증을, `document_bridge.py`는 별도 LibreOffice Python 프로세스에서의 UNO 변환을 담당합니다.

문서 도우미 관련 원문은 실행 폴더의 `_internal`에도 자료로 포함하며 생략하면 안 됩니다.  
`package.py`는 소스와 실행 폴더의 원문 일치를 검사합니다.

Word·PowerPoint·Excel 등 Office 변환에는 공식 Windows x64 LibreOffice 설치와 그 설치의 UNO Python이 필요합니다.  
LibreOffice 자체는 이 배포물에 포함하지 않습니다.

앱의 도구 화면에서 상태를 확인하세요.

Java를 시스템에 등록하거나 JAVA_HOME을 바꿀 필요가 없습니다.  
H2Orestart의 정확한 v0.8.0 소스·GPL 원문은 `licenses/H2Orestart`, Java의 정확한 17.0.21+9 전체 상응 소스·원문 고지는 `licenses/Temurin17`에 함께 보관합니다.  
재빌드할 때 이 폴더를 포함해야 하며 프로그램과 라이선스 자료를 분리해서 배포하지 마세요.

HWP5/HWPX 상호 저장과 DOCX/TXT에서 HWP/HWPX로의 제한 저장을 추가합니다.  
앱 Python3.12 worker가 python-hwpx6.12.0과 기존 lxml6.1.3을 사용하며 LibreOffice Python에 앱 확장 모듈을 주입하지 않습니다.  
HWP의 다른 출력은 기존 LO/H2O 읽기를 유지합니다.  
DOC·PPT·XLS는 구형 형식으로 내보내기를 지원하지만 전용 서식·차트·외부 데이터·매크로 등의 완전 보존을 보장하지 않습니다.  
CSV/TSV는 첫 시트의 표시값을 저장합니다.  
XLSB는 입력 전용입니다.  
자세한 범위는 `1.10-문서지원안내.md`를 확인하세요.

문서 실제 통합 검사는 LibreOffice를 설치한 환경에서 `python -B -X utf8 -m unittest test_documents_integration -v`로 실행합니다.  
외부 출처의 HWP/HWPX/XLSB 검증 표본은 재배포하지 않으며 해당 검사의 입력 준비 조건과 검증 기록을 확인하세요.  
기존 249개 검사와 새 형식·화면 검사도 함께 수행해야 합니다.  
실제 Windows 탐색기 Shift 드래그 검증은 오프스크린 검사와 별도로 수행합니다.

### GitHub 사본에서 문서 런타임 복원

로컬 전체 소스에는 Java 실행부와 정확한 상응 소스가 이미 들어 있습니다.  
공개 저장소에서는 대형 Java 실행부·원본 소스 아카이브를 제외하고 원문 고지·고정 버전·개별 해시 목록과 복원 코드를 보관합니다.

기존 OCR·HEIC·Qt 등 전체 자산·법적 자료의 준비 조건은 위 절과 해당 출하 목록을 따르며, 이 명령 하나가 모든 외부 도구를 설치한다는 뜻은 아닙니다.  
고객 설치본에는 필요한 Java와 H2Orestart를 이미 포함하므로 이 복원 명령이나 Python을 요구하지 않습니다.

### 종료 오류 보존과 검사 범위

`test_document_shutdown.py`의 4개 검사는 최초 변환 오류·close 오류를 종료 중의 후속 오류로 가리지 않는지 확인합니다.  
현재 문서 검사는 이 종료 보존 4개와 나머지 47개를 합해 총 51개로 집계하며 기존 검사 기대값을 완화하지 않습니다.  
당시 정책 검사가 12개였을 때의 나머지 45개·합계 49개는 이전 집계입니다.  
종료 보존 모듈의 개별 제한은 30초, 신규 하네스 전체 제한은 600초입니다.

성공은 결과 파일 생성만으로 판정하지 않습니다.  
변환 뒤 문서 close와 데스크톱 terminate가 승인되고 도우미가 종료 코드 0으로 끝나며, 소유 Job의 프로세스가 남지 않고 격리 프로필 정리가 완료돼야 합니다.  
최초 연결 오류가 있다면 해당 오류를 보존하며, 로컬 프로세스를 회수했다고 변환 성공으로 바꾸지 않습니다.  
외부 변환 도구의 비정상 종료에 대한 근본 원인은 별도 진단 대상입니다.

일반 재현 검사는 위 `documents_suites110.py` 명령으로 현재 51개를 직접 실행합니다.  
기존 249개 회귀와 문서 51개는 서로 다른 검사 묶음입니다.  
이미 실행한 51개의 산출물·소스 해시를 확인하는 절차는 51개를 다시 실행한 것과 구분하며, 독립 검증자는 최종 소스의 51개 검사를 별도로 직접 실행합니다.
